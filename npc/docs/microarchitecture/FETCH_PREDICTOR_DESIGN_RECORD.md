# 取指控制流预测器：模块边界与时序契约

2026-09-15，RV32 面试工作树。本次将 BHT、BTB、RAS 分开管理，保持当前算法、参数、
查询延迟和训练生效时刻。原预测器对 core/IFU 的接口不变，不增加流水寄存级。

## 模块职责

| 模块 | 拥有的状态与功能 |
| --- | --- |
| `riscv32_fetch_control_flow_predictor` | 两级查询的 PC/epoch、BHT/RAS 查询快照、响应、统一握手、最终方向/目标选择；共享的控制流解析事件寄存器 |
| `riscv32_branch_history_table` | 两位饱和计数器数组、组合读端及条件分支训练写端 |
| `riscv32_branch_target_buffer` | BTB 表项、替换位置、查询 set 快照与 tag 比较、训练 set 快照、待写事务及训练旁路 |
| `riscv32_return_address_stack` | 调用/返回识别、栈操作寄存器、返回地址数组、写指针、数量及栈顶副本 |

`branch_target_kind_e` 是 BTB 与预测选择之间的共享接口类型。BTB 的 tag、索引、way、
训练快照和写事务类型均留在 BTB 内部，其他模块不直接访问其数组。

## 查询与更新时序

一次请求握手时，控制模块保存 PC/epoch、BHT 计数和 RAS 栈顶；BTB 同时保存对应 set。
下一流水级按该 PC 做 tag 比较、方向与目标选择并寄存响应。反压时各部分一起保持，
子模块没有独立的请求队列或 ready 链。

BTB miss 选择 PC+4。命中条件分支时取 BHT 最高位；命中直接/间接跳转时预测 taken；
命中返回时优先取有效 RAS 栈顶，否则取 BTB 目标。不满足四字节对齐的目标不预测 taken。

训练来源是无异常控制流执行结果被接收的事件，不是提交事件。以事件采样沿为 E0：

- E0：保存共享解析事件；RAS 并行保存译出的栈操作。
- E1：BHT 和 RAS 更新各自状态；BTB 保存训练 set 快照。
- E2：BTB 保存选定 way 的写事务。
- E3：BTB 写数组。连续训练同一个 set 时，训练快照使用最新待写事务旁路。

查询没有训练值旁路：同一沿的查询采样读取更新前状态。拆分时不改变这一行为。
复位使 BHT 为弱不跳转 01，清 BTB 有效位及替换位置，清 RAS 数量、指针和栈顶。
`flush_lookup` 只清在途查询，不清训练状态；`invalidate` 清 BTB、RAS 及对应待更新状态。
BHT 计数器保留，invalidate 同拍可以完成之前已经寄存的 BHT 更新，随后共享事件寄存器清空。
独立 invalidate 不会自动取消查询，系统需要通过原有恢复控制清查询。

## 验证要求

用拆分前实现进行逐周期对照，检查 ready、valid、PC、epoch、预测及 next PC；覆盖连续查询、
反压、flush、invalidate、查询与训练同拍、同 set 连续训练、计数器饱和和 RAS 环绕。
再运行现有流水线与定时中断系统回归。综合结果单独记录，不能由模块拆分推断面积或频率改善。
本记录只维护文字和表格。

## 本次验证结果

5 组参数、共 120,000 周期的新旧预测器外部输出对照通过；原流水线、定时中断系统和
SoC MicroBench `test` 通过。750 MHz 配置下，所有 MicroBench 窗口的周期、退休数和
原生计时结果与拆分前一致。功能对照不自动证明综合时序通过。
最终采用相同 820 MHz 综合目标生成的网表，在 730 MHz 下 setup、hold 及门控时钟检查通过，
面积 76,480.320 μm²；本次不增加流水级来追求更高频率。
