# RV32 复位释放与重定向路径时序设计

日期：2026-09-06。范围：rv32-interview 分支，接续 D-cache 写数据优化。

## 重定向校验

进入 EX/MEM 执行结果寄存器时，额外用明确命名的 `predicted_next_pc_q` 保存预测后继地址：预测跳转取原预测目标，预测顺序取输入 PC+4。输出侧仅比较实际 next_pc 与这个寄存值。原执行结果 payload 不改写，不增加流水周期；综合可删除没有下游消费者的旧预测字段寄存器。容量、flush 优先级和背压契约保持不变。

验证需要覆盖预测方向及目标组合、PC 加法进位/回绕、背压稳定和 flush 清空，并跑完整系统中断/流水控制回归。

## 系统复位

外部低有效复位在系统入口唯一的 reset controller 中异步置位。两级上升沿寄存器完成释放同步，再由下降沿寄存器统一释放系统复位。核、CLINT、仲裁/路由及 SoC 位宽转换器使用同一个释放结果。同步链使用未门控输入时钟；外部复位拉低时不依赖时钟，重新拉高后至少经过两次上升沿及随后的下降沿才能开始工作。

下降沿释放为下游上升沿触发器提供半周期 recovery/removal 预算；实际是否满足由映射网表 STA 决定，不能只凭 RTL 拓扑断言收敛。原始异步输入到同步链的检查属于同步器边界，例外只能限定到这些端点；同步器输出到核内各 RN 的路径必须保留检查。禁止对全核复位网络一律 false-path。

纯核端口 rst_ni 接收系统控制器的输出。为检查真实释放驱动器，另提供仅包含 reset controller 和 core 的 STA 顶层；该顶层不包含 CLINT 或 SoC。其面积与纯核面积分开记录。新增检查不覆盖 CTS、布线后的复位树或模拟亚稳态概率，物理实现必须继续检查这些内容。


## 验证后的实现补充

原始异步端口不建模为同步数据输入；网表审计限定它只连接三个同步器 RN，核内 1,161 个 RN 全部由控制器输出或其非反相缓冲驱动。当前 iSTA 对复位 false-path 的处理不能作为边界依据，因此不对同步器输出设 false-path。数据输入逐个约束，映射网表有 101 个。

单个释放触发器不足以直接驱动全核。`build_reset_tree.py` 在展平映射网表中插入 96 个 BUF_X4，新增树每级扇出最多 16；原单元功能保持不变，并通过结构等价比较。该步骤属于综合后的电气负载修复，不是 RTL 中复制同步器，也不代替布局后的复位树设计。`sta-reset` 自动执行并保存未缓冲与缓冲后的结果。

最终 820 MHz max/min TNS 均为 0，门控时钟检查为正；设计及功能回归通过。实际结果见 [验收报告](../verification/RV32_RESET_REDIRECT_FIX_2026-09-06.md)。
