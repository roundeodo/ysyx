# 小型 TAGE 方向预测实验

2026-09-24 设计；默认关闭。先用模型筛选，再用本说明约束RTL，不把初筛当成采用结论。

## 电路结构

PC与16位已解析条件历史 → 并行读取基础二位表及三张带标签表 → 选择最长匹配历史的方向 → 原有唯一预测响应寄存器。
三张表分别使用4、8、16位历史；每表N项，基础表也是N项。每项保存present、8位部分tag、3位方向计数器和1位useful，逻辑状态为41N+16位，另计流水载荷中的快照。
索引用PC字地址异或折叠历史；tag混合PC与两种折叠历史。所有参数从配置入口传入；实验只承诺N=8/16/32。

查询上下文保存历史、provider编号（0为基础表）、当时方向和alternate方向。训练重新计算当时索引与tag；只有当前表项仍匹配才更新provider，避免延迟训练写到已经替换成别的标签的条目。部分tag碰撞仍是预测别名，不是架构身份。

## 状态更新与恢复

基础表在有效条件分支解析时训练；provider使用当前计数器作饱和更新。当provider和alternate不同，useful置为provider是否正确。
错误预测时在provider之后的更长历史表中，选择第一个空项或useful=0项分配。没有可替换项时，只清除这些候选项的useful，下一次有机会再分配。无后台全表清零计数器，不增加等待。
策略3采用标准useful更新；策略4在provider错误、alternate正确时，额外保护仍匹配原tag的alternate表项，快照增加2位备用提供者编号。两者表容量相同。基础表正确则不分配的选择性机制仅在模型中筛选，不等同于论文的loop成功过滤。

reset清空整个tagged表载荷及历史，基础表初始化弱不跳。tag/counter也带复位是本原型的实现选择；只复位present能否改善面积与布线尚未单独测量。invalidate优先于训练，清历史及tagged present，保留基础计数器；普通flush丢弃年轻载荷，保留已解析历史。预测状态永远不生成架构副作用。
当前版本明确使用已解析历史，不能称为推测TAGE。推测版本须另定义查询、预译码纠正、非分支恢复、异常和FENCE.I的历史恢复所有权，不能只在查询时增加一次移位。

## 寄存器、等待与旁路

算法数组是唯一新增持久状态；查询上下文沿既有队列与流水寄存器传递。没有新增查询级、训练级或状态机，吞吐不降低。查询读沿前数组状态，同拍训练在沿后可见，与基础BHT一致；不添加EX训练到下一PC的组合旁路。
provider标签检查、分配优先选择属于训练路径；索引异或、表读、tag比较、最长匹配选择属于查询路径，须分别看STA。不能只报告表位数而省略寄存器和组合选择面积。

借鉴范围：TAGE的几何历史/部分tag/提供者/有用性分配；没有SC、loop、path history、多银行共享或ahead pipeline。此版本用于分离“更强表结构”的贡献，不是完整TAGE-SC-L复现。


## 与论文实现的差别

本原型使用三张短历史表、1位useful、固定选择第一个可分配的更长历史表；没有弱新provider的备用选择计数器（USE_ALT_ON_NA）、周期性全表useful老化、路径历史或推测GHR。策略4仅借鉴2025年作者文章中的备用项保护规则。表由当前标准单元流程映射，没有预测器SRAM宏；原论文的KiB预算不能直接换成本核面积。这里只比较这组明确缩小的实现，不能用其负结果否定完整TAGE-SC-L。
