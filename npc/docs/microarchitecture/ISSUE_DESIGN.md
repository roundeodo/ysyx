# Issue 级：操作数准备与发射边界

ROB 后端明确分开 Decode、Issue 和 Execute。原后端保持原流水连接；fetch buffer 空时直通。
测量与取舍见 [实施记录](../verification/RV32_RETIRE_BYPASS_2026-10-01.md)，不能仅凭增加一级认定性能提高。

## 数据流与状态

Decode 组合译码 → Issue 指令寄存器 → GPR/CSR 读取、scoreboard 依赖与前递选择 →
原执行入口寄存器 → ALU/MUL/DIV/LSU → ROB → Commit。

| 边界 | 保存什么 | 写入、保持与清除 |
| --- | --- | --- |
| `riscv32_issue_reg` | 一条 `decoded_uop_t` 和有效位；不保存操作数值 | 空闲或旧项发射时可接收译码；阻塞保持；任何前端恢复清空 |
| 原执行入口寄存器 | 已选定的操作数、控制信息及对应 ROB 身份 | Issue 与 ROB 分配同拍成功才写入；FU 未接收时保持；按原恢复规则清空 |
| ROB | 指令身份、完成结果和异常 | 原有顺序分配、独立完成端口、按年龄恢复和顺序退休 |

Issue 寄存器没有空时直通，否则译码到依赖选择的组合路径仍存在。旧项发射与新项接收
可在同拍进行，连续发射不插气泡。该寄存器是一条明确的流水级，不另设 decode FIFO。
原 fetch buffer 只在反压时保存取回的指令，空时可直接进入译码。

## 读数与前递

GPR 地址、CSR 地址、读写意图和异常都取自同一条 Issue 指令。不能把已寄存的指令
与仍在 Decode 的寄存器地址或 CSR 字段配对。等待期间重新查询最新结果；发射时才把
操作数锁进执行入口。保留当前 ALU、各 FU 当拍完成和已完成 ROB 项到 Issue 的前递。

scoreboard 是组合电路，不再附带隐含流水级。ROB 在 Issue 进入 Execute 时分配；
尚留在 Issue 的指令没有 ROB 身份。FU 接收仍按程序顺序，允许独立 FU 乱序完成；
不会把一项 Issue 寄存器称为乱序发射队列。

## 反压与恢复

Decode ready = Issue 为空或当前指令可发射；flush 当拍拒绝新输入并清有效位。
满级交接允许吞吐一条/拍，但 ready 反馈仍需 STA 检查，不能只检查正向数据。
分支纠错、非分支错误 taken、提交异常、中断和 FENCE.I 的前端恢复都清除 Issue。
中断停止 Issue→Execute，排空已进入 ROB/FU 的工作；未发射的 Issue 指令可直接取消，
不能把它计入必须排空的 backend busy 而形成死锁。

## 验证与对照

ALU 结果级和流水 MUL 在队首完成时可直接进入 Commit；其余结果读取已完成 ROB 项。
旁路受阻时，结果写入已有 ROB 项，下一拍继续提供同一条指令，不增加缓存。
DIV 和 LSU 保留完成寄存边界，避免返回、退休授权与恢复形成组合反馈。
完成→Issue 前递独立于退休旁路，所有 FU 均保留。

检查随机反压/flush、满级同时出入、CSR/GPR 与指令对齐、精确异常、恢复同拍响应及中断；
另用定向指令流检查独立 MUL、DIV、LSU 的真实重叠和受依赖/单 LSU 限制的反例。
最终比较同频周期、合法频率下时间、面积及总线流量；没有证据时不声称 train 加速。
