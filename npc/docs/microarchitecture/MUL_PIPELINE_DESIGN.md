# RV32 乘法流水与顺序完成

已验证的可选配置，2026-09-28。`NPC_MUL_PIPELINE_ENABLE=1` 与 M 扩展同时启用；
零值保留已验证的迭代基线。此处定义电路；验证状态、PPA 和负结果见
[验证与取舍](../verification/RV32_MUL_MODULES_700MHZ_2026-09-28.md)。
`rv32im-pipelined` 默认700 MHz，迭代稳定配置保持700 MHz。

## 模块职责

`riscv32_mul` 只实现乘法数据通路：分块部分积、两层压缩、最终64位积。
它保存已有的部分积与压缩结果寄存器；EXU分别提供两级写使能，未使能时保持。
`riscv32_div` 只负责迭代除法和余数。EXU保存指令身份、每级有效位和普通指令结果，
统一处理反压、顺序完成及恢复。flush只清EXU的有效位，乘法器的数据寄存器不需要复位。
该职责拆分不增加寄存器、运算拍、队列容量或等待；稳定迭代配置保留原实现作为对照。

700 MHz保留实现把外部接收能力与实际发射许可分开计算。外部ready只检查空槽和下游ready，
实际槽位推进、入队、结果valid仍使用原issue许可；许可为真时接收条件与原式等价。
许可为假时，ID/EX由progress保持，或由恢复flush清空，不允许年轻指令产生副作用。
缓存替换更新必须继续以真实命中握手为准，不通过放松异常门控或改变等待模型换取频率。

## 运算与寄存边界

EX 输入拍并行计算四个 16 位分块部分积；第一个寄存级保存部分积和指令结果包。
下一拍用两层 carry-save 压缩为两行；第二个寄存级保存两行和同一指令身份。
第三拍相加并选择低/高半，直接进入已有 EX 结果寄存器。普通乘法延迟三拍、启动间隔一拍。
ID/EX 同沿另存 64 位乘法操作数，隔离四个部分积电路对通用操作数与地址路径的扇出；
只在有效乘法进入时写入，未增加流水拍。SVA 检查其与 ID/EX 操作数逐位一致。
两级均可反压，空级或旧项推进时接收新项，flush 只清有效位；不新增 DONE 搬运级。

普通 EX 结果在流水为空时直通。已有老乘法时，年轻普通结果随相同寄存级顺序推进，
避免乘法未完成而年轻 ALU 提前提交；普通结果在各级均可前递，不等待无关的乘法计算。
乘零仍直接产生零，流水为空时保留一拍路径。PC、目的寄存器、异常、预测快照随结果保存。

除法独立为 `riscv32_div`，仍为单上下文逐位迭代，保留所有快捷情况和最终拍前递。
它可以在更老乘法排空时计算，但年轻指令仍不能越过除法。流水除法与可越过除法的
scoreboard/完成队列不属于本候选，不能声称已经支持。

## 依赖与副作用顺序

译码选择最近的生产者：ID/EX → 新流水第一级 → 第二级 → EX 结果 → LSU → WB。
每级提供 present、rd、writes_rd、forwardable 和结果；最近生产者未就绪时必须等待，
不能取更老的同名结果。这是固定级间依赖检测，不是通用 scoreboard，也不复制 32 位 busy 表。
WAW 随顺序结果通路自然保持；操作数在进入 ID/EX 前取齐，因此不会增加 WAR 风险。

LSU 只在新流水为空时接收指令。待最后一个结果进入 EX 结果级后，原 hazard 对异常和
分支纠错的门控继续生效，避免年轻 store 越过老异常。串行化与中断排空包含新增有效位。
普通分支恢复清空新增流水。非分支错误 taken 在结果交付时恢复，保留当前交付结果、
清除流水内与 ID/EX 中更年轻的指令；已开始的年轻除法也被取消。

## 参考与取舍

[Rocket Multiplier.scala](https://github.com/chipsalliance/rocket-chip/blob/master/src/main/scala/rocket/Multiplier.scala)
分开提供迭代 MulDiv 与 PipelinedMultiplier，并让结果携带请求身份。
[CVA6 issue stage](https://docs.openhwgroup.org/projects/cva6-user-manual/03_cva6_design/issue_stage.html)
说明功能单元就绪、源操作数和目的寄存器冲突的职责。
本候选独立实现分块乘法和弹性顺序完成，不复制其 RTL，不引入 CVA6 的 scoreboard。

验证必须覆盖独立乘法连续接收、相关链、同名多生产者、混合 ALU/分支/访存、反压、
恢复同拍、精确异常、中断排空和全部 M 算术边界。保留同镜像迭代对照，比较周期、面积、
通过 STA 的频率和执行时间；本轮没有改变稳定预设：现有应用周期没有改善，而面积仍高于迭代实现。

性能窗口继续使用被动退休计数与原生定时器。旧按指令类别累计的延迟观察器只有一个
上下文，流水配置明确显示 n/a，不用它推导 oracle 加速；缓存与周期/退休计数不受影响。
