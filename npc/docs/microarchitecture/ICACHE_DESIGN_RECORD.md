# I-cache 设计记录

状态：当前结构说明；验证范围见实验记录

最后更新：2026-09-24

## 1. 当前结构与职责

I-cache 保存最近使用的指令，减少对下层内存的访问。当前为组相联、阻塞式 L1 指令缓存，
默认 1 KiB、4 路、32 B 缓存行，使用分段访问 RRIP（源实验策略 13）。
这是从 RV32 面试分支同步的已选前端配置；其 RV32 性能和时序结论不能直接用于本核。
配置来源和本次验证见[同步记录](../verification/FRONTEND_CONFIGURATION_SYNC_2026-09-24.md)。

| 模块 | 负责什么 |
| --- | --- |
| `riscv_pma` | 根据物理地址判断是否可执行、可缓存 |
| `riscv_icache_tag_array` | 保存并读取地址标记和缓存行有效状态 |
| `riscv_icache_data_array` | 同步读取指令数据，接收回填写入 |
| `riscv_icache_miss_unit` | 跟踪一次缺失、回填进度及原请求响应 |
| `riscv_icache_refill_axi4_master` | 将本地回填请求转换成 AXI4 读事务 |
| `riscv_icache_replacement` | 保存分段访问 RRIP 状态，前递同拍命中更新并锁定候选替换路 |
| `riscv_icache` | 组织查找、命中选择、替换与失效过程 |

IFU 传入地址和请求身份，不直接操作缓存阵列或 AXI 通道。

## 2. 查找与命中

S0 在 `lookup_req_valid_i && lookup_req_ready_o` 时接收请求，保存身份并启动同步阵列读取。
S1 根据地址属性与各路标记判断：

- 不可执行：返回取指访问错误。
- 可执行但不可缓存：发起一次不分配缓存行的访问。
- 缓存命中：选择相应指令字并返回。
- 缓存缺失：选择替换位置，把请求交给缺失处理单元。

响应被阻塞时保留内容。缺失处理期间不接收新的查找，仍是阻塞式缓存。原先不能启用的
回填字选择、逐字可见向量和相应端口已删除；原缺失请求所需字的提前返回仍由miss unit负责。

## 3. 缺失与提前返回

可缓存请求按缓存行起始地址发起 AXI4 INCR 递增突发。当前回填接口每次返回一个 32 位
取指字；在 64 位 AXI 数据通道上使用 4 B 的窄传输，默认 32 B 行需要 8 个 beat。
总线数据位宽与每拍实际传输大小分别定义，详见 [AXI4 互连](../interconnect/AXI4_ARCHITECTURE.md)。

工作过程：

1. 开始覆盖替换位置前，先清除旧缓存行的有效状态，防止旧标记命中部分更新的数据。
2. 每个成功接收的字写入数据阵列，记录进度和错误状态。
3. 当请求所需的指令字到达时，生成一次响应，不必等整行完成。这称为提前返回（early restart）。
4. 最后一个字成功返回且本次回填没有错误时，写入新标记并将整行置为有效。
5. 总线事务和原请求响应均结束后，释放这次缺失记录。

当前突发从行首递增，所需指令字不一定最先传输。不要把提前返回写成“关键字优先传输”。
提前返回可让该指令的执行与剩余回填重叠，但不会解除当前缓存对新查找的阻塞。

### 错误与反压

- 请求所需字返回之前或该字本身出错：向原请求返回一次访问错误。
- 已成功交付所需字后，其他字出错：不安装整行，不撤销已交付指令，也不返回第二次响应。
- IFU 暂时不接收响应时，保存该响应，并继续接收剩余回填，直到总线事务结束。
- 发生错误时不能用旧标记命中已经被覆盖的数据。

以上是当前实现的行为，仍需对应的错误注入和反压测试记录。

## 4. 替换与失效

优先选择无效路；各路都有效时使用分段访问 RRIP：同一行内连续命中不提升优先级，
离开该行后再次命中才提升。候选替换路与 tag 同拍读取，同组命中更新会前递给新查询，
反压期间候选快照保持。状态和握手边界见[替换逻辑设计](ICACHE_REPLACEMENT_DESIGN.md)。

`NPC_ICACHE_REPLACEMENT_POLICY=0` 保留原轮转策略供对照，默认 13；单路配置需选择 0。

当前 `fence.i` 维护顺序是先让 D-cache 写回脏数据，再使 I-cache 失效。期间阻止新取指
访问，并处理旧路径响应。D-cache写回失败时保持阻塞并重新清理，成功后才进入失效，见
[D-cache 设计](DCACHE_DESIGN_RECORD.md)。

## 5. 必须检查的性质

- 同一组内不能有两路同时命中同一地址。
- 请求身份、替换位置和未完成响应在需要等待时保持稳定。
- 整行成功回填前不能设置整行有效状态；错误回填不得安装有效行。
- 每次缺失只产生一个原请求响应，已经接收的总线事务必须完成。
- 失效完成后，所有缓存行均不可被正常查找命中。
