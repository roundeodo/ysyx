# I-cache 替换实验电路

本模块只拥有替换策略状态，不保存tag、数据或请求，不增加cache流水级。仅策略4～16实例化；
0～3保持原实现以便对照。数据容量、路数、行大小仍由统一配置入口提供。

输入按S1已完成的事件更新：cache hit响应握手，或可缓存miss接收，两者互斥。
miss的victim有效性使用tag快照，不重复保存一套valid。优先选择invalid仍由I-cache主体完成。
失败回填留下的策略状态不使行有效，下一次invalid分配覆盖其元数据。

| 编号 | 策略与状态 |
| --- | --- |
| 4 | 真LRU：两路专用每组1位，其余每行log2(ways)位年龄；每次访问提升为MRU |
| 5 | Tree-PLRU：每组ways-1位；访问时沿树路径指向另一子树 |
| 6 | 随机：32位确定性xorshift，miss推进；读取时冻结对应way |
| 7 | BRRIP：每行2位RRPV，5位miss计数，每32次有1次插入2，其余3 |
| 8 | DRRIP：同RRPV，10位饱和选择器；固定leader组比较SRRIP/BRRIP |
| 9 | 分段访问RRIP：只有离开该行后的再次hit才提升，增加前一次访问行地址及存在位 |
| 10 | 分段访问+PC重用反馈：64×2bit预测表，每行6bit插入签名及1bit已重用标志 |
| 11 | 与10相同，签名再混入访问路径历史的低6bit；只在行切换时推进历史 |
| 12 | 与7～11使用相同电路边界的SRRIP，作为基础结构对照 |
| 13/14 | 分别为9/12的查询路径精简版：查询只前递同组hit，不经过miss分配更新 |
| 15/16 | 分别为11/10的同等查询旁路版；学习表训练、历史、插入及失效规则不变 |

9借鉴ACIC对行内连续访问与跨段重用的区分，未实现其i-Filter或准入结构；10/11借鉴
签名重用训练与GHRP的路径信息，不是完整GHRP或ICARUS。11使用已发生的cache访问路径，
不读取未来分支结果，也不新增推测分支历史/恢复栈。仅首次跨段hit将插入签名计数加一，
未曾跨段重用的有效victim离开时减一；新行按预测表非零插入2，否则3。
历史在原型中声明为16bit，但高10bit不参与任何输出，综合会删除；实际有效历史为6bit。
未选策略的学习表、签名、历史和计数器也会被常量传播删除，不是每个配置都包含这些状态。

以1 KiB、4路、32 B行为例，共8组32行：PLRU为24bit树状态加2bit查询快照；SRRIP
为64bit RRPV加2bit快照；分段访问再增加27bit前次行地址和1bit存在位。路径学习版另有
192bit行签名、32bit重用标志、128bit学习表及6bit有效历史。以上不含原有tag/data/valid，
面积以整核综合为准，不能按状态位比例换算。DRRIP需要至少4组才能同时包含两类leader；
更小组数下本原型会退化，不能把这类模型结果当作完整集合对决策略的证据。

组合路径按S1事件译码、策略下一状态、S0 victim选择的顺序展开。时钟沿同时更新策略
状态和已接收查询的victim快照，两组寄存器不是串接的两级流水线。查询与上一条hit更新
同拍时，victim选择可看到同组前递；查询后被反压则快照保持。
这条前递与策略12一起测量，避免把基础结构变化的收益归给新策略。
victim快照与已有tag读口处于同一寄存边界，只有新查询握手才更新；它保证S1受阻期间
替换身份不变，不是额外一级流水线。它也将victim比较放在S0，避免与S1的miss分配、
学习表更新连成一条组合路径；这里只保存way编号，而非再保存整组RRPV。其复位值不参与
有效请求，首次查询握手前输出被忽略。
原策略1在同步读取时保存旧RRPV值，同沿的S1命中更新要到后续查询才可见；12/14则前递
这次同组命中。因此两者属于不同的查询/更新时序边界，不能要求替换次序逐事件完全相同。
这只影响替换选择，不改变tag命中判断或指令结果，性能和组合路径分别实测。

复位和FENCE.I全失效清策略状态、路径历史与前次行存在位。普通redirect不清cache的
物理替换历史，不撤销总线请求；错误路径可影响策略，但不能改变取指身份或架构结果。
所有状态只影响victim选择/插入优先级，原cache的valid、错误、排空协议仍负责正确性。

13/14的依据是顶层`lookup_s1_ready`在`miss_req_valid`时为0，因此分配miss与新查询互斥。
查询直接读原RRPV，再把同组命中路的优先级前递为0；不经过分配时的全组老化和插入选择。
状态更新仍完整保留，下一次miss完成后的查询读取已经写入的状态。模块对查询/分配互斥增加
断言，测试亦遵守这一接口约束；没有在CPU中增加等待。9/12保留为同算法、不同电路的对照。

15/16将同一条查询旁路用于学习原型。学习表只决定miss插入值；在无分配的查询拍，
RRPV变化仍只有同组hit提升，因此查询不需要经过签名训练、表读取和插入值选择。
学习表及行签名的写入路径完整保留，下一拍的状态没有改变。它们与11/10做等周期对照，
再比较整核面积和四组STA，不能把不可同时发生的分配/查询路径当作算法必需的延迟。
