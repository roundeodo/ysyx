# 多请求 LSU 与单 miss D-cache

2026-10-01，可选实现与验证记录。研究依据见
[开源比较](../learning/LSU_DCACHE_DESIGN_REVIEW.md)；默认仍关闭；实测结果见 [验证记录](../verification/RV32_LSU_CONCURRENCY_2026-10-01.md)。

## 选择与目标

选择两项访存上下文、带身份返回、单 MSHR 的 hit-under-miss。请求接收与完成解耦参考
CVA6，缓存查询与缺失处理分离参考 HPDcache；不引入 BOOM 的未知地址投机和大型关联 LSQ。
当前后端顺序发射、ROB 4 项，下层读通路一次只接受一个事务。完整 BOOM LSU 的恢复和搜索
成本缺少对应的乱序发射窗口；两个 MSHR 也需要互连同步升级。因此先实现能够在现有边界
内发挥作用的并发结构，保留容量扩展与仅增加上下文的对照。

预期改善第二条 load 挡住独立运算、miss 期间其他行 hit 等情形。数据依赖链、两个独立 miss、
store 顺序和 I-cache 等待不会自动消失；收益与面积/时序以实测为准。

## 电路与状态归属

- LSU：两项紧凑指令上下文；每项区分待发请求、等待响应、本地异常。空时直接发给存储层，
  反压时才保持。请求 ID 是上下文索引；返回按 ID 读取地址低位及操作类型，格式化一次。
- 后端：每项 LSU 身份对应一个 ROB tag 与取消标志。恢复后已接受的请求排空，迟到响应丢弃；
  完成前不得复用该项。其他空项可继续接受安全 load。串行化操作等待全部旧项排空。
- 访存路由：cache 请求计数保持路由，允许多个 cache 请求共享同一目标；切换 uncached/本地
  错误前等待最后一个 cache 响应，禁止因年轻地址改变旧 R/B 归属。
- D-cache：保留一个 miss 上下文和现有 victim 保护；S1 查询可与 miss 并行。victim 采集占用
  读端口时停止新查询；其他时刻允许 load 查询。正在替换的组/路不可命中，其他路仍可命中。
  遇到 miss 或被预留行时保留 S1，旧 miss 完成后重新同步读取一次，避免使用旧 tag/data。
- 响应：miss 与 hit 共享一个完成口，S1 hit 优先；miss 等待交付时暂停接收下一查询，
  至多让当前 hit 先返回一次。已经展示且受阻的 miss 保持优先级，不能被后来到达的 hit 替换。
  miss 当拍真正交付且阵列无冲突时，可同时接收下一 load；不把“出现 miss 响应”当作无条件
  空转理由。不为全部正常 hit 增加响应搬运级。

store、MMIO、uncached 读继续需要队首授权。store 不在旧 miss 期间进入查询；本轮不增加
允许 store 提前退休的缓冲，保持现有精确错误确认、clean 失败停止和 dirty-victim 恢复。
已接受但后来被取消的 load 只来自可缓存、幂等区域，继续排空不产生软件可见写副作用。

## 参数与比较

`NPC_LSU_ENTRIES=1/2` 控制上下文数，`NPC_DCACHE_HIT_UNDER_MISS=0/1` 控制 cache 并发。
默认保持 1/0；正式两项配置要求 ROB 和 load overlap 开启。比较 1/0、2/0、2/1，
容量、ROB 深度、程序镜像与设备模型保持一致。没有新增 CPU Issue/完成流水级。

新增保留条件均对应请求身份、协议反压、阵列读写冲突或错误恢复；不因模块边界强制打拍。
验证覆盖 hit/miss 乱序响应、同组/同行、随机反压、恢复同拍、槽复用、错误和维护。

## 返回时序

返回路径是新增并发的主要时序代价。比较了 miss/memory 优先，以及 S1 hit/本地异常优先
两种仲裁。最终采用后一种：无本地完成时提前选好返回上下文，减少晚到 RVALID 控制宽数据
选择的路径；miss 响应出现后不再接下一 lookup，保证旧 miss 不被持续 hit 饿死。

单槽 LSU 没有两个完成来源竞争，按 `LSU_RESPONSE` 状态直接选择返回；多槽所需的保持与
仲裁控制不应进入单槽的数据选择路径。没有增加固定流水级。面积和时序必须看相同异常
语义下的最终映射，不能依据中途不同版本的一次结果决定保留或放弃。

LSU 的两个本地异常也可能同时存在，必须保存受阻本地响应的槽位索引；不能因低编号槽位
重新分配就改变已经展示的异常。集成测试专门覆盖“槽 1 本地异常受阻时复用槽 0”。

## 访存路由的组合深度

700 MHz 复核定位到有效地址 → PMA → 请求窗口 → uncached AXI valid，原双槽版本差 8 ps。
uncached valid 单独使用“空闲或最后响应交付”的窗口；它不需要 cache 并发容量判断。
ready 和路由更新继续使用原统一握手规则，cache 可以在其他 cache 请求在途时继续接收。
两者继续支持空闲直通、响应与新请求同拍交接，仍由旧 route 状态选择响应，没有增加寄存器。
整体拆开 valid/ready 的初版映射退化到 660 MHz，已撤销，保留实测负结果。
只化简 uncached valid 后，700 MHz 仍差 2 ps。继续把 uncached adapter 的 AR/AW/W valid
按“已持有通道”与“新请求直通”两条互斥来源并行组合，避免先按状态赋值、再用新请求
优先覆盖的选择层。通道状态和新请求窗口互斥，载荷、AW/W 独立保持及响应交接不变。
这些改写均不增加周期；最终通道回归通过，双槽在同约束下通过700 MHz，故保留。

## 保留与消除的等待

| 边界 | 当前处理及依据 |
| --- | --- |
| LSU 空槽 → 存储请求 | 当拍直通；只有下游反压时保存请求。 |
| LSU 成功响应 → 槽位再分配 | 同拍复用；错误响应当拍阻止接收新请求，迟到响应不复用身份。 |
| D-cache hit → 下一查询 | 同拍交接；store hit 同址读写由字节合并旁路定义。 |
| D-cache miss 响应 → 下一 load | 响应当拍被接收、S1 空且阵列无冲突即可交接；不再固定空转。 |
| 被 miss 阻塞的 S1 | 等旧 miss 结束后同步重读；旧查询的 tag/data 可能已被回填或错误恢复改写。 |
| 同组安装、victim 采集 | 分别有 tag 读写冲突和数据读端口占用，保持等待。 |
| store/MMIO 发出 | 保留 ROB 队首授权，防止较老异常后的不可撤销副作用。 |
| 已展示且受阻的请求/响应 | 保持载荷及身份；这属于协议状态，不能用旁路绕过。 |

旁路覆盖正常可推进条件，不等于取消资源冲突或顺序约束。额外的 refill 数据/metadata
转发需要独立的面积、时序和触发次数证据；本次没有宣称同步重读已经被这种转发替代。

## 为什么不直接复制其他核

- BOOM 的 LDQ/STQ、未知地址投机、关联转发和违例重放服务于乱序发射窗口。本核尚无该窗口；
  直接复制不能解除顺序 Issue 中的 RAW，且要改变现有精确总线错误边界。
- CVA6 的身份管理值得采用；其已提交 store buffer 不能直接照搬。本核要求普通 store 在
  返回成功后才退休，若提前退休就需要重新定义后续总线错误的处理方式。
- HPDcache 的“预留缺失行、按阻塞原因重试”适合这里；其多请求方、多 MSHR、RTAB 和流水深度
  不作为必须复制的结构。当前只保留一个 miss 和一个被阻塞的 S1。
- Rocket 的 secondary miss 合并和 replay 可供后续扩展；TileLink 权限与一致性状态不是本核的
  AXI/PMA 条件。本次同行请求通过回填后重读完成，不宣称已经实现多 MSHR 合并队列。

这些是针对当前资源与错误语义的选择，不能推导出本核整体优于上述开源处理器。
