# 显式 Issue 级：实现与测量

> 本文是 9 月 29 日的历史测量。10 月 1 日已恢复部分退休旁路，当前实现与新对照见[退休旁路与作用验证](RV32_RETIRE_BYPASS_2026-10-01.md)。

本轮用真正的 Decode→Issue 边界替代 ROB 配置的强制 fetch buffer 落拍，统一 FU 完成写 ROB、Commit 读取已完成队首，并简化 PMA 组合编码。最终通过 720 MHz 的综合后 STA，但 **MicroBench 尚未证明开启 ROB 更划算**。保留可选后端，默认不开启；没有提交或推送。

当前结构见 [后端说明](../microarchitecture/BACKEND_DESIGN.md)和 [Issue 边界](../microarchitecture/ISSUE_DESIGN.md)。本文保存实验条件、失败尝试和结果，不充当另一份模块手册。

## 为什么此前 train 有退化

已核对用户两次运行：`passive-train-20260928T123834Z` 是引入 ROB **之前**的流水乘法版本；`passive-train-20260929T032154Z` 是强制 fetch buffer 落拍的 ROB 版本。两次均为 700 MHz，软件镜像一致，存储模型与缓存参数一致。

| train 子程序 | 引入 ROB 前 / ms | 上一版 ROB / ms | 变化 |
| --- | ---: | ---: | ---: |
| qsort | 37.979 | 39.124 | +3.01% |
| queen | 12.911 | 13.626 | +5.54% |
| bf | 28.622 | 29.720 | +3.84% |
| fib | 115.362 | 115.395 | +0.029% |

qsort、queen、bf 的计时区间没有乘除法指令，不能指望新增 MUL/DIV 重叠直接抵消恢复和后端管理的代价。此前关闭 fetch 空时直通确实增加首条交付延迟；完整回归通过不代表这项时序取舍对所有程序有性能收益。没有将全部退化都归因于这一拍，因为 ROB 控制和访存授权也发生过变化，尚无覆盖完整 train 的独立消融。

fib 是矩阵运算，不是简单的递归 Fibonacci。`mult` 的实际内循环包含：

```text
lw t6,0(t5)
lw t0,0(a3)
... 指针更新 ...
mul t0,t0,t6
lw t6,0(a4)
... 地址更新 ...
add t6,t6,t0
sw t6,0(a4)
```

单 LSU 无法同时处理多个 load，MUL 依赖前两次读取，累加和 store 又依赖其结果。源码支持“重叠空间受依赖与单 LSU 限制”的解释；没有该 train 窗口的独立 stall 归因，不将它写成已完成的瓶颈占比测量。已观察到的 fib 差距也只有约 0.03%。

## 电路取舍与 STA

综合流程未改：NanGate45、`AREA 3`、820 MHz 映射目标，同一网表按 20 MHz 间隔检查数据和 clock-gating 的 setup/hold。未放松约束。

| 候选 | 全检查组通过频率 | mapped cell area / μm² |
| --- | ---: | ---: |
| 上一版 ROB：fetch 强制落拍，DIV 不走退休旁路 | 700 MHz | 119,769.692 |
| fetch 直通 + 显式 Issue | 680 MHz | 121,607.752 |
| 上项 + 所有 FU 统一完成写 ROB | 700 MHz | 121,340.688 |
| 上项 + PMA 并行属性编码，最终保留 | **720 MHz** | **121,906.470** |
| 相同最终源码，ROB 关闭 | 680 MHz | 117,158.636 |

仅增加 Issue 不能解决 Execute 地址计算→LSU→PMA/选路→AXI 的长路径。统一完成边界切除 FU 完成到退休/年轻访存授权的反馈，保留完成到 Issue 的前递；没有新增结果数组，删除了失去用途的 `retire_bypass` 字段和选择器。

PMA 各物理地址区域不相交，最终改为并行生成权限、可执行、cacheable 等属性，避免地址计算后再经过串行属性选择。没有改地址区间、权限、请求周期或延迟模型。700 MHz 的 Total/Scored 周期与简化前完全一致。旧无 Issue 结构曾拒绝类似改法；本次重新综合后才保留，不能把源码层次减少等同于必然提频。

720 MHz：data setup +7 ps、gating setup +8 ps、data hold +59 ps、gating hold +97 ps。740 MHz：data setup −23 ps、gating setup −22 ps。最终限制包括乘法完成到 ROB 写入和 I-cache RRIP 的门控使能；最长路径已不再是 Decode→scoreboard。

这是综合后、理想时钟条件的结果，余量很小，不代表布局布线后芯片保证达到 720 MHz。

## 真正的 FU 重叠与性能

相同定向程序在旧流水乘法后端和最终后端运行，检查软件结果；除 CSR 专项外同时跑 NEMU DiffTest。

| 程序 | 原后端周期 | 最终后端周期 | 说明 |
| --- | ---: | ---: | --- |
| 独立 DIV/MUL/ALU/load 混合 | 6649 | 6111 | 减少 8.09% |
| 连续独立 MUL | 1076 | 1076 | 旧版已支持流水 MUL，没有新增收益 |
| 未命中 load 与独立 MUL | 623 | 532 | 减少 14.61% |
| 相依 MUL→DIV 循环 | 2536 | 2395 | 数据依赖不重叠，但独立循环控制可以重叠 |

混合程序观测到 129 次 MUL、129 次 load 在老 DIV 未完成时派发；连续乘法程序有 319 次相邻周期接收 MUL；访存程序有 32 次 MUL 在 LSU 等待期间派发。身份计数确认年轻指令先完成，软件结果与顺序退休检查通过。

这仍是**顺序发射、乱序完成**：忙碌 DIV 后面的另一条 DIV，或忙碌 LSU 后面的另一条访存，会阻止其后的指令继续派发。ROB 不是乱序发射队列。

| MicroBench test 配置 | MHz | Total 周期 | Total / ms | Total IPC | Scored / ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| 历史引入 ROB 前的冻结版本 | 700 | 2,220,172 | 3.172 | 0.217756 | 1.309 |
| 上一版强制 fetch 落拍 ROB | 700 | 2,251,654 | 3.217 | 0.214667 | 1.347 |
| 当前源码 ROB 关闭 | 680 | 2,171,419 | 3.193 | 0.222642 | 1.329 |
| 最终 Issue + ROB，同频比较 | 680 | 2,212,020 | 3.253 | 0.218275 | 1.373 |
| 最终 Issue + ROB | 700 | 2,262,764 | 3.232 | 0.213477 | 1.351 |
| 最终 Issue + ROB，合法上限 | 720 | 2,310,365 | 3.209 | 0.209031 | 1.331 |

时间取原生计时器；Scored 是多个整数微秒窗口之和，所以与累计周期换算可能相差数微秒。720 MHz 的 Scored IPC 为 0.330972。Total 包含更多非核心计算工作，不能与 Scored 混用。

同为 680 MHz，开启 Issue/ROB 的 Total 周期增加 1.87%。按各自合法频点，720 MHz ROB 的精细周期换算时间仍比当前 680 MHz 原后端长约 0.49%，面积×时间约差 4.56%。它比上一版 700 MHz ROB 略快，但没有超过历史引入 ROB 前的 700 MHz 版本。**不能据此宣称 ROB 已提升整体 MicroBench 性能，也不建议默认开启。**

最终 700 MHz 与上一版 ROB 的 D-cache 流量相同：11934 次 refill / 47736 words、8010 次写回；I-cache 完整安装由 2062 增至 2154。720 MHz 为 2155。上述均为整次仿真计数，不能直接归入某个计时窗口。没有功耗测量或完整 train 新结果。

## 验证与复现

通过：Issue 与 fetch buffer 各 10000 周期随机反压/flush；scoreboard 2/4/8 项随机查询；ROB 2/4/8 项随机完成、反压、恢复、满队列交接和完成前递；36 项后端恢复；整核算术、精确异常、非分支错误 taken、FENCE.I/缓存错误、中断、量化内核；原生 MicroBench test。没有关闭断言或删除失败测试。

新增 CSR 对齐程序保留 `mscratch` 自检。NEMU 在 CSR 0x340 主动报不支持，因此此项使用程序自身常量检查，其余四个新程序仍使用 DiffTest。初版访存测试读取未初始化地址，DUT 的 0 与 NEMU 的 0x67676767 不同；改为软件镜像中的已初始化数据，并保留数据校验。失败日志留存。

PMA 对照固定参考提交，检查 200000 个随机地址、130 个区域边界地址及 CHIPLINK 0/1。它是对照仿真，不是形式证明。

在仓库根目录执行：

```sh
python3 npc/scripts/test_backend_input.py --output npc/result/issue-recheck/input
python3 npc/scripts/test_backend_rob.py --output npc/result/issue-recheck/rob
python3 npc/scripts/test_backend_recovery.py --output npc/result/issue-recheck/recovery
python3 npc/scripts/test_pma_equivalence.py --output npc/result/issue-recheck/pma
python3 npc/scripts/measure_execute_ppa.py --output npc/result/issue-recheck/ppa \
  --name issue --mul-pipeline 1 --backend-rob 1 --backend-entries 4 --load-overlap 1
python3 npc/scripts/run_microbench_perf.py --scale test --isa rv32im \
  --mul-pipeline 1 --backend-rob 1 --backend-entries 4 --load-overlap 1 --cpu-mhz 720 \
  --icache-bytes 1024 --icache-ways 4 --icache-line 32 --icache-policy 13 \
  --bht-entries 16 --btb-entries 16 --btb-ways 2 --btb-policy 0 \
  --direction-policy 0 --history-bits 4 --ras-entries 4
```

手动测新版本 train 时将最后一条的 `--scale test` 换为 `--scale train`。原来已经启动的仿真不会因修改源码变成新版本，必须重建后重新运行。ROB 关闭对照使用 `--backend-rob 0 --load-overlap 0 --cpu-mhz 680`；两者同频比较均用 680 MHz。
