# RV32 等待与旁路优化迁入 RV64

2026-09-24。目标是 `ysyx-workbench/npc` 的 RV64 单发射顺序核。
来源为 `ysyx-workbench-rv32-interview` 提交 `47c852e12b9ce086b872095f59cf54fbe5a6fda6`。
这次采用逐模块适配。两个目录都有未提交改动，整仓 merge 会带入实验预测器与不同平台语义。
源 HEAD 已包含等待优化、H1 末字采集旁路、老异常阻止年轻访存、过期预测和脏数据恢复修复。
源工作区新增的策略 13 已在前一轮同步；其余未提交的方向预测、压缩 BTB 等实验没有带入。

## 迁入了什么

| 范围 | 采用的改动与保持条件 |
| --- | --- |
| 流水线 | 合并译码与读寄存器组合路径；ID/EX 保留单项；保留 EX 结果与 WB 寄存边界 |
| 操作数与 LSU | load 成功交付时前递；空闲请求直通；成功完成允许年轻普通结果进入空 EX 结果级；异常和反压仍阻止越过 |
| 精确异常 | 老 EX 结果的异常立即阻止年轻 LSU；普通 FENCE 不额外排空无关 ALU；CSR/FENCE.I 继续串行化 |
| 前端 | BHT/BTB/RAS 拆开管理状态；一级预测响应；直接训练；IFU 和取指队列直通，保持被反压的旧请求 |
| 恢复 | 当拍选择 redirect；非分支携带过期 taken 预测时在 EXU 分流前纠正至 PC+4，当前指令继续交付 |
| I-cache | miss 分配直接请求 refill；关键字响应直通；排空后一次清除有效位；保留策略 13 的替换查询旁路 |
| D-cache | 命中与下一查找交接、store 字节前递、末字采集直接发写回、最后必要响应直接安装并完成、clean 跳过干净项 |
| 数据与系统总线 | 空闲请求直通，独立 AW/W 握手，成功响应与新请求同拍交接；旧响应和新地址分别确定归属 |
| 错误与维护 | 写回失败保留并恢复 dirty 数据；FENCE.I 先停止预测、排空取指，再 clean 和 invalidate |

共享 victim 缓冲、压缩 CSR 状态、分段 PMU 计数器和 x0 不存储等改动，目标工程此前已经
具有相应实现，不能全部算作本次新增收益。PMU 只同步按状态归属组织代码。
旧译码级、读寄存器级和重定向寄存器文件保留，移出活动 filelist；不删除历史和实验材料。
逐文件变更与保留项见证据目录的 `rtl-inventory.json`。

## 哪些没有直接搬过来

- 保留目标 RV64 的 XLEN/核数据/AXI 数据 64 位、物理地址 32 位、指令 32 位，保留 CSR 行为。
- I-cache 仍为 1 KiB、4 路、32 B 行、策略 13；BHT 16 项、BTB 16 项/2 路、RAS 4 项；
  D-cache 仍为 4 KiB、2 路、64 B 行。
- 源分支的定时器中断、CLINT 计时/寄存器扩展与复位物理边界属于平台改动，未混入本次移植。
  CLINT 的响应交接也保留目标实现，后续连同定时器合同单独验证。
- RV32 的同宽 SoC 转换直通不能替代 RV64 的 64→32 位拆分；目标转换器保留并通过原定向测试。
- 保留目标 FENCE.I 清理失败后阻塞并重试的策略，没有采用源分支等复位的停机策略。
- 不采用源分支已撤回的“写回接收同拍发 refill”候选，也不声称实现了缺失完成同拍接收下一查找。
- 没有加入 gshare、TAGE、压缩 BTB、推测历史、乱序结构或 AI 专用指令。

## 同配置周期比较

35 个软件镜像 SHA-256 及 NEMU 参考库 SHA-256 均与前一轮完全一致，每个程序退休指令数一致。
总周期由 **1,232,427 降至 752,876，减少 38.9%**；各程序减少 30.7%～45.2%。
这是同一功能回归集合的周期变化，不能当作 AI 推理吞吐，也不能在没有时序依据时换算最高频率。
逐程序数据见 `software-comparison.json`。

## 面积与时序

以 `riscv_core` 为顶层，使用相同 Nangate45 typical 库、DELAY 0、300 MHz 约束。
两版均采用理想时钟，输入/输出延迟为周期的 20%，输入转换时间 0.1 ns；复位路径设为 false path。
缓存映射为标准单元阵列，没有 SRAM 宏，也没有布局布线与功耗测量。

| 指标 | 迁移前 | 迁移后 |
| --- | ---: | ---: |
| 映射标准单元面积（µm²） | 372,254.232 | 350,962.262 |
| 映射单元数 | 164,803 | 155,085 |
| setup 最差裕量（ns） | +0.454 | **−1.014** |
| setup TNS（ns） | 0 | −41,707.658 |
| hold 最差裕量（ns） | +0.057 | +0.060 |
| 电容与转换时间检查 | 存在违规 | 存在违规，最差项恶化 |

面积减少 **5.72%**，但**迁移后未通过 300 MHz 的 setup 检查**，不能把周期减少写成
频率也提高。两版 hold 和时钟门控检查在当前报告中具有正裕量；这不代表物理实现收敛。

最差路径从 AXI 响应输入经过 D-cache 回填/错误控制和写数据选择，进入数据阵列。
写数据网 `data_write_word_data_45_` 驱动 512 个寄存器输入，末级单元延迟约 2.985 ns。
电气报告最差转换时间裕量由约 −1.137 ns 恶化至 −2.531 ns，电容裕量由约 −0.523 pF
恶化至 −0.558 pF。旁路控制和缓存映射共同影响该路径，不能把全部退化归因于某一项旁路。

**下一步优先处理此路径。** 在明确的 SRAM 宏或标准单元分 bank 实现下处理高扇出、缓冲和
写数据选择，再评估是否需要在回填完成处增加寄存边界。改动后须重跑旁路与错误恢复回归，
同时比较周期、面积、时序；不能只用减少等待拍数作为最终取舍依据。

两次综合驱动检查均为 0 个问题，综合与 STA 进程均返回 0；STA 正常结束不等于时序通过。
日志没有报告未约束路径，但未做独立约束覆盖审计。两版均有理想时钟零转换时间的库查表范围告警，
高扇出数据线还存在电气违规，因此不采用工具推算频率作为最高工作频率。
完整约束、库与脚本哈希、网表和报告见证据目录 `ppa/`。
