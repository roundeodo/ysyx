# 减少综合后缓冲器面积

2026-09-25。接续 [复位与电气修复](RESET_ELECTRICAL_FIX_2026-09-25.md)。

本轮针对 6,249 个新增 BUF_X2 的面积成本做对照。CPU RTL、库、原始映射网表、
700 MHz 时钟、输入延迟、输入转换时间、输出延迟和每端口 10 fF 输出负载保持一致。
只改变综合后缓冲插入策略，不修改功能 RTL，不增加流水级，不关闭时序或电气检查。

## 旧策略的问题

旧脚本同时限制单元输出扇出不超过 16、负载不超过 Liberty 电容上限的 65%。
这两个项目策略比库的电容限制更保守，不能把因此增加的全部缓冲认定为电路必需。

按原始映射网表逐个驱动端计算接收引脚电容后：

- 400 条网络超过库电容上限。
- 2,214 条网络没有超过库电容上限，但触发了旧的扇出或余量规则。
- 另外两个常量驱动没有库电容上限，旧脚本仍按项目扇出规则处理。

电容未超限不等于时序和转换时间一定通过，因此最终方案仍须运行完整 STA。

## 完全不加新增缓冲的对照

原始映射网表面积为 123,395.804 µm²，能够完成综合。700 MHz 下完整验收失败：

| 检查项 | 原始网表结果 |
| --- | ---: |
| 最大延迟检查，最差端点为 LSU 寄存器 RN 的 recovery | −2.391 ns |
| 门控最大延迟检查 | −2.398 ns |
| 数据最小延迟检查 | +0.060 ns |
| 门控最小延迟检查 | +0.097 ns |
| 电容、转换时间 | 均有违例 |

复位释放寄存器直接驱动 593 个输入，总负载约 1.044 pF，库上限约 0.0606 pF。
其中包含 585 个核内异步控制端及其他复位相关逻辑。其他超限网络主要位于 I-cache，
还包括驱动较多寄存器的门控时钟输出。这些驱动问题需要处理，不能将综合命令成功视为时序通过。

## 最终选择

默认改为只修复库电容上限超限的网络，不额外设置全网扇出上限，不再使用 65% 的电容预算。
转换时间、数据与门控的最大/最小延迟、复位连接和逻辑连接等价检查全部保留。

| 方案 | 新增 BUF_X2 | 标准单元面积 µm² | 700 MHz 完整验收 |
| --- | ---: | ---: | --- |
| 上一轮扇出 16 / 65% 电容预算 | 6,249 | 130,044.740 | 通过 |
| 完全不加新增缓冲 | 0 | 123,395.804 | 失败 |
| 本轮按实际电容上限修复 | 812 | 124,259.772 | 通过 |

相对上一轮删除了 5,437 个不再需要的缓冲，新增缓冲数量减少约 87.0%，全核面积减少
5,784.968 µm²（约 4.45%）。相对原始映射网表只增加 863.968 µm²（约 0.70%）。
812 个是本轮通过验收的实现结果，不是已经证明的理论最少数量。

| 最终检查项 | 实测结果 |
| --- | ---: |
| 数据建立 / 最小延迟裕量 | +0.053 / +0.060 ns |
| 门控建立 / 保持裕量 | +0.050 / +0.097 ns |
| 最大 / 最小延迟 TNS | 0 / 0 ns |
| 电容约束 | 通过；最差报告裕量舍入到 0.000 pF，全量静态负载检查未超限 |
| 最差转换时间裕量 | +0.061 ns |
| 单元输出实际最大扇出 | 160；未施加额外的全网扇出限制 |

本轮网表无需额外缩短关键缓冲连接，就通过了全部检查。复位审计仍覆盖 585 个核内异步控制端。
功能 RTL 与上一轮保持一致，沿用其两项复位定向测试和 35 项 RV64 DiffTest 结果；本轮没有
冒称重跑功能回归。新增和相关 Python 检查共 7 项通过，验证关闭扇出策略后仍修复电容超限。

## 正式入口与复现

`make sta` / `make sta-qualified` 默认使用 `STA_MAX_FANOUT=0`、
`STA_CAPACITANCE_FRACTION=1.0`。0 表示不施加额外的项目扇出上限，库中的电容和转换时间
约束保持生效。需要重现旧策略时可显式指定 16 和 0.65，不能将它们写成所有网络的库硬要求。

```sh
make -C npc git_commit= sta \
  STA_QUALIFIED_OUTPUT_DIR="$PWD/npc/result/sta/buffer-cap-only-replay"
```

首次对照在 `cap-only-100/` 完成实际 STA；正式生成脚本在 `public-repair/` 重新生成网表，
SHA-256 与已测候选完全相同，随后复用同库、同约束、同频率的报告，在 `final/` 重做连接审计
及完整验收。复用关系写入 `public-repair/provenance.json`，不将报告复用写成第二次独立 STA。
`final-audit.json` 绑定原始网表、最终网表、RTL、库、约束与脚本版本。

这仍是 Nangate45 typical、理想时钟、固定输入输出负载下的综合后结果；布局布线后需根据实际
寄生参数重新优化缓冲和驱动强度。上一轮完整记录保留，不覆盖历史面积或失败报告。

证据目录：`result/verification/buffer-area-20260925/`。
`before/` 保存本轮修改前的脚本、测试与指导文档；上一轮全部网表和测量记录保留。
