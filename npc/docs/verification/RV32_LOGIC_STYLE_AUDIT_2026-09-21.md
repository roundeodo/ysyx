# RV32 逻辑与可读性复查

基线：`rv32-interview-20260911`，`63206ba`，RV32 baseline 参数。
本文记录修改前的检查与实施计划，对应基线 `63206ba`。
后续源码整理、候选实现及测量结果见[实施记录](RV32_REFINEMENT_2026-09-21.md)；下文的
“当前问题”“尚未修改”均指检查时的基线，不能作为后续工作树的状态说明。

检查结论：主要直通路径已经存在，但缓存事务交接还有可验证的候选，部分源码顺序仍需整理。

## 仍有等待的地方

| 编号 | 当前位置与行为 | 可以尝试的电路改动 | 必须验证的条件 |
| --- | --- | --- | --- |
| H1 | `dcache_miss_unit`：最后一个 victim 字已从同步读口返回，仍先进入 `MISS_SEND_WRITEBACK`，下一拍才发写回请求 | 最后一个字直接并入行数据，当拍发写回；反压时保存完整行 | 单字行、AW/W 独立反压、从请求接受到 B 响应期间的行数据稳定；不能只提前 valid |
| H2 | 同模块：普通 dirty miss 的写回请求被 adapter 接收后，下一拍进入 `MISS_SEND_REFILL` 才发 refill；读通道即使空闲也等待 | 写回请求被接收的同拍发 refill，允许独立读写通道重叠 | 发 refill 前失效 victim；R/B 任意先后与错误；写回仍未完成时不能提前安装或报告成功 |
| H3 | `dcache`、`icache`：miss 最后完成沿仍因 `miss_transaction_present` 关闭下一 lookup | 允许最终完成与下一查询交接；分别补齐 metadata 和 data 的读写同址旁路 | 最后一字、同 set/way、不同 set、错误、响应反压和失效冲突。I-cache 的低电平锁存写窗口还需单独处理 |
| H4 | `fence_i_ctrl`：前端已经空闲时仍经过 `DRAIN_FRONTEND`；D-cache clean 完成后再下一拍发 I-cache invalidate | 对已满足的维护条件直接交接 | 提交同拍是否接收了取指请求、已呈现且受阻的 valid、clean/invalidate 的唯一完成及前端恢复时刻 |

H1、H2 各有一个阶段交接周期可研究，不等于整程序必然各少一拍：下游反压可能覆盖收益。
H3 是阻塞式 cache 的交接边界，不能只放宽 ready；H4 不要求把所有维护操作改为并行。
这些候选尚未做改动后的面积、STA 和 workload 对照，不标为“已证明更优”。

还发现 `hazard_ctrl` 对串行化指令统一等待老 WB 离开，即使老指令只是普通 ALU。
可单独研究成功提交的同拍交接，但 CSR 在译码读值且没有提交写前递，异常/中断也在提交点处理，不能整体删除串行化条件。
`icache_axi` / `dcache_axi` 的末响应与新事务尚不能同拍交接；当前上层也不能在该拍提供下一事务，单改 adapter 不会消除上述整条路径的等待。

## 是否值得优化

下面是处理优先级，不是改动后的性能结论。规模估算引用最近的
[train 报告](../../result/performance/passive-train-20260919T230802Z/report.json)和
[整程序计数](../../result/performance/passive-train-20260919T230802Z/simulation.log)：
600 MHz，整程序 1,018,187,017 拍；不套用 Total/Scored 窗口。

| 项目 | 决定与依据 |
| --- | --- |
| 过时注释、无语义别名、重复表达式、源码顺序 | 优先整理。维护收益明确，按等价性验收；不预报面积下降。公共函数仅在语义相同且能简化阅读时提取，不强制共享实际运算器 |
| H2：写回接收与 refill 交接 | 优先做小候选。已有独立读写通道，主要改阶段控制；仍需处理请求反压和错误，不应增加新的宽缓冲 |
| H1：最后 victim 字与写回交接 | 在 H2 后独立尝试。需处理最后一字的选择、单字行和整行保持；若为一拍收益引入明显数据 mux/面积代价，则保留现状 |
| H3：I-cache 完成与查询交接 | 先补触发计数，再决定。整程序有 7,233,852 次 cacheable 回填完成，按每次理想省一拍约 12.06 ms（0.71%）；实际还要有下一请求且不能被其他等待覆盖，需评估 tag/data 旁路及锁存写窗口 |
| H3：D-cache 完成与查询交接 | 暂列低优先级。虽然有 2,610,689 次 miss，但全部可见 lookup 请求等待只有 409,519 拍，合计约 0.683 ms（0.040%）；并非这些等待都来自 miss 完成交接，不能按每次 miss 都省一拍报告收益 |
| H4：FENCE.I 阶段交接 | 不作为当前 train 加速的优先项。归档镜像反汇编只在启动段 `0x3000005c` 出现 `fence.i`，在基准计时前；未来有频繁代码更新负载时再测，简单且能减少状态复杂度的整理可以单独考虑 |
| 串行化指令与普通 WB 同拍交接 | 暂缓。涉及 CSR 译码读值、提交写入、异常和中断优先级，先测此类阻塞次数，不能整体放开串行化 |
| 单独给 cache AXI adapter 加事务交接 | 暂不做。上层当前不能及时给出下一事务；等上层交接有收益证据后再决定是否需要 |
| 预测反馈寄存器、反压保存、同步阵列读、剩余 burst 排空及异常年龄限制 | 按现有结构保留。这些承担实际时序、协议或正确性责任，不能以数量少为目标直接删除 |

H1/H2 对 704,017 次普通脏行 miss 若各理想节省一拍，合计约 **2.347 ms、0.138%**。
这是事件数乘局部周期差的静态估算，不是程序实测，也不是考虑全部总线竞争后的严格上界。
如此小的周期收益，若导致明显降频、增大面积或显著增加维护难度，就不值得保留。
H3 应观察“最终响应/回填完成且下一请求 valid、其余资源可用但 ready 关闭”的事件，
并区分同址/异址及反压情况；当前整程序计数没有单列这个交集，不能据此保证收益。

## 明确的代码冗余与阅读问题

| 位置 | 当前问题 | 应采用的整理方式 |
| --- | --- | --- |
| `icache` 文件头、`core` 维护断言旁、实验 `redirect_arbiter` 注释 | 分别仍描述已删除的 invalidate FSM、已寄存的重定向、当前核使用寄存恢复模块 | 注释只描述现存电路；历史说明留在历史记录 |
| `icache` 的 `refill_metadata_write_* → metadata_write_*` | 旧选择器删除后剩五条一对一别名；`lookup_s1_ready` 中又存在被 `!miss_req_valid` 排除的 miss 握手项 | 合并无语义变化的接线，化简条件；不要宣称删除了五组寄存器 |
| `core` 的 `idu_decoded_uop → decoded_uop` | 取消独立译码级后仍留下 payload/valid/ready 三条别名 | IDU 直接连接现有译码通道；同时检查监视器引用 |
| `icache`、`dcache` | 阵列实例在前，驱动读写端口的选择逻辑在数百行之后 | 先说明端口所有权；按请求选择、同步读、比较/响应、miss 与维护反馈组织局部电路，不把所有声明集中到文件头 |
| `clint` | 计时寄存器更新依赖很后面的写译码；64 位 `mtime_read_snapshot` 实际只读取高 32 位 | 接口写握手/译码放到状态更新的依赖说明附近；快照改为语义明确的高半部分之前检查调试引用 |
| `dcache` 与 `dcache_miss_unit` | 两份相同 `merge_store_bytes` 函数 | 可以共享纯函数定义；两个实际数据通路仍分别需要字节选择，不能把源码复用当作面积收益 |
| `lsu`、`exu` | 同一移位表达式重复用于 byte/half/word；顺序 PC、分支目标等有重复表达式；LSU 紧凑上下文又展开为宽请求给辅助函数使用 | 命名一次实际公共值，辅助函数只接收所需字段；不要据此推断综合器生成了多份运算器 |
| `dcache_axi` | IDLE/SEND 重复构造相同 AXI 属性 | 公共属性只定义一次，当前/保存 payload 的选择和 valid 控制分开；改变 mux 位置仍需看映射结果 |
| `common/riscv32_pkg`、`sim/` | 存在旧 P0/P4 阶段说明、实验类型穿插、字段访问被拆成多行等格式残留 | 实验类型集中标注；当前接口按数据流排列；恢复正常的字段访问与续行缩进 |

源码别名、未消费字段和重复表达式通常会被综合器消除；本轮没有将它们计作已确认的物理面积冗余。
`mtime` 高半快照本身必须保留，低半读与随后高半读之间不能发生撕裂。

## 逐模块覆盖

下表覆盖 STA 清单全部 **45 个模块、5 个 package**；模块名省略 `riscv32_`。
“未发现新增固定空拍”仅表示本轮源码检查结论，不表示形式化证明所有状态或所有参数均最优。

| 模块 | 电路与检查结论 |
| --- | --- |
| `pma` | 组合区域/权限译码，无等待状态 |
| `bht`、`btb`、`ras` | 并行组合查询，解析事件训练；没有各自再加查询流水级。表/栈是算法状态 |
| `branch_predictor` | 一项弹性预测响应；该寄存边界切断 next-PC 反馈，不能直接全部组合化 |
| `ifu`、`fetch_buffer` | 请求队列和指令队列均有空队列直通与同拍出入；保留受阻请求、身份与 epoch |
| `icache` | 命中直接返回；H3 及接线/代码顺序问题 |
| `icache_tag_array`、`icache_data_array` | 同步读；有效位一次失效；写暂存保证锁存阵列低电平写窗口，不能当作多余指令流水级删除 |
| `icache_miss_unit`、`icache_axi` | 分配直发 AR、关键字直接响应、反压才保存；余下 burst 仍需排空。事务交接见 H3 |
| `idu`、`regfile`、`operand_mux` | 组合译码、异步 GPR 读和前递；没有独立 RR 寄存级，x0 不占寄存器阵列 |
| `id_ex_reg` | 单项弹性执行上下文，没有第二份 skid；类型标志用于缩短控制路径，不构成额外一级 |
| `exu` | 组合 ALU/AGU/分支/CSR；有表达式和默认赋值可简化，没有内部等待 FSM |
| `ex_result_reg` | 保存结果、预测校验和异常身份；删级会改变恢复、年龄关系和路径长度，不能只看结构体相似 |
| `lsu` | 空闲直发、成功完成交接和 load 前递已存在；本地异常仍须遵守较老 EX 结果的顺序 |
| `data_mem` | PMA 路由与旧事务返回身份分开；当前/保存请求选择服务实际反压，无新增固定阶段 |
| `dcache` | hit 连续查询、store 同址字节前递、clean 跳过非脏 way 已存在；H3 及代码顺序问题 |
| `dcache_tag_array`、`dcache_data_array` | 同步读，store/read 同沿旁路由顶层负责；最终 refill/read 交接需另补旁路 |
| `dcache_miss_unit` | H1、H2；分配直发、最后必要 R/B 当拍完成已存在，错误和 B 未完成时仍需等待 |
| `dcache_axi`、`uncached_axi` | 空闲 AR/AW/W、响应直通已存在；uncached 成功完成可接下一请求，独立 AW/W 进度与错误限制保留 |
| `completion_mux`、`commit` | 组合汇合与提交控制，没有附加流水级 |
| `wb_reg` | 一个提交边界，可同拍出入，提交恢复清年轻 valid |
| `csr_file`、`pmu` | 组合读与架构状态更新，没有访问 FSM；计数器不是仿真侵入造成的等待 |
| `hazard_ctrl` | 最近生产者优先前递、LSU 成功交接已存在；老异常/老 LSU 约束必须保留，串行化末拍可单独研究 |
| `interrupt_ctrl` | 架构恢复 PC 与后端排空；CSR/提交优先关系必须一并考虑 |
| `trap_ctrl`、`redirect_mux` | 组合优先级与恢复，无额外 redirect 寄存级 |
| `fence_i_ctrl` | H4；FSM 输出、次态、时序的书写顺序符合规范 |
| `core` | 装配与事件连接；译码别名、过时注释和局部排序待整理 |
| `axi4_arbiter`、`axi4_router` | 末 R/B 与新地址交接已有；保存受阻地址所有者及读写路由是必要协议状态 |
| `axi4_clint` | 末 R/新 AR、B/新 AW/W 交接已有；计时、快照保留，源码宽度/顺序待整理 |
| `reset_controller`、`core_reset_boundary` | 复位同步/释放与综合边界，不能按指令周期优化删除 |
| `npc_system`、`npc_axi` | 系统/SoC 接线，无附加硬件流水状态；DPI GPR 读函数有重复的 x0 判断 |
| `axi4_soc_width_converter` | RV32 同宽分支五通道组合直通；RV64 分支未在本轮做功能穷举，其状态不进入 RV32 硬件 |
| `riscv_config_pkg`、`addr_map_pkg`、`axi4_pkg`、`ysyx_soc_axi4_pkg`、`pkg` | 配置、类型、常量与函数；不实例化 ROB/PRF 等实验硬件，但混合实验定义影响阅读 |

目录内另外检查了 **7 个仿真模块、1 个 DPI 头文件、7 个实验模块、2 个 filelist** 的用途、引用和控制边界。
仿真监视器不反向控制 ready/stall；standalone memory/UART 的延迟与事务间隔属于测试环境，不能通过缩短它们冒充 CPU 优化。
历史 decode/register-read/redirect 和独立 ALU/移位/七段码/error-target 实验不在正式硬件清单；保留源码，不算作当前 CPU 面积。
本轮对仿真统计和历史实验做的是结构与引用检查，没有重跑它们的所有功能场景。

## 验证与后续改动顺序

本轮定向探针沿用 D-cache miss 的 **24 个** R/B 顺序、错误、反压与 clean 用例，全部通过，并额外观察 H1/H2 和完成边界。
另一个探针隔离前端已空闲的 FENCE.I，维护正常完成。

| 实测观察 | 结果 |
| --- | --- |
| 最后一字返回且写回接收端 ready，但写回 valid 尚未拉高 | 20 次：18 个 dirty miss、2 个 clean，各一拍 |
| 普通 dirty miss 写回请求握手且 refill 接收端 ready，但 refill valid 尚未拉高 | 18 次，各一拍 |
| miss 响应握手时新 miss 的 ready 仍为 0 | 22 次；该探针未同时驱动下一请求，不将次数换算为程序损失周期 |
| FENCE.I 前端已空闲的 drain 阶段 | 1 拍 |
| clean 完成当拍 invalidate 尚未发出 | 1 次，下一拍才发出 |

这些测试用于确认现状，不是候选 bypass 的验收，也不替代整核回归。
配置、源文件 SHA256、探针与原始日志保存在 [本轮记录目录](../../result/verification/rv32-logic-style-audit-20260921/)。

实施顺序按上方取舍：先做源码整理和 H2/H1 小候选；H3 先计数，H4 等低优先项暂缓。
每个功能候选都先检查准确的握手沿、反压、错误与唯一副作用，再做精确异常/中断回归、组合环、同条件面积/STA 和 workload 对照；确认更优后才保留。
本次基线检查没有产生新的综合或 train 成绩；后续结果由上述实施记录单独维护。

额外边界：D-cache clean 的总线错误在 `core` 中通过仿真断言报告，没有接入架构 trap 恢复。
这不是等待优化；若扩展该故障场景的支持，需要另行设计并验证，不能把断言当成硬件异常处理。
