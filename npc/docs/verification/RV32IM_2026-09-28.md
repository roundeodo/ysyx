# RV32IM 集成与测量

这是初次集成时的测量快照；当前 640 MHz 配置与电路变更见[后续时序优化](RV32IM_TIMING_2026-09-28.md)。
本文的 580 MHz 和旧延迟模型结果保留为历史对照，不作为当前 train 成绩。

电路见[乘除法设计](../microarchitecture/MULDIV_DESIGN.md)。本轮新增八条 M 指令和
独立 `rv32im-balanced` 预设，原 `rv32-balanced` 保持 RV32I。工作在本地 interview
目录完成，未推送。工作区原有的前端研究及 2026-09-27 写通道延迟校准均保留。

## 基线与对照

冻结起点：`47c852e12b9ce086b872095f59cf54fbe5a6fda6` 加当时工作区差异；不能把这个
commit 单独当作已发布稳定版。`npc/result/rv32im-20260927/baseline.json` 记录源码
SHA256，`baseline/`、`baseline.diff` 保存修改前源码和差异。

全部对照使用 1 KiB / 4-way / 32 B / policy 13 的 I-cache，256 B / 2-way / 16 B
的 D-cache，16 项 BHT、16 项两路 BTB、4 项 RAS，关闭预测器实验策略。
MicroBench 软件分别为 `rv32i_zicsr_zifencei` 和 `rv32im_zicsr_zifencei`，ILP32、`-Os`。
`--isa rv32im` 同时启用 M 硬件；两个 ISA 使用不同 AM 构建目录。

原生 CLINT 仍输出微秒，仿真端被动统计相同取样窗口内的周期与退休数，未插入 CSR
计数代码。所有 SoC 外设源文件的 SHA256 在各组实验中一致；工具版本、镜像、
完整命令和归档源码哈希见本目录 [data/rv32im-2026-09-28](data/rv32im-2026-09-28/)。

## 性能结果

先比较两个都能通过 STA 的 **580 MHz**，单位为原生定时器毫秒：

| 指标 | RV32I 软件/硬件 | RV32IM 软件/硬件 |
| --- | ---: | ---: |
| MicroBench test Total | 5.952 | 5.068 |
| MicroBench test Scored | 2.228 | 1.955 |
| Total IPC | 0.224418804 | 0.144975502 |
| Scored IPC | 0.332703203 | 0.280534784 |

Total 缩短 **14.9%**，Scored 缩短 **12.3%**。硬件指令替代软件例程后，退休指令数
下降，IPC 也可以下降；性能判断使用时间/周期，不能只比较 IPC。
RV32I 原镜像在启用 M 的硬件上运行时，Total、Scored、整程序的周期和退休数与原核
完全一致，排除了新增执行控制本身使原有指令变慢的情况。

额外的 int8 点积代理做 256 组 64 项有符号点积及标量除法归一化，数据共 128 B。
结果由 Python 整数模型计算，两个软件镜像均通过 NEMU DiffTest。相同 RV32IM 硬件上，
RV32I 软件用 2,385,341 拍，RV32IM 软件用 192,451 拍，约 **12.39 倍**同频加速。
它使用 standalone NPC 平坦存储模型，计数覆盖整程序，不是 SoC 定时器结果，也不代表
完整神经网络、SIMD 或矩阵指令性能。短测与这个代理都不能外推为 train 的完成时间。

### 跨主频结果的限制

720 MHz 下：I 的 Total/Scored 为 6.567/2.242 ms；IM 为 5.827/2.011 ms。
IM 网表没有通过 720 MHz，该组只用于周期对照。各自通过 STA 的频点下，当前模型
输出 I@720 的 6.567/2.242 ms，以及 IM@580 的 5.068/1.955 ms。
**不能把这个跨频率差值直接称为真实硬件加速。**

原因有实测证据：相同 I 镜像、相同 79,008 次 D-cache 查询和 12,188 次缺失，
降到 580 MHz 后定时器总时间反而减少。clean miss 为 83.612/720≈116.1 ns 与
67.282/580≈116.0 ns；dirty miss 则为 488.508/720≈678.5 ns 与
310.502/580≈535.3 ns。异常差异主要出现在含写回的路径，指向当前延迟校准模型的
频率敏感性；后续[并发读写诊断](TIMING_AUDIT_2026-09-28.md)已复现写校准等待
通过 SDRAM 仲裁进入读计时器并再次放大的路径，尚未量化其对整个 train 的贡献。
定时器/周期同窗校验通过不能证明
访存模型具有正确的跨频率物理行为。本轮没有更改延迟模型，主结论采用同频数据。

## 面积与时序

统一 NanGate45、Yosys/Slang、AREA3、820 MHz 映射目标；带实际复位边界和复位树，
iEDA 检查数据 setup/hold、时钟门控 setup/hold。频率按 20 MHz 网格实测通过点及
相邻失败点，都是综合后 STA，不是布局布线后的硅上频率。

| 配置 | mapped cell area / μm² | 通过频点 | 上邻失败点 |
| --- | ---: | ---: | ---: |
| 冻结 RV32I | 101,418.618 | 720 MHz | 740 MHz |
| 当前源码关闭 M | 101,584.336 | 720 MHz | 740 MHz |
| RV32IM | 106,355.578 | 580 MHz | 600 MHz |

相对冻结基线，面积增加 4,936.960 μm²，约 4.9%；相对当前源码关闭 M 的对照，
增加约 4.7%。关闭 M 后周期和通过频点保持不变，重映射面积比冻结版高约 0.16%。
580 MHz 同频 Total 的面积×时间比为 0.892，约降低 10.8%。M 网表在 580 MHz 最差数据裕量 +0.019 ns，
600 MHz 为 −0.027 ns。当前最差路径从 ID/EX 操作数经地址加法、LSU 请求选择与
数据通路到数据 AXI 输出，报告中不是乘法器部分积路径。全核重新映射后的频率变化
不能全部归因于乘法器组合延迟。这里采用经过验证的 580 MHz，没有增加通用流水级。

## 正确性与复现

- 单元：11,359 个向量，覆盖八操作、符号边界、除零、溢出、151 次取消、发出暂停、
  随机长度末拍反压及非分支错误 taken 恢复；M 关闭时拒绝全部 M 编码。
- 整核：2,803 个算术/寄存器别名/RAW/访存用例通过 NEMU；misa.M、老异常阻止年轻
  除法及 store 通过程序自检。配置、IDU、ALU、CSR、流水线及 RV64I IDU/ALU 回归通过。
- 中断：除法迭代时注入 IRQ，保持 25 个 EX 等待周期后再受理；检查结果、mepc 和
  mret，覆盖 0/83 拍总线延迟。原 CLINT、AM、中断及 IFU 恢复用例仍通过。
- 精确异常 80 项、FENCE.I/非分支纠错/写回错误恢复整核测试 100 项通过，含旧跳转改成 MUL/DIV。
- test 的十个子项全部通过；没有运行 train。分项周期与退化情况见机器结果，不仅保留
  加速项。编译器改变了代码地址和访问序列，非算术子项不保证加速。

以下在 `ysyx-workbench-rv32-interview` 根目录执行；`CAPSTONE_HOME` 指向本机已有安装，
在其他机器上换成实际位置。

```sh
export NPC_HOME="$PWD/npc"
make -C npc NPC_CONFIG=rv32im-balanced git_commit= test-muldiv
make -C npc NPC_CONFIG=rv32im-balanced git_commit= \
  CAPSTONE_HOME=/home/yong/ysyx/ysyx-workbench/nemu/tools/capstone/repo test-muldiv-core
make -C npc NPC_CONFIG=rv32im-balanced git_commit= test-timer-interrupt
python3 npc/scripts/measure_muldiv_ppa.py --output /tmp/rv32im-ppa \
  --baseline npc/result/rv32im-20260927/baseline
```

手动运行完整 train：

```sh
python3 npc/scripts/run_microbench_perf.py --isa rv32im --scale train --cpu-mhz 580 \
  --icache-bytes 1024 --icache-ways 4 --icache-line 32 --icache-policy 13 \
  --bht-entries 16 --btb-entries 16 --btb-ways 2 \
  --btb-policy 0 --direction-policy 0 --history-bits 4 --ras-entries 4
```

仍使用原生计时器，观察器给出同窗 IPC。请以该次实际输出为 train 成绩。
无需给 `--btb-target-bits` 传 0；省略即原全宽 BTB。

本轮修正了两项验证/工具问题：Slang 对新增配置位需显式导入后再从 package 导出；
Verilator 测试台的 procedural force 需在负沿更新 IRQ 电平。另修复性能脚本的通用
`make clean` 同时删除其他 ISA 目标文件的问题：现在只清当前 ARCH，并锁住同 ARCH
的构建及归档过程。失败和中断日志保留在原始索引中，未通过屏蔽断言制造通过。

结论：对算术密集的标量边缘软件，硬件 M 有明确价值；MicroBench test 的同频收益
也覆盖了本轮面积增量。保留 RV32I 面试基线，提供独立 RV32IM 配置供软件选择。
它不是已证明对所有负载、所有频率都最优的实现；进一步取舍应先解决跨频率存储模型
的边界，再测试 train 和实际软件。
