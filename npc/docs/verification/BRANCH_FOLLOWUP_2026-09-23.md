# 分支预测补充探索：负载覆盖与历史方向预测

2026-09-23。原始记录：`npc/result/branch-followup-20260923`。

本轮发现了局部加速，但没有找到优于当前配置的面积×执行时间方案。负载覆盖确实影响收益，
也不能说原预测已经足够好：正则切分和配置解析仍有明显的预测改进空间。当前保留
BHT16/BTB16/RAS4；历史方向预测及BTB策略保留为默认关闭的实验原型。没有提交或推送。

## 基线、目标和实验范围

基线HEAD为`47c852e12b9ce086b872095f59cf54fbe5a6fda6`；当时已有修改也逐文件复制并哈希，
保留原始diff。因此B0指本轮开始时冻结的实际工作区，不能仅用HEAD重新构造它。
I-cache为1 KiB/4路/32 B/策略13，D-cache为256 B/2路/16 B；BHT16、BTB16/2路轮转、RAS4。
这不是最初未优化I-cache的历史版本。

事先固定的目标是整核映射面积×执行时间；每个程序家族等权，每家族输入等权，时间比取几何平均。
候选不能有超过3%的单项退化。先根据开发集冻结选择，再运行保留集；保留集不用于换参数或重新挑选胜者。
同频比较使用全部候选均通过STA的560 MHz；另外按各自通过STA的频点重新仿真。
首响应100 ns、后续beat累计间隔10 ns，从真实AR握手开始计时；换频率不缩放旧周期。

## 模型、RTL和简单对照

先用真实退休轨迹做冷启动、立即训练模型，筛选短历史gshare和Bi-mode，再完成真实RTL。
gshare使用4位历史与PC索引高位异或；Bi-mode的预算包含选择表和两张方向表。
查询时保存历史快照，训练使用该快照重建索引；历史只记录已解析条件分支。
不增加预测寄存级，不加入推测历史、检查点或EX到查询的组合旁路。
电路、状态及恢复规则见[方向预测原型](../microarchitecture/DIRECTION_PREDICTOR_DESIGN.md)。

| 代号 | 与B0的差别 |
| --- | --- |
| B0current | 新RTL关闭实验，用于检查公共接口改造成本 |
| B64 / B128 | 只将PC索引二位计数器扩大到64 / 128项 |
| G64 / G128 | 相同计数器数量，gshare，4位已解析历史 |
| M64 | Bi-mode，共64个二位计数器，含选择表，4位历史 |
| S32 | BHT64，BTB扩大到32项，原准入和轮转策略 |
| A32 | 在S32上只为实际taken的新分支分配BTB项 |
| R32 | 在A32上增加按taken复用更新的RRIP替换 |

同时测量旧256 B/直接映射/16 B行I-cache与新缓存的交叉组合。
旧缓存组合未重新做STA；它们在660 MHz存储换算下的结果只用于功能周期诊断，不参与硬件选型。
BTB只复测上述代表性容量、准入、替换对照，没有声称穷举所有预测器。

这些方向预测RTL是经典方法的适配，不称近期创新。McFarling、Bi-mode及近期TAGE相关、
MORSL、LLBP、Thermometer、BTB-X的阅读和适用边界见[研究笔记](../learning/BRANCH_RESEARCH_NOTES.md)。
其中哪些只阅读、哪些做模型、哪些做RTL分别记录，不能把已读论文统称为已实现。

## 负载是否掩盖了预测价值

在独立仿真源码中比较原预测、全部不跳预测、未来正确路径预测。保持原查询流水线，不添加
理想模式的额外延迟；逐次核对查询PC，三个模式共30次执行匹配退休数、摘要及独立软件输出。
生产RTL没有未来路径输入。下表是660 MHz存储换算下、每家族两个开发输入的时间比。

| 家族 | 全部不跳相对原预测 | 理想未来路径相对原预测 |
| --- | ---: | ---: |
| JSON/BPE | +10.53% | -11.08% |
| 量化装载 | +12.87% | -4.65% |
| runtime控制 | +6.01% | -10.57% |
| 正则词法切分 | +0.44% | -11.71% |
| INI配置解析 | +13.54% | -25.54% |

新增负载改变了收益分布，也表明还有改进机会。理想预测不能作为可实现策略或严格数学上界，
因为错误路径变化也会改变缓存和总线行为。新旧I-cache交叉中，G128和M64在旧缓存上也未出现
稳定优势，不能仅用“I-cache优化后掩盖收益”解释负结果。

立即训练模型中，G128的控制流错误数几何平均比例为0.8943，M64为0.9344；在真实RTL、
合法共同频点560 MHz下，开发集时间比例分别为1.00545和1.00865。错误数更少不等于执行更快。

被动跟随G128查询快照发现：61.6%～81.9%的条件分支在查询后、解析前，又有至少一条其他
条件分支完成解析；13.3%～62.8%的查询历史位串与解析前历史不同，平均查询到解析约12.2～30.2周期。
观察器开启与关闭的10个输入，结果及全部既有计数器逐项相同。这证明立即训练模型缺少真实
训练间隔，不能单凭相关性认定全部退化都由历史滞后导致。

函数归因中，runtime输入约41%的动态控制流来自RV32I软件除法，部分模型优势集中在那里。
正则和INI没有这项软件除法贡献；不能把除法模型收益直接外推到带M扩展的CPU。

这些结果不是SRAM宏、布线后时序、整SoC面积或硅上实测。

B128和G128都只通过560 MHz：580 MHz下最差WNS分别为-0.019 ns和-0.044 ns，端点是方向
计数器写口。G64在680 MHz为-0.008 ns，同样落在训练写口。不能把降频全部归因于查询XOR，
也不能把G128早期660 MHz功能仿真中的收益当作可用硬件加速。

B0current为101617.852 μm²、720 MHz；同频全部结果及既有计数器与B0一致，DFF、latch、

报告另给出以B0current为公共基础结构的面积归一化，候选仍未胜出。
G64比B0多132个DFF，M64多148个：包含表容量、4位历史及现有载荷中的32/48位快照，不新增流水级。

## MicroBench与验证口径

本轮仅跑MicroBench **test**，没有重跑train。相同软件镜像、合法共同560 MHz、SoC原生timer：

| 配置 | Total time | Total IPC | Scored time | Scored IPC |
| --- | ---: | ---: | ---: | ---: |
| B0current | 0.003828 s | 0.361370058 | 0.001740 s | 0.442074389 |
| G128 | 0.003789 s | 0.365115620 | 0.001730 s | 0.444632845 |

这说明G128在这个短测试上有小幅收益，不能外推为train或所有软件更快。Scored窗口退休数
均为430313；Total中计时后格式化输出路径随测得时间变化，退休数相差6。微秒API的量化也会
影响如此短的原生计时。观察器开关对照均通过；宿主编译O2只影响仿真墙钟速度，未改客体镜像。
早期660 MHz结果保留为回归诊断，G128在该频点未通过STA。

- 方向表8组、各20000周期，覆盖饱和、别名、延迟训练、旧快照、Bi-mode选择及失效优先级。
- B0current/G64/M64/G128均通过fetch、FENCE.I、脏行恢复和40项精确异常回归。
- G64/M64/G128各通过10个NEMU DiffTest程序；22个输入独立参考及镜像重建一致。
- 代理程序使用固定边界的被动计数：时间=窗口周期/实际配置频率，IPC=同窗口退休数/周期。
- MicroBench使用原生timer窗口与被动退休计数，没有每条指令执行CSR读取。
- `i_beats`为I读握手数；历史命名`d_beats`为D读或写握手所在周期数，不能相加冒称精确总beat数。

原始构建失败、解析器修复及NEMU环境修复均保留，见原始记录中的`workload-check-failures.md`。
没有改期望输出、删除失败测试或关闭断言制造通过。

## 存储敏感性与适用边界

对B0、G128、R32分别重新运行全部10个开发输入，统一合法560 MHz；每行均相对于该存储条件的B0。
随机模式对AR/AW/W加入确定种子的反压。以下均核对同一程序的退休数、摘要及输出，结果未用于重新选型。

| 物理首延迟 / beat间隔 | G128时间变化 | R32时间变化 | G128面积×时间 | R32面积×时间 |
| --- | ---: | ---: | ---: | ---: |
| 20 / 10 ns | +0.07% | -3.17% | +2.55% | +4.90% |
| 200 / 20 ns | +0.97% | -2.00% | +3.47% | +6.17% |
| 100 / 10 ns，加随机反压 | +0.55% | -2.44% | +3.05% | +5.69% |

快存储下G128在runtime和正则家族分别约快0.73%、0.70%，但量化装载、JSON与INI退化，整体仍未胜出。
R32在快存储下的整体时间收益扩大到3.17%，仍不足以抵消面积。当前物理存储模型不是所有系统的
通用代表；五个开发家族各两个输入，六个保留家族各两个输入，结论也不代表全部边缘AI软件。

本轮支持继续研究查询历史的及时性与训练路径，而不支持“更复杂的预测器必然更快”。
推测历史需要覆盖BTB未识别的条件分支、年轻查询恢复和同拍重定向，不能只增加一个全局寄存器
写使能。本轮没有实现它。若以后改公共训练电路，应同步优化简单对照，重新做同预算比较。
