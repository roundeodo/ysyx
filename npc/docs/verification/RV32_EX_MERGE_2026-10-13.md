## 当前结构

RV32 默认 `NPC_EXECUTE_RESULT_REGISTERED=0`：组合译码/GPR读取/前递 → ID/EX →
组合整数、分支、CSR、AGU及预测校验 → 完成选择 → WB → 组合提交。
普通 EX 不再经过独立结果级；LSU 保留单项事务上下文，响应直接参与完成选择。
旧结果边界用 `1` 显式选择，RV64 默认仍为1。

顺序与恢复边界：

- 老 LSU 存在时，年轻普通 EX 保持 ID/EX；老 LSU 返回先占用 WB。
- 年轻 LSU 仅在老 LSU 成功交付时可同拍接收；故障不得放行年轻 store。
- 当前 EX 的恢复只随成功交付发生，清年轻取指/译码，不反馈阻止当前指令。
- 老 WB 异常/mret、FENCE.I 优先；精确异常、非分支错误 taken、历史修复均保留。

模块/接口不等于流水级。CVA6 的组合 branch unit、LSU 空槽直通与 CSR 提交上下文的
源码核对和借鉴边界见[CVA6 接口记录](data/ex-merge-20261013/cva6-interfaces.md)。
本核没有 scoreboard，不能照搬独立年轻指令越过老 LSU 的完成组织。

## 时序修复

删除结果寄存器后，原先分属两个周期的执行运算、预测校验和恢复控制需要在同一个
周期内完成。完成端与发射端的反馈也不再被该寄存边界隔开：老 LSU 完成可能经交付
条件、恢复及取指反压影响 IFU 的 PC 更新和 I-cache 查询。因此违例不能只归因于
ALU，也不能只优化分支比较器。

每次按实际 STA 路径修改 RTL。中间报告先后出现地址加法→PMA/路由→AXI 直通、
返回指令→直接目标加法→预测校验→IFU PC，以及老访存完成→恢复→PC 推进条件等
路径。缩短其中一条后，其他路径可能成为最差路径；源码看起来更并行也可能因映射
与扇出变化而退化，所以未采用的候选及报告一并保留。

所有修改均未新增流水寄存器、缓冲或等待：

1. EX 后继比较并行计算，再选择一位 mismatch，避免先选宽地址再比较。
2. AGU 每4位并行求两种进位输入，组间前缀合并；分支/SLT 字节比较并行合并关系。
3. I-cache 响应身份来自保持的 S1；数据来源由已寄存的 miss 占用选择。
   预译码指令字绕过错误清零，但公开 fault 响应仍为零，错误禁用所有预译码恢复。
4. B/J 目标并行计算；低13/21位相加，高位 PC/PC+1/PC−1提前计算，再按符号与进位选择。
5. RRIP 查询用命中分类与独热路提前算同组前递，只有合法新查询才采样；训练仍按真实握手。
6. 普通 EX 的阻塞只读 LSU busy；年轻 LSU 的交接保留成功判定。PC 更新已有恢复优先级，
   其普通推进条件去掉重复恢复门控；公开预测请求握手保持原样。

中间候选均保留原始负结果。raw-hit 单项、双 victim 候选、AGU 单项未通过700 MHz，
不能因单元测试通过而采用。双 victim 已回退；最终组合重新测量，不能拼接单项最好的结果。
详细顺序与原始证据见[候选记录](data/ex-merge-20261013/next-candidates.md)。

## 改动范围与路径证据

架构改动是删除EX内部结果寄存边界，并将预测校验/解析交付移到EX。无反压时分支
训练比旧边界提前一拍；有反压时仍只在实际交付沿更新，不能把整体预测序列声称为
逐拍完全相同。BHT/BTB/RAS的表结构、容量、训练规则及弱态BTFNT规则未改。

前端修改集中在`direct_target`、IFU及I-cache的响应/预译码/替换查询电路。预译码
新增的是组合数据线，不保存每行预译码元数据。I-cache仍为1 KiB/4路/32 B/策略13，
同步读、单miss阻塞、关键字提前返回的结构不变。D-cache RTL、容量、策略及延迟模型
在本轮未改；表中的D-cache信号是路径经过点，不表示修改了D-cache。

以下是不同候选在700 MHz下的最差数据路径；不是同一条路径的连续延迟分解：

| 候选证据 | 实际起点→终点与RTL连接解释 | 违例原因/处理 |
| --- | --- | --- |
| [raw-hit单项](data/ex-merge-20261013/rejected-raw-hit/synthesis/frequency-checks/700/timing.json)，−0.253 ns | ID/EX执行包→AGU→PMA/路由→uncached直通→AXI WVALID | 进位传播与多层访问控制串接；该单项未采用，后续缩短AGU |

表中的功能连接按RTL与映射单元解释，不把综合后的长单元名直接当作架构模块边界。

## 测量条件

RV32I，I$1 KiB/4路/32 B/策略13，D$256 B/2路/16 B；BHT16、BTB16/2路、RAS4，
弱态BTFNT与早期直接目标开启，其余 TAGE/SC/Loop/推测历史保持关闭。
同一 MicroBench test 镜像；CPU700 MHz，设备100 MHz，device-clock-v1模型；
原生定时器窗口、被动周期/退休计数，observer开关对照。未跑train，不外推其收益。

综合使用同一 NanGate45 typ、Yosys/Slang、ABC AREA3、820 MHz映射目标与复位树；
对生成的纯核 `riscv32_core_reset_boundary` 网表实际按700 MHz运行四组STA。
820是映射参数，不是已通过频率。边界含核心/缓存/预测器及复位控制，不含完整SoC。
IO约束按频点比例设置，复位释放受时序检查；没有放宽约束或改综合策略。
这是综合后估算，无布局布线寄生或签核证明。

## 复现

```sh
# RV32默认选择单级EX；纯核综合后仍需执行实际700 MHz检查。
NPC_HOME="$PWD/npc" make -C npc NPC_CONFIG=rv32-balanced test-ex-arithmetic test-pipeline
python3 npc/scripts/test_ex_merge_difftest.py --registered 0
python3 npc/scripts/run_microbench_perf.py --scale test --cpu-mhz 700 \
  --timing-model device-clock --icache-bytes 1024 --icache-ways 4 \
  --icache-line 32 --icache-policy 13 --branch-static 2 --early-target 1 \
  --verify-observer
python3 npc/scripts/run_synthesis.py --target sta-reset --keep-artifacts \
  NPC_CONFIG=rv32-balanced NPC_EXECUTE_RESULT_REGISTERED=0 \
  STA_FREQUENCY_MHZ=820 'STA_SYNTH_STRATEGY=AREA 3' \
  STA_TOOL_DIR="$PWD/npc/result/sta/rv32-interrupt-20260906/toolflow"
python3 npc/scripts/check_ex_merge_timing.py \
  --directory npc/result/synthesis/current/sta/riscv32_core_reset_boundary-820MHz-buffered \
  --toolflow npc/result/sta/rv32-interrupt-20260906/toolflow --mhz 700
```

需先安装相同工具并提供记录中的NanGate45/toolflow。检查四组`passed=true`，
不能仅检查工具退出码；保留700 MHz报告后按产物规则清除大网表。
