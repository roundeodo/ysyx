# BTB 并行选路实现与取舍

**结论：并行原型已经实现并验证，但没有替换默认 RTL。** 多路 RRIP 的训练路径有所改善，
当前两路配置的整核面积、时序和周期综合看没有收益。稳定版本保持 `316d1d2` 的 BTB，
默认仍为 16 项、两路、轮转替换、700 MHz。原型与失败结果保留，未提交或推送。

## 范围与电路

修改对象是完整目标 BTB 的训练选路，不是 BHT。BHT 没有 way；BTB 查询的 tag 比较和
目标合并原本已经并行。本次没有修改 compact BTB、I-cache、预测算法、恢复协议或计时模型。

原型电路按以下顺序组织源码：

1. 每路独立产生 tag 命中和空路候选。
2. RRIP 每路并行判定 RRPV=0/1/2/3，归约出最高等级；不逐路累计最大值。
3. 每路用自己的候选位和更低路号的候选归约，产生低路号优先的独热选择。
4. 命中覆盖空路，空路覆盖替换受害者；在写口编码索引。
5. 原有同步写口更新载荷、有效位及策略状态。

没有新增寄存器、流水级、等待或训练队列。同拍查询/训练仍观察沿前表项；下一拍可以
直接查询更新结果。失效优先于训练，RRIP 同等级和空路均优先最低路号；命中项由唯一
tag 保证。归约和编码仍有组合深度，“并行”不代表与 way 数量无关的恒定延迟。

三个原型均保留了上述行为：

| 原型 | 写索引电路 |
| --- | --- |
| v1 | 命中、空路和替换受害者统一独热选择，再编码 |
| v2 | 命中/空路与受害者分别形成索引；轮转指针直接复用，避免解码再编码 |
| v3 | 多路沿用 v1；两路直接生成一位选择式，避免通用编码器 |

v2 的第一次测试因旧断言仍要求“命中/空路向量”在满组替换时独热而失败。随后按实际
接口拆成命中/空路独热、索引范围及 RRIP 受害者独热检查，再完整重跑；未关闭断言。
初始失败日志和修正前源码也保留。

## 默认配置的整核结果

相同 NanGate45 库、AREA 3 策略、820 MHz 映射目标、复位缓冲与 SDC。面积包括纯核、
复位边界及插入的复位缓冲，不包括 SoC。700/715/720 MHz 检查复用各自网表，检查
data/gating 的 setup/hold 四组；不是布局布线签核。

| 实现 | 面积 µm² | 700 MHz data setup | 700 MHz gating setup | 715 MHz 四组 |
| --- | ---: | ---: | ---: | --- |
| 稳定基线 | 102004.882 | +0.025 ns | +0.038 ns | 通过 |
| v1 | 102079.628 | +0.017 ns | +0.016 ns | 未通过 |
| v2 | 101513.048 | −0.304 ns | −0.258 ns | 未通过 |
| v3 | 102034.940 | −0.318 ns | −0.314 ns | 未通过 |

四个实现的 720 MHz 检查均失败。基线和 v1 的 700 MHz 四组通过；v2/v3 的 hold
检查通过但 setup 失败。820 MHz 仅是映射目标，不能称为可运行频率。

v1 面积增加 74.746 µm²（0.0733%），既没有减少周期，也失去原先很小的 715 MHz 余量。
v2 虽省面积，但不足以弥补时序退化；v3 的两路专用选择式也没有改善整核结果。

整核关键路径分别落在 IFU PC/请求队列和数据 AXI 输出。独立 BTB 的输入到写口路径
不能代替整核中“解析事件产生 → 训练 → BTB 写口”的完整路径。改写后综合网表的
组合共享、映射和扇出也会变化；目前未独立量化这些因素，不能将全部退化归因于某个
BTB 门级，也不能从一个局部表达式直接推断整核频率。

这不意味着“并行比较更慢”。默认 policy0 不启用 RRIP 最大值链，查询 tag 比较也
已经并行，因此默认两路缺少本次改写要解决的长链。v2 的最差路径从 EX 结果寄存器
经过 LSU/数据访存逻辑到数据 AXI 输出；v3 的最差路径从指令 AXI 输入到 IFU PC
寄存器。它们不是 BTB 的逐路比较链。相同设置下重映射后的路径退化已经测到，但
尚未通过固定其余逻辑的映射对照定位具体原因，不能把一般性的共享、扇出或编码
成本当作已证实的根因。当前结论只是否决这三个原型替换默认配置。

## 多路结构的独立模块对照

保持每组对照的 entries、ways、policy、接口、库、映射策略及 I/O 约束一致。
除默认两路外，总容量均为 32 项、policy2；700 MHz 筛选全部 BTB 寄存器 D pin。
这里报告训练路径 setup 余量，**不认证对应多路整核的运行频率**。

| 配置 | 原 BTB 面积 | v3 面积 µm² | 原训练 setup | v3 训练 setup |
| --- | ---: | ---: | ---: | ---: |
| 16 项/2 路/policy0 | 8122.310 | 7993.034 | +0.655 ns | +0.651 ns |
| 32 项/4 路/policy2 | 16393.314 | 16622.340 | +0.469 ns | +0.474 ns |
| 32 项/8 路/policy2 | 16561.426 | 16915.472 | +0.381 ns | +0.401 ns |
| 32 项/16 路/policy2 | 16855.356 | 17521.420 | +0.069 ns | +0.321 ns |

16 路的训练余量增加 0.252 ns，BTB 面积增加约 3.95%；4/8 路收益小。
该对照的训练路径延迟从约 1.318 ns 降至 1.066 ns，减少约 19.1%。这支持对实际存在
长串行选择链的多路结构采用并行候选；默认两路没有同样的前提。
v2 的 16 路余量进一步达到 +0.409 ns、面积 17409.434 µm²，但其默认两路整核失败，
不能据此推荐整套 v2。这些结果说明多路扩展值得使用并行候选，同时说明当前两路
并不存在需要强制采用通用选择网络的时序瓶颈。

## 正确性与周期

- 独立全 PC C++ 模型：62 个配置，覆盖 1/2/4/8/16 路、全部五种策略、三种索引及
  准入规则；每个通过的版本检查 2232000 次查询和 55296000 次表项状态，包括
  有效载荷、替换指针、RRPV、复用记录与签名计数器。
- v3 前端契约：10 个预测器配置、120000 周期，覆盖随机反压、失效、flush、连续训练、
  查询/训练同拍及运行中复位；fetch 身份/恢复契约通过。
- v3 的 10 个已有 CPU 程序通过 NEMU DiffTest；lint 通过，原有警告仍在。
- MicroBench **test**：稳定仿真器、v1、v3 使用同一个镜像、700 MHz 模型参数、
  device-clock-v1、100 MHz 设备模型及相同缓存/预测配置。只有 BTB 源码不同，
  各子测试、计时事件窗口、完整计数器输出和架构校验值完全一致；观察器开/关一致。

| 原生计时窗口 | 周期 | 退休指令 | IPC |
| --- | ---: | ---: | ---: |
| Total | 2684531 | 831627 | 0.309784838 |
| Scored | 1048317 | 430313 | 0.410479845 |

这些是 test 的数据，不是 train。未运行 train，也没有新增预测准确率或执行周期收益。
v3 的 700 MHz 仿真只验证逻辑及同条件周期；其 STA 已失败，不能把仿真时间当作合法
700 MHz 硬件执行时间。现有精确异常、错误 taken 恢复、FENCE.I 和总线错误逻辑未修改；
本轮没有重新运行这些整核错误注入回归。

## 保留与复现

当前 RTL 已按字节恢复为基线，BTB SHA256 为
`570398a12b710ae69d76bd1ddabee1428fc1f10df4c452bb5b4425277b9c8594`。
仅扩展了 BTB 模型测试，并去掉它对旧 `result` 目录中宏定义清单的依赖。
用户已有 `am-kernels`、`ysyxSoC` 子模块修改保留；replay worktree 未修改。

证据在 [data/btb-way-parallel-20261010](data/btb-way-parallel-20261010/)：
`summary.json` 汇总数值；`experiment/parallel-v*.sv` 是可综合原型；`core/`、`selection/`
保留网表压缩件、原始报告、配置及约束；`tests/`、`performance/` 保存验证及周期证据。
`archive-index.json` 记录原路径与哈希。大编译目录和临时综合网表已在归档后清理。

在仓库根目录检查当前稳定 BTB：

```bash
python3 npc/tools/branch_v3/test_btb.py --output npc/result/branch-v3/btb-unit-check
```

原型复现使用 `replay_btb_parallel.py --variant v1|v2|v3`，将冻结的 BTB 放在独立源码目录，
不会覆盖当前 RTL；默认跑模型，`--synthesis core|module` 启动对应边界的综合。
归档的 `experiment/measure_selection*.py` 和 `probe_core*.py` 给出本次映射及指定频点
检查的原始操作，使用前按实际 scratch 路径调整。综合需使用已核验的 toolflow。

后续只有在明确需要扩展 way 数时，再围绕实际整核训练/查询路径验证多路并行原型。
在当前两路设置下，保持稳定实现比强制采用本次原型更符合面积、时序和维护目标。
