# LSU 与 D-cache 阻塞：实测与升级依据

2026-10-01。结论：单事务 LSU 确实损失独立执行机会，尤其影响 `dinic/lzip/ssort`；
但不能解释所有程序的 ROB 负收益。load 数据依赖和 cache miss 等待更广泛；`queen/fib`
的第二条访存阻塞很少。此次没有修改功能 RTL、延迟模型或软件计时方式，没有默认启用新配置。

## 范围与测量方法

- interview 工作树：HEAD `5493a6aec976f4f9bdc075834d3f1202b0ae16ef` 加现有未提交改动，
  不能仅用 HEAD 代表被测后端。基线文件哈希、已有差异与状态保存于原始目录。
- 原生 MicroBench **test**，RV32IM，流水 MUL，ROB 4 项、load overlap 开启、明确 Issue 级。
  CPU 模型 680 MHz、设备 100 MHz；选用旧后端与新后端都已通过 STA 的共同频点。
  I-cache 1 KiB/4 路/32 B/策略13；D-cache 256 B/2 路/16 B。预测器和存储模型保持原参数。
- 同一个未插桩镜像，SHA-256 `628d93c7fc6df6804d690769a8f5fe02782099f1292bd7abda23f61702c611ad`。
  探针只注入冻结的仿真副本，直接读取 RTL 状态；不添加工作负载指令，不反馈 ready/valid。
- 在现有 CLINT 低字读握手处导出上升沿前累计快照，逐项核对原生观察器的周期、退休数和 ticks。
  所有窗口按 `[begin,end)` 差分。23 个采样点齐全；Total、十项 Scored 周期与退休数分别一致。
- 主分类互斥：派发成功 → 控制恢复 → EX 中的访存顺序/排空/LSU容量/其他FU等待 →
  Issue 串行化/RAW/ROB满/传递 → 无待发指令。此优先级用于描述观测位置，不代表唯一根因。
  其他事件允许重叠，不能相加，也不能直接当成升级后的可节省周期。

## 原生窗口：哪些问题实际发生

Scored 共 **928,906** 周期、317,724 条退休指令，IPC **0.342041**。

| 互斥主分类 | 周期 | 占 Scored |
| --- | ---: | ---: |
| 第二条访存因 LSU 不接收而阻塞派发 | 60,238 | 6.48% |
| Issue 等待 load 生产者的数据 | 212,813 | 22.91% |
| Issue 等待其他生产者的数据 | 6,157 | 0.66% |
| 访存未获顺序授权 | 102,905 | 11.08% |
| EX 空闲，但 Issue 因 ROB 无空位不能推进 | 43,041 | 4.63% |

D-cache miss 在途 **381,770** 周期（41.10%），这是可与上表重叠的状态占用。
访存顺序等待中有 68,054 周期 LSU 同时不就绪；65,736 周期同时存在 D-cache miss，
25,351 周期同时存在 uncached 路由。不可将这些子项相加，或把整个 11.08% 都算成可删除的等待。
平均 ROB 占用约 1.90 项；整个窗口 ROB 无接收空间占 8.07%，也与其他等待重叠。

访存顺序等待占 34.65%，不能代替 Scored 的 11.08%。两者原始分项均保留。

## 被挡住的第二条 load 原本要访问什么

在 58,100 个“普通 load 被挡住且存在 D-cache miss”的周期，仿真只读检查当前 tag：

| 当前地址关系 | 周期 | 占这类等待 | 对应候选 |
| --- | ---: | ---: | --- |
| 同一在途请求的 cacheline | 8,444 | 14.53% | 同行等待合并或回填转发 |
| 不同 cacheline，当前 tag 命中 | 26,489 | 45.59% | hit-under-miss |
| 不同 cacheline，当前未命中 | 23,167 | 39.87% | 多 miss，但需下层支持 |

这是影子查询，不是真实 cache lookup，也未假设端口无冲突。
`dinic` 中另行命中等待为 19,412 周期，`lzip` 中另行未命中等待为 14,292 周期。
`ssort` 有 5,213 周期等待同一行；全程序热点 PC `0xa00026b8` 对应连续读取数组相邻字。

其中 21,227 周期，第二条访存后面的 Issue 指令是操作数就绪的整数/乘除法，且 ROB 可分配。
**这不是 21,227 个可节省周期。** 同一条简单 ALU 可能反复等待数百拍，执行它只能消耗一拍；
还需看其后指令、FU可接收能力、ROB容量和关键依赖。`lzip` 热点 `0xa00018f4` 后是一条独立
`addi`，随后立即是 store，说明仅加请求队列也可能很快再次遇到顺序限制。

## 因果对照与简单对照

定向程序在整核 RTL 上用 NEMU 和常数结果双重检查：每个程序都退休 **557** 条指令。
仅把第二条 load 后独立的 DIV/MUL 移到它前面，访存相对次序和工作量不变。
这利用现有 FU 并行，不修改 LSU，不能冒充新增硬件的性能结果。

| 场景 | 先发两条 load | 先发 load，再发独立运算 | 周期变化 |
| --- | ---: | ---: | ---: |
| 第二条 load 在同一行 | 1742 | 1606 | -7.81% |
| 第二条 load 在另一条热行 | 1742 | 1606 | -7.81% |
| 第二条 load 在另一条冷行 | 1742 | 1606 | -7.81% |
| 两条 load 反复命中 | 1618 | 1606 | -0.74% |

这些使用 standalone flat-memory 模型，不是 SoC 物理用时。影子查询在三个对应场景分别计入
同行、另行hit、另行miss，作为探针语义检查。历史冻结的原后端也运行同组对照，完整结果保留；
它不能与原生 test 混用，也不能把软件重排收益直接当作待实现队列的收益。

另做 **仅 D-cache 容量由256 B变1 KiB** 的原生对照：路数仍为2，行长仍为16 B，保持阻塞结构。

| 后端 | D-cache | Total 周期 | Scored 周期 |
| --- | --- | ---: | ---: |
| 原后端，无 ROB/Issue | 256 B | 2,171,419 | 901,995 |
| ROB/Issue | 256 B | 2,204,695 | 928,906 |
| 原后端，无 ROB/Issue | 1 KiB | 1,963,894 | 740,834 |
| ROB/Issue | 1 KiB | 2,001,157 | 769,354 |

扩容使 ROB 版 Scored 周期下降 **17.18%**，原后端下降 **17.87%**；ROB版 miss 从3752降为1903。
但 ROB 相对原后端的 Scored 劣势从 **2.98%** 变为 **3.85%**。
这证明容量/缺失压力值得优化，也证明“只把存储优化好，ROB就必然更快”不成立。
1 KiB D-cache 仅为周期敏感性实验，尚未做新面积/STA，不能据此默认启用或宣称同频物理实现通过。

## 升级顺序与边界

1. 第一组对照：保留当前基线；两项普通 load 上下文配合原阻塞 cache；相同上下文再加
   单 MSHR 的 hit-under-miss。空时直通、返回与新请求交接同拍；不新增强制 Issue/完成寄存级。
   分别量化入口解耦与真正 cache 并发的收益，容量扩展另作简单对照。
2. 对 hit-under-miss，修改 LSU 身份/取消、数据路由、cache lookup 与回填写口仲裁。
   正在替换的 victim 必须被保护；同组/同行冲突明确等待或转发。先不让年轻 store 提前产生副作用。
3. 暂不直接上两项 MSHR：`riscv32_dcache_axi` 只保存一个读回填；`riscv32_axi4_arbiter`
   的新 AR 窗口仅在无在途读或旧 RLAST 握手时打开，`riscv32_axi4_router` 也保持单个读归属。
   必须连同身份路由、SoC bridge/目标接收能力和设备时钟延迟模型一起评估，不能只改 cache 数量。
4. store buffer 单独论证。未提交地址/数据暂存与允许向 cache/MMIO 写入分开；当前普通精确
   access fault、clean失败停止、dirty-victim恢复不能因提前退休而丢失。
5. 下一轮验收保留本轮分程序窗口，检查回包配对、同拍恢复/返回、槽复用、地址/字节冲突、
   FENCE.I、总线错误和随机反压；再比较同频周期、各自合法频点时间及面积。

## 验证与复现

两版探针开启/关闭的23个原生采样与架构审计相同；最终探针的采样也与此前已通过STA的
680 MHz基线逐字节相同。主分类之和等于窗口周期；退休计数等于原生观察器；影子分类之和
等于对应等待周期。本轮运行3个缓存/后端原生组合，并复用已核验的原后端256 B归档参考，
共同覆盖4种配置的10项test；16次定向程序全部DiffTest通过。
详细探针首次编译因局部枚举引用缺少层级而失败，已修复，失败日志保留；没有RTL功能失败被屏蔽。
正式RTL、宿主代码、Makefile和延迟模型的哈希均未改变。

```sh
python3 npc/scripts/measure_lsu_stalls.py \
  --reference npc/result/retire-bypass-20261001/perf-final-680 \
  --output npc/result/lsu-recheck --verify-observer --standalone
python3 npc/scripts/test_lsu_issue_blocking.py \
  --simulator npc/result/lsu-recheck/build-standalone/top_sim \
  --output npc/result/lsu-directed-recheck
```

容量对照给第一条命令增加 `--dcache-bytes 1024`，原后端再增加 `--backend-rob 0`，
每次使用新输出目录。此次未跑完整train，未实现多请求LSU/非阻塞cache，也未做新综合/STA。
