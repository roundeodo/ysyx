# RV32 源码整理与缓存交接优化

基线为 `rv32-interview-20260911` 的 `63206ba`；结果对应基于该提交的本轮实现，源码对应关系以归档 SHA256 为准。
**保留源码整理和 H1（最后一字直发写回）；H2 并发交接撤回，H3/H4 暂缓。**
修改前的全部模块检查见[基线审查](RV32_LOGIC_STYLE_AUDIT_2026-09-21.md)。

## 采用什么、为什么

| 项目 | 结果与取舍 |
| --- | --- |
| 源码整理 | 保留。合并 I-cache/core 的无选择作用别名、重复纯函数与表达式；按请求、阵列、比较/响应、反馈组织 I/D-cache；修正旧注释、字段换行和 CLINT 高半快照命名。纯整理的 test 周期与基线完全一致，但面积略增，不能宣传为面积优化 |
| H1：最后 victim 字 → 写回 | 保留。最后一字直接补入已有行数据并发写回，反压时由原行缓冲和发送状态保持；没有新增行缓冲或流水级。功能、600 MHz STA 与整程序 test 均通过，面积基本持平、周期小幅减少 |
| H2：写回接收 → 同拍 refill | 功能通过，但不合入。H1+H2 在当前模型下反而变慢；H2 单项的 600 MHz data setup 裕量也由整理后的 73 ps 降至 6 ps。延迟模型存在顺序敏感性，不能据此判定真实硬件上的并发更差，待模型验证后重评 |
| H3：miss 完成 → 下一 lookup | 已增加被动计数，保留原交接。多数候选请求同组，需补齐 tag/data 同址旁路，I-cache 还涉及锁存写窗口；当前机会不足整程序周期的 1%，模型又影响请求时刻的比较，暂不扩大实现 |
| H4、CSR 串行化及低频维护交接 | 保留。当前 train 镜像的 FENCE.I 在计时窗口之前，test 串行化停顿仅 3 拍；未证明值得扩大控制与验证范围 |
| AXI 无效载荷不清零 | 独立通道测试通过，但只在已撤回的并发组合上做了综合，没有证明独立收益，不合入当前版本 |

当前保留的写回/refill 发起交接拍不是 AXI 协议要求。B 响应仍独立跟踪，回填可以与未结束
的写回重叠；没有把整次写回与整次读回填串行化。当前电路说明见[D-cache 说明](../microarchitecture/DCACHE_DESIGN_RECORD.md)。

## 同条件测量

I-cache 256 B / 1 路 / 16 B 行，D-cache 256 B / 2 路 / 16 B 行；BHT 16 项、BTB 16 项 / 2 路、
RAS 4 项。负载为未插桩的 MicroBench **test**，CPU 600 MHz、设备等效 100 MHz、mtime 1 MHz。
镜像、ELF 和工具相同，没有非 RTL 运行输入变化；Makefile 只增加测试入口与帮助文字。
IPC 为同窗口退休数除以周期数；原生定时器分辨率为 1 µs，Scored 是十个区间之和。

面积为包含核复位缓冲的 NanGate45 映射单元面积，不含 SoC、布局布线或寄生参数。
沿用 820 MHz 综合目标和 DELAY-0 策略，将同一网表改用 600 MHz 约束检查四类时序。
下表 Fmax 仅由数据 setup 推算，**实际确认通过的运行点是 600 MHz**。

| 方案 | 面积 / µm² | 600 MHz data setup WNS / ns | 数据 setup 估算 Fmax / MHz | test Total 周期 | test Total IPC |
| --- | ---: | ---: | ---: | ---: | ---: |
| 修改前 | 69,536.922 | +0.034 | 612.620 | 3,553,436 | 0.215102228 |
| 仅源码整理 | 70,047.908 | +0.073 | 627.735 | 3,553,436 | 0.215102228 |
| 整理 + H2 | 69,863.570 | +0.006 | 602.282 | 未测 | 未测 |
| 整理 + H1 + H2 | 整程序退化后停止映射 | — | — | 3,582,759 | 0.213339217 |
| **最终：整理 + H1** | **69,575.758** | **+0.062** | **623.292** | **3,544,972** | **0.215609884** |

最终版相对修改前：面积增加 **38.836 µm²（0.056%）**，Total 周期减少 **0.238%**，
Scored 周期减少 **0.277%**。没有减少物理寄存器：两者均为 7,640 个 DFF、2,048 个数据锁存器。
最终 data hold、clock-gating setup/hold 裕量分别为 +0.059、+0.027、+0.097 ns。

| 同一原生窗口 | 修改前 | 最终版 |
| --- | ---: | ---: |
| Total 定时器时间 | 5.923 ms | 5.908 ms |
| Total 退休数 | 764,352 | 764,331 |
| Scored 周期 / 退休数 | 1,556,380 / 430,311 | 1,552,076 / 430,311 |

十个计分子项目的退休数分别一致；Total 包含准备、校验、打印等工作，以各版本实测退休数
计算 IPC。D-cache miss 次数均为 12,188，其中 8,096 次脏替换；脏替换平均延迟从 121.759
降至 120.303 拍，命中延迟仍为 1 拍。比较数据见[同条件对照](../../result/performance/rv32-refine-20260921/capture-comparison.json)。

未采用的 H1+H2：Total 周期增加 0.825%，Scored 周期增加 0.201%，脏替换平均延迟升至
126.497 拍。另一个 H1+H2+AXI 无效载荷简化组合测得 69,896.022 µm²、600 MHz data setup
+0.052 ns；未跑其完整负载，也未证明无效载荷简化的独立收益，不把该数值归因于单项修改。

## 设备延迟模型的限制

独立实验固定下游 AR 在第 8 拍接收、R 在第 10 拍返回，只将上游 VALID 从第 2 拍提前到
第 1 拍。频率比为 1 时，两者都在第 10 拍收到 R；比值为 6 时，反而从第 50 拍推迟到第 55 拍。
当前 AXI Delayer 从 VALID 起点缩放包括握手前等待在内的延迟，因此存在这种顺序敏感性。

原生计时器与周期计数仍互相吻合，但结果代表当前模型，不能直接当成真实 100 MHz 设备上
并发请求的性能排序。该机制已经复现；尚未逐事务证明它解释了整程序的全部差值。本轮保留
原模型进行对照，没有通过改变计时或设备延迟制造性能收益。
证据：[探针源码](../../result/performance/rv32-refine-20260921/delayer_start_order_tb.sv)、
[结果](../../result/performance/rv32-refine-20260921/delayer-start-probe.log)。
后续应先验证设备服务时序与并发竞争的模型，再重评 H2 等依赖请求重叠的优化。

## H3 的实际触发次数

最终版完整 test 的观察器开关两遍均得到以下**整程序**计数；不是 Total/Scored 窗口计数。

| cache | 完成次数 | 完成时下一查询等待，同组 | 异组 |
| --- | ---: | ---: | ---: |
| I-cache | 27,250 | 22,700 | 4,550 |
| D-cache | 12,188 | 4,763 | 272 |

它们是候选触发次数，不是已节省周期，也不是收益的严格上限。按当前轨迹每次少一拍粗估，
I-cache 约占整程序周期的 0.684%，D-cache 约 0.126%；只做异组交接约为 0.114% 和 0.0068%。
不能外推为 train 收益。观察器只读信号，不驱动 CPU 控制，不进入综合。

## 验证与复现

- 源码整理：EXU/LSU/D-cache、24 个原 miss 用例、18 个 I-cache 用例及 lint 通过；完整 test
  的 Total、Scored、子项目、整程序周期/退休数与基线相同。
- H2 单项：RV32 / 16 B 行的 102 个 miss 契约用例通过。H1+H2 和最终 H1 各通过 RV32 / 16 B、
  RV32 / 4 B 单字行、RV64 / 32 B 行共 306 个用例，覆盖请求反压、整行保持、R/B 顺序、错误与 clean。
- AXI 原整理版本及无效载荷候选各通过三种配置共 24 个通道用例。正式入口为 `test-dcache-axi`；
  `test-dcache-miss` 已保留扩展用例和最后一字旁路检查。
- 最终 H1：RV32 D-cache、精确异常 40/40、DiffTest 35/35、NPC/SoC lint、系统位级组合环检查通过；
  MicroBench test 十项通过，观察器开关审计一致，600 MHz 四类 STA 检查通过。
- 更早的 H1+H2 集成阶段另通过中断 8 项和 RV64 EXU/LSU/D-cache 回归。最终撤掉 H2 后按上述
  受影响范围复测，没有重复宣称所有历史配置均已穷举。
