# RV32 直通与周期优化验证

对象：面试分支，基线 `c253a1a8`，保持 RV32 单发射、顺序执行与提交。
对应电路说明见[设计记录](../microarchitecture/RV32_CYCLE_OPT_DESIGN.md)。
本轮没有修改 cache 容量、关联度、预测表容量或外设延迟来换取结果。

## 实际修改

| 路径 | 修改与边界 |
| --- | --- |
| IFU 预测上下文 | 4 项缩为 1 项；只与已被阻塞 I-cache 接收的唯一请求配对，旧 epoch 返回仍丢弃 |
| 前端队列 | 请求队列、fetch buffer 支持空队列直通及满队列同拍出入；受阻后保存请求 |
| taken、训练与 redirect | taken 响应当拍查询目标；BHT/BTB/RAS 从 EX 结果直接训练；恢复来源组合优先选择 |
| ID/EX 与 load-use | 删除额外 skid 载荷，保留单项 ID/EX；成功交付的 load 可以直接前递，最近生产者优先 |
| LSU、I-cache AXI、uncached AXI | 普通请求空闲直通，未接收时保存重试；LSU 成功完成拍可接下一请求，故障完成禁止交接 |
| D-cache miss 与写回 | 合并失效/发 refill、安装/返回；脏行只由 miss unit 保存到 B，adapter 不再复制一行 |
| D-cache 保持缺陷 | 响应反压时保持同步阵列输出和 store 字节旁路，不再跟随未接收的输入地址 |
| 系统 AXI 与 CLINT | 末响应与新地址可同拍交接，旧响应与新请求分别路由；CLINT 可同拍接收 AW/W |

EX 结果、WB、同步阵列读、未完成总线事务上下文、FENCE.I drain/clean 和复位同步继续保留。
这些状态负责指令年龄、数据可用时刻或协议保持，不能按字段相似直接删除。
较老 EX 异常禁止年轻 LSU 发出的修复保持有效；本轮直通没有绕过这条约束。

## 组合路径的处理

初版直通把旧存储响应、ready、PC 选择和加法串联。调整为提前计算顺序 PC/目标 PC 加 4，
按已保存的预测选择查询地址；训练 payload 从解析寄存器直接产生，只用 valid 控制写表。
进一步让 LSU 和 uncached 的数据选择只依赖寄存状态，避免握手条件先清零整份 payload。
这些调整不增加寄存器或等待周期。

综合始终使用同一套 Yosys/Slang、Nangate45 typical、`DELAY 0`、纯核加复位控制器与
扇出上限 16 的 `BUF_X4` 复位树；基线有 63 个 buffer，优化后为 48 个。
结果是综合后、理想连线条件下的估计，不含布局布线和整个 SoC。
输入/输出延迟均为周期的 20%；因此不能把某次报告的 Fmax 直接当作已通过频率，
必须对同一网表重新检查 data/gating 的 setup/hold 四组约束。

## 测量结果

| 项目 | 基线 | 本轮 |
| --- | ---: | ---: |
| 映射单元面积 | 73,081.372 μm² | 69,580.014 μm²（−4.79%） |
| DFF 数量 | 8,410 | 7,647（减少 763） |
| 数据锁存器数量 | 2,048 | 2,048 |
| 通过四组时序检查的频率 | 700 MHz | 600 MHz |
| 对应最差 data setup / hold | +0.048 / +0.057 ns | +0.005 / +0.059 ns |
| 对应最差 gating setup / hold | +0.201 / +0.097 ns | +0.063 / +0.094 ns |

600 MHz 的 setup 余量很小。更保守的 540 MHz 检查为 +0.153 ns；以上均是当前库和约束下的
综合后结果。820 MHz 不通过；该约束下报告的 Fmax 为 636.308 MHz，不能直接作为通过频率。

| microbench **test** 配置 | Total 周期 | Total 定时器时间 | Total IPC | Scored 定时器时间 | Scored IPC |
| --- | ---: | ---: | ---: | ---: | ---: |
| 基线，700 MHz | 4,498,243 | 6.426 ms | 0.169738 | 2.904 ms | 0.211617 |
| 本轮，700 MHz，仅作同频周期比较 | 4,018,017 | 5.740 ms | 0.190168 | 2.479 ms | 0.248021 |
| 本轮，600 MHz，通过时序 | 3,603,144 | 6.005 ms | 0.212130 | 2.624 ms | 0.273317 |
| 本轮，540 MHz，通过时序 | 3,362,026 | 6.226 ms | 0.227354 | 2.736 ms | 0.291290 |

同频比较：Total 周期减少 **10.68%**，IPC 增加 **12.04%**。
按通过时序的 600 MHz 重跑，Total 用时仍减少 **6.55%**，Scored 用时减少 **9.64%**。
因此本轮取舍是更小的状态存储、更少等待和更长组合路径；在本次负载上，降频后执行时间仍改善。
600/540 MHz 的更高 IPC 还包含外设延迟换算为更少 CPU 周期的影响，不能全部归因于硬件优化。

700 MHz 的整程序诊断计数中，RAW 等待从 73,925 降至 30,512，前端查询在途等待从
138,373 降至 18,848。LSU 结构阻塞、前端供给和恢复等待仍分别占 33.50%、24.98%、19.54%；
它们包含真实 miss、反压与错误路径恢复，不能继续按“多余寄存器”无条件删除。
这些是整程序计数，不与 Total/Scored 窗口混加。

性能程序为未插入 CSR 计数指令的原生 microbench；本轮使用 `test` 输入。
I-cache 为 256 B/1 way/16 B line，D-cache 为 256 B/2 way/16 B line，BHT/BTB 为 16 项，
BTB 2 way，RAS 4 项。外设延迟按 100 MHz 设备等效时间换算，CLINT `mtime` 每微秒加一。
CPU 频率变化时重新配置分频及外设延迟周期并重跑，不能只把原周期数除以另一个频率。

Total 和 Scored 分别使用原程序的总窗口和十个计分窗口，不使用宿主仿真耗时。
IPC 在相同窗口按退休指令数差值除以 CPU 周期差值计算，边界取 timer AR 即将握手的上升沿前状态。
直通后，下一次 timer 请求可能早于较老指令退休，不能用静态程序距离代替窗口退休数。

## 验证与证据

- 最终整核：精确异常 **32/32**、RV32 DiffTest **35/35**、定时中断 **8/8** 通过。
- 定向边界：LSU 直通/交接、uncached 独立 AW/W、D-cache 反压及字节旁路、脏行写回/错误、
  I-cache、前端 taken 间隔、fetch buffer 满/空/flush、AXI 末响应交接 **10 项**通过。
  预测器对独立模型比较 **5 组参数、60,000 周期**通过；共享 LSU/uncached 的 RV64 用例也通过。
- Verilator standalone/SoC lint 完成。宽结构体带来的 `UNOPTFLAT` 提示仍存在；
  Yosys/Slang 展开至位级后，完整 `npc_system` **0 个组合环，check 通过**。
- 宿主计时观测与分析测试 **8/8**；最终 700 MHz microbench **10/10**，观测器开/关一致。
  600/540 MHz 的 microbench 也均 **10/10**，原生时间、采样和频率一致性校验通过。
  模块用例按各次修改执行；最终整核回归与源码哈希见 `checks.json`、`check-source-hashes.json`。

基线 64 个 RTL 输入逐文件核对为 `c253a1a8`；各次测量的程序二进制及工具版本相同。
最终排版和注释调整通过词法比较，50 个综合输入与冻结源码的 RTL token 一致，
见 `input-comparison.json`、`final-rtl-review.json`。本轮未运行形式化全状态证明。

直通改变了 CLINT AR 握手与 LSU 上下文写入的相对时刻，因此只读 DPI 在直接握手时取入口 PC，
延迟发出时取保存的 PC。宿主允许多个待退休采样，按顺序关联到成功退休的 load。
错误返回或未退休采样使测量失败。该修正不向 CPU 反馈控制，也不改变程序二进制。
短汇编测试从 VCD 独立逐拍核对退休数；21 次提交中只有 19 次退休，ECALL/EBREAK 不计数。
观测器开关对比要求日志、计数和架构副作用摘要完全一致。

## 全模块检查的范围与未完成项

以下为 `71e44bf` 时的复核记录；后续实现与复测见[第二轮等待周期复查](RV32_WAIT_AUDIT_2026-09-19.md)。

对提交 `71e44bf` 复核：综合清单包含 **45 个模块、5 个 package**，50 个文件的当前
SHA256 均与 `final-rtl-review.json` 一致。原[结构审查](RV32_REGISTER_CYCLE_REVIEW_2026-09-19.md)
覆盖这份清单（`redirect_stage` 随后替换为 `redirect_mux`）；本轮改动涉及其中 19 个当前模块
和 1 个 package，其余按审查结论保留。仿真模型与历史实验另列，不计入芯片面积优化范围。

这证明检查有完整的模块清单，不能证明所有可省周期都已消除。复核发现以下局部直通候选
仍未实现，也没有修改后测试或 PPA 结果，不能列入上面的收益：

| 位置 | 当前行为 | 待验证的方案与边界 |
| --- | --- | --- |
| `icache_miss_unit` miss 入口 | 接受 miss 后，下一拍进入 `MISS_SEND_REFILL_REQUEST` 才发 refill | 空闲时由入口请求直接产生 refill；受阻再保存重试。仍须保存 miss 身份，并保证 victim 失效、请求保持及只发一次 |
| `icache_miss_unit` 关键字响应 | critical word 先写入响应寄存器，下一拍才向 IFU 呈现 | 响应缓冲为空时直接呈现关键字；IFU 反压时捕获。必须维持错误累计、epoch 配对、唯一响应及剩余 burst 排空 |
| `uncached_axi` 连续事务 | 请求 ready 仅在 IDLE；旧 R/B 完成后下一拍才可接新请求 | 成功响应交付与新请求同拍交接；分别使用旧响应身份和新请求 payload，保留错误恢复限制及独立 AW/W 进度 |

前两项各涉及一个局部寄存等待，第三项涉及事务交接空拍；程序收益会受其他等待覆盖，
不能直接相加。直通也会延长 tag 比较到 AXI、AXI 返回到译码，或响应到新请求的组合路径。
保留反压缓冲不等于每次都必须经过该寄存级；是否采用这些方案，应以定向测试、整核回归、
同负载周期数及通过时序的频率共同判断。本次复核只补充记录，未改 RTL、未重新运行综合。
