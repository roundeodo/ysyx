# RV32 I-cache 结构与替换选型

## 最终结果（2026-09-22）

按预先冻结的规则，采用独立预设 **`NPC_CONFIG=rv32-balanced`：1 KiB、4路、32 B行，
策略13（分段访问RRIP的查询旁路版），仿真CPU频率720 MHz**。原`rv32-baseline`保持不变。
本轮只修改I-cache组织和替换策略；D-cache、BHT/BTB/RAS、CPU流水级及AXI并发度不变。
配置文件为[rv32-balanced.mk](../../configs/rv32-balanced.mk)。

完成910项模型扫描、30项整核RTL/PPA比较，以及冻结后六项保留输入的验证。
下表用时按各自STA通过频点重新仿真，开发集和保留集分别以其B0归一化；越小越好。

| --- | --- | ---: | ---: | ---: | ---: | ---: |

均衡预设的全核面积比B0增加 **45.03%**。
开发集用时减少 **46.80%**、面积时间积减少 **22.85%**；
保留集用时减少 **51.22%**、面积时间积减少 **29.25%**。
统一340 MHz时，开发集/保留集周期比分别为 **0.5738/0.5372**。
各配置的最高通过频点均不低于340 MHz；340 MHz是统一仿真点，不是另一次Fmax测量。

**策略本身的额外收益很小。**相对同为1 KiB/4路/32 B的简单SRRIP，保留集平均用时仅减少
**0.52%**，面积时间积减少 **1.13%**，最差单项慢 **2.13%**；
符合事先约定的3%界限。相对小基线的大幅收益主要来自缓存组织，不能全部归于新策略。
这是声明的矩阵、存储模型、AREA3映射和20 MHz网格内的选择，不代表其他工艺或程序下的全局最优。

## 为什么选这些参数

- **1 KiB**：在标准单元实现下平衡容量与成本。2 KiB分段方案虽然开发集用时比为0.4038，
  但面积增至146,512 μm²，面积时间积比0.8459，劣于所选0.7715。512 B/2路/64 B的LRU
  也很接近，面积时间积比0.8011；它是较小面积取向的合理选择。
- **4路**：模型与RTL同时比较相联冲突和选择成本。同为1 KiB/32 B的PLRU从4路改8路，
  同频周期只减少1.77%，面积增加3.41%，合法频率下面积时间积反而增加1.64%。
  8路分段原型还受查询路径限制；这不是对所有8路电路实现的否定。
- **32 B行**：1 KiB/4路PLRU由16 B改32 B，同频周期减少6.99%、面积减少5.38%。
  2 KiB/4路PLRU由32 B改64 B，同频周期反而增加1.15%；更长的行并非总有收益。
- **分段访问RRIP**：连续读取同一行不反复提升保留优先级，离开后再次命中才提升。
  与同一查询旁路结构的普通SRRIP比较，开发集同频周期减少2.66%，合法频率面积时间积
  减少3.18%。选择它是因为实测的有限收益，不是因为机制更复杂。
- **查询旁路**：分配miss与新查询互斥，因此查询不必穿过分配时的全组老化/插入网络。
  策略9与13的六项结果及全部计数器等价；旁路使通过频点从600提升至720 MHz，
  同频周期不变。相应的面积时间积减少4.19%，这部分属于电路改进。
- **拒绝学习表作为当前配置**：1 KiB路径学习方案即使加查询旁路，仍只有460 MHz，
  相比分段旁路方案的开发集面积时间积增加16.45%。2 KiB/64 B的PC学习版也未胜过PLRU。
  已验证RTL以显式策略编号保留，当前预设不实例化这些表。

720 MHz时数据setup slack为0.003 ns、时钟门控setup为0.016 ns，hold两组均通过；
740 MHz未通过。数据最差终点为`data_axi4_manager_o_1_`，不能再把本配置频率瓶颈全部
归于替换查询。数值只对应当前综合后约束，尚无布线/PVT签核或可靠功耗测量。

## 预先约定

用户选择均衡目标：正确性与全部STA组通过后，最小化全核映射面积×执行时间。
执行时间先按三个AI代理类别等权取几何平均，每类两个输入等权；MicroBench单独回归，
不把它称为AI成绩。保留输入每项相对基线退化不得超过3%。候选在开发集选定再验证保留集，
不能看保留结果后更换参数继续宣称独立验证。若新策略未优于简单策略，选择简单策略。
这一面积时间积目标来自用户随后确认的均衡取舍，替代任务书建议的初始时间/面积筛选线。
保留集开始前冻结的回退规则是：开发集胜者若为新策略，还须在保留集保持相对最强简单
对照的面积时间积优势，且每项用时不超过该简单对照的1.03倍；否则采用已经冻结的简单
对照。简单对照若也超过基线的单项退化界限，则保留B0，不重新调参。

基线、未提交差异、RTL和参数冻结在 `result/frontend-selection-20260921/baseline`。
保持RV32I，D-cache和预测器配置不变；共享AXI参照服务从握手开始计时，首beat100 ns、
后续beat10 ns。580 MHz用于前期逻辑筛选；最终同频点取580与全部候选合法频点的较小值，
并重新仿真。各自STA通过点也各跑一次，综合统一AREA3/NanGate45。
最终同时报告最小面积、最短时间与面积时间积，不声称对全部程序全局最优。

**9月22日计时复核：**旧参照RAM每个beat分别向上取整，10 ns在720 MHz下变为
11.11 ns，在800 MHz下正好10 ns。这会影响跨频率的细小策略收益。本轮最终比较改为
从AR握手开始累计物理时间：第n个beat的最早接收周期为
`AR_cycle + ceil((100 + n×10)×CPU_MHz/1000)`。因此不累加逐beat取整误差。
单个读突发占用共享接口，读写通道独立；R受阻时数据保持，已到期的后续beat可逐周期跟上。
这是带突发缓冲的参照目标，不代表所有真实存储器。B响应仍从最后一个W握手起计算首字延迟。
旧的按握手逐beat计时模式保留为`--memory-mode cycle`，不混入新模式的排名。

修正后的测量保存在`result/frontend-selection-physical-20260922`，全部30项重新运行；
镜像、开发/保留划分、候选、评分与回退规则不变。PPA复用相同电路和约束的测量。
`test_reference_memory.py`独立检查多个频率、延迟、突发长度、反压、并发写和请求接收时刻。
独立探针共1158项通过；新模拟器在旧模式下六个开发负载的完整结果和全部计数器与旧记录
一致，新模式的退休数、执行摘要和输出校验值也一致。证据为`memory-mode-audit.json`。
软件执行时间来自固定窗口周期数除以配置频率；这个RAM模型与SoC MicroBench的CLINT计时
是两个实验环境，修正不改变既有SoC定时器或MicroBench镜像。

结构扫描：256 B～16 KiB，1/2/4/8路，16/32/64 B行。模型广筛后，仅将容量曲线有价值的
配置与策略带入RTL，包含同容量简单策略以及增加容量的对照。当前数据阵列是标准单元映射，
不把SRAM产品的容量直接换算成本核面积。
实际产品参照：[Espressif官方ESP32-C3数据手册第4.1.2.3节](https://documentation.espressif.com/esp32-c3_datasheet_en.html)
列出16 KB、8路、32 B块的只读cache，支持预装载及early restart；它服务外部flash，
不是本核独立L1I/L1D结构的直接对应物。256 B是本项目的历史面积取舍，不是从该产品规格
推导出的容量。本轮因此在模型中扫到16 KiB，再按本核标准单元实现的面积与时间筛选。

## 比较与验证顺序

模型包含FIFO、LRU、Tree-PLRU、随机、SRRIP、BRRIP、DRRIP及重用反馈候选；OPT只表示离线
上界。在线策略不得使用未来地址。先在模型中分离空间访问与跨段重用，再筛选上下文预测。
RTL阶段至少补齐LRU和筛中的策略；保持默认基线可复现，所有实验通过配置选择。
新增状态先说明用途、更新时机、同拍优先级、复位/FENCE.I规则，不增加无理由流水级。

正确性包括模型独立交叉检查、替换顺序定向测试、随机反压、同拍请求交接、恢复和响应、
FENCE.I、clean失败停止、dirty-victim恢复及精确异常回归。测量期间不得改变软件镜像和
参考结果。最后冻结开发集胜者，在新保留集、不同延迟和随机反压下检查泛化与退化。

## 模型怎样进入 RTL

`tools/icache_explore/model.cpp`按实际退休PC回放，扫描910个几何/策略组合。在线策略共13种：
FIFO、LRU、Tree-PLRU、Random、LIP、BIP、SRRIP、insert-3、BRRIP、DRRIP、分段访问RRIP、
分段访问加PC反馈、分段访问加路径反馈；另列OPT离线上界。最后三种是本核原型，不能直接
称为ACIC、GHRP或ICARUS。连续访问同一行在模型中压缩存储，但普通策略仍观察段内hit。

模型只筛选miss、回填字节与策略表访问，不输出CPU执行时间。退休轨迹没有错误路径和
握手竞争，RTL测量才覆盖它们。先保留不同容量曲线上的候选，再保留同容量的简单对照；
并分别测试只改行大小、只改容量、两者组合，以及旧SRRIP与带同拍状态前递的SRRIP。
这样可以分开容量、基础电路和策略的收益。
矩阵是有界筛选，不是910项全部做RTL综合。64 B行减少miss的同时可能增加回填流量，
8路增加选择和替换路径；30项RTL点覆盖这些取舍，不能声称未测组合也被证明较差。
DRRIP在不足4组时缺少完整leader集合，这些退化模型行不作为采用该策略的依据。

1 KiB/4路/32 B这一固定结构上，六项开发轨迹的miss几何平均比（PLRU=1，越小越好）：

| 策略 | 模型miss比 |
| --- | ---: |
| FIFO | 1.1728 |
| LRU | 1.0644 |
| Tree-PLRU | 1.0000 |
| 随机 | 1.0221 |
| LIP | 1.0001 |
| BIP | 0.9807 |
| SRRIP | 0.9993 |
| 固定插入3 | 0.9845 |
| BRRIP | 0.9651 |
| DRRIP | 0.9778 |
| 分段访问RRIP | 0.9043 |
| 分段访问 + PC反馈 | 1.5585 |
| 分段访问 + 路径反馈 | 0.9842 |
| OPT（离线上界） | 0.6590 |

在这个结构上，DRRIP没有胜过更简单的BRRIP，真LRU也没有胜过Tree-PLRU。因此优先将
BRRIP和分段访问方案带入整核比较；其余模型结果保留，不把这一点推断成所有容量下的结论。
PC反馈在量化装载上发生明显退化；加入历史缓解了它，却没有胜过只区分访问段的方案。
2 KiB/4路/64 B下PC反馈表现较好，所以仍实现该点，验证它是否能抵消硬件成本。
这些数值只指导筛选，不是加速比；最终决策采用RTL、全核面积和合法频点的结果。

替换模块以同一拍的S1事件更新下一状态，S0查询覆盖同组hit更新前递；
仍与tag读取同步，不增加流水级。LRU/PLRU、随机及RRIP系列通过generate选择，未用分支
不实例化。策略10/11的学习表、签名和重用标志必须计入面积，不能把它们视为免费信息。
13～16利用阻塞式cache不允许miss分配与新查询同拍这一条件，查询不再穿过miss老化/插入
网络。13/14与9/12、15/16与11/10，在六项开发输入上的周期、架构结果和所有计数器
分别完全一致。单独比较STA，
不把查询电路改进归入替换算法收益。完整边界见[电路记录](../microarchitecture/ICACHE_REPLACEMENT_DESIGN.md)。

## 综合与计时口径

测量顶层为`riscv32_core_reset_boundary`，包含处理器核和复位边界，不包含SoC外设、
外部存储及核外I/D仲裁器。所有配置使用相同AREA3映射策略、820 MHz映射目标、
NanGate45典型库、复位buffer处理及SDC。
在同一映射网表上按20 MHz网格确认运行频点，扫描上限800 MHz；达到上限不声称最大频率
只有800 MHz。检查data/gating各自的setup/hold四组，任何`slack (VIOLATED)`均判失败，
包括显示为-0.000的记录。缓存已完成的结果并用二分缩小频率区间；后续扫描还使用报告
估计值选择探测点，并用失败频点的新报告修正后续探测。SDC输入延迟随周期变化，报告的
Fmax估计也可能变化，估计值本身不算通过。搜索已检查所有网格边界、失准估计、周期缩放
和非单调缓存记录；仅改变扫描顺序，不改映射、SDC或通过条件。最终通过点及其上方
一个网格点都实际运行STA；没有放宽时序约束。这里只是综合后时序，不是布线后签核。
历史580 MHz来自DELAY 0映射；本轮B0也统一重做AREA3并通过800 MHz。选型基准使用
这个800 MHz的B0，不把候选相对历史580 MHz的差值全部算成微架构收益。

AI代理TB的固定`#5`只推动离散时钟沿，不使用Verilog的`$time`或主机耗时作为程序用时。
`cpu_mhz`同时决定参照内存的周期换算与`C/f`；因此两处采用同一频率定义。
AI代理计时窗口为`(begin标记退休, end标记退休]`，不计begin标记、计入末尾NOP；
周期数与退休数使用同一边界，`T=cycles/(MHz×10⁶)`，`IPC=retired/cycles`。
观察器从RTL退休接口被动采样，不在负载中轮询CSR；全部配置使用同一镜像。换频率时重新折算相同物理服务延迟后再仿真，不能直接把旧周期数
除以新频率。观察器不开启DUT控制信号；关闭trace文件输出及主机C++从O0改O2只加速
仿真器，基线六项结果与全部计数器逐项一致。最终还检查观察器开关的架构结果等价。

流量用I侧已握手R beat统计，每beat为4 B，包含错误路径流量；没有新增预取或请求并发。
原始计数器`d_beats`实际统计D侧发生读或写传输的周期，若同拍读写只记一次，因此导出时
明确命名为`data_transfer_cycles`，不把它与I beat相加冒充全部总线字节数。
访问计数和传输量只是活动指标，不作为功耗测量。

MicroBench使用SoC原有软件镜像和原生计时器窗口，CPU频率显式传入、外设参考100 MHz，
CLINT提供1 MHz微秒计数。被动观察器同时核对timer tick差与CPU周期差，误差小于一个tick，
这里指每个独立计时区间；Scored汇总十个区间，取整差也会累加。原程序Total/Scored打印
值必须分别与tick统计一致。它和上述共享AXI参照RAM是两种存储环境，成绩分开列。
