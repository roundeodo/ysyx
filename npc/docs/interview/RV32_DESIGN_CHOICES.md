# RV32 面试：结构、参数与选择理由

更新于 2026-09-24。本页描述 `NPC_CONFIG=rv32-balanced`；具体模块连接见
[架构说明](RV32_ARCHITECTURE_ATLAS.md)，构建和测量口径见[固定版本](RV32_REMOTE_SNAPSHOT.md)。
旧 `rv32-baseline`、历次实验和简历初稿中的参数不自动代表本版。

## 如何介绍项目

这是 RV32I 单发射顺序处理器，支持 Zicsr、Zifencei、基础 M-mode 异常、定时中断和 mret。
流水线使用 Valid/Ready 接口处理反压，使用前递减少数据相关等待，并约束指令发出与完成
顺序以保证精确异常。前端包括参数化 I-cache 和 BHT/BTB/RAS；数据侧是阻塞式写回缓存
及非缓存通路。取指与数据 AXI 通路在系统层共享外部存储接口，接入 ysyxSoC。

边缘 AI 是软件场景：研究使用 tokenizer/解析、量化数据装载、runtime 控制等代理。
本版没有乱序、多发射、硬件乘除法、向量、MMU 或 AI 加速器，也没有完整模型推理成绩。

## 指令流与寄存边界

预测器并行查询 BHT、BTB、RAS，统一保存一次预测响应。IFU 将预测身份与 I-cache
指令配对，送入两项取指缓冲。队首指令组合译码、读取 GPR、选择前递并检查相关性，
满足发出条件后写入 ID/EX；没有独立 decode/RR 寄存级。

EXU 内含 ALU、分支处理和 AGU。普通结果进入执行结果寄存级，访存请求进入 LSU，
随后两条完成通路汇合至 WB；提交控制是组合逻辑。取指、译码、执行、访存、写回和
提交是功能划分，不能因此称为固定六级流水线。没有 ROB 或物理寄存器重命名。

## 为什么采用这些资源

| 当前选择 | 理由与实际取舍 |
| --- | --- |
| 单发射、顺序执行 | 先实现可验证的指令、异常和 SoC 系统，避免当前引入乱序完成与恢复状态；不宣称对所有边缘程序最优 |
| 取消独立 RR，保留 ID/EX | 减少一次传递和寄存器；译码、GPR 读取及前递组合路径变长，接受按 STA 降频 |
| 两项取指环形 FIFO | 空队列直通，满队列出队可同拍入队；不搬移整条载荷，不据此宣称多个 I-cache miss 并发 |
| I-cache 1 KiB、4 路、32 B/行 | 扩大代码工作集容量、减少冲突和行数开销；更长 burst 增加占用，容量与相联度增加面积，经过开发/保留集与完整 STA 比较 |
| I-cache 策略 13：分段访问 RRIP | 每行二位重用距离状态；只有离开该行后的再次命中才提升优先级，避免连续取同一行把所有行都视为近期有用；查询旁路不经过互斥的 miss 分配更新 |
| I-cache 单缺失，Early Restart | 所需字到达先返回，继续完成整行；没有改变自然 burst 顺序，也没有多 MSHR 或 hit-under-miss |
| D-cache 256 B、2 路、16 B/行 | 阻塞式 Write-Back / Write-Allocate，8 组、每行 4 beat；本轮固定它以隔离前端收益，未宣称其容量或策略已达最优 |
| BHT 16 项、二位计数器 | 按 PC 索引，少量状态；较大 bimodal、gshare、小型 TAGE 在当前负载/预算下未改善综合面积×时间，故保留小表 |
| BTB 总计 16 项、2 路、8 组 | 保存完整目标，策略 0；扩容、准入、替换、目标编码分别比较。短目标在跨地址区间调用时退化，未默认启用 |
| RAS 4 项 | 用已解析的调用/返回更新，补充返回目标；没有推测栈检查点，深调用仍可能溢出 |
| 预测器单级响应 | BHT/BTB/RAS 并行读取后组合选择，不再串接无必要的两级 BTB；TAGE 原型也沿用同一响应边界，但其逻辑和状态成本实测更大 |

当前配置在[预设](../../configs/rv32-balanced.mk)中显式固定。实验机制由参数选择，
关闭后的映射面积也单独测量；不能将扩容、公共电路或缓冲驱动收益归给算法。

## 控制与恢复必须讲清楚

**前递和相关性：**选择程序顺序中最近的同名寄存器生产者。较年轻的生产者尚未完成时，
不能取更老 WB 的值。当前已有 LSU 成功完成拍的 load 前递；还需满足响应、异常和
下游接收条件。直通消除等待也会拉长组合路径，并非所有状态都可以删除。

**精确异常与 store：**较老 EX 结果包含异常时阻止年轻指令发出；老 LSU 未完成时也
限制年轻执行，防止尚未恢复就把 store 送出。已被总线接受的写事务不能靠 flush 撤销。
放开 LSU 成功完成拍的交接不等于允许年轻指令任意越过老访存提交。

**FENCE.I：**排空旧请求、clean D-cache、失效 I-cache 和相关预测状态后恢复。
在 EX/LSU 分流前统一纠正“预测 taken 但实际非分支”，避免新指令沿旧目标继续执行。
clean 错误进入复位才能退出的硬件停止状态；普通 dirty-victim 写回失败先恢复旧行，再
报告当前访存异常。不能把 FENCE.I 已提交后的错误补成属于该指令的普通精确异常。

**定时中断：**CLINT 比较 mtime/mtimecmp，经 MTIP、MIE/MTIE 和安全边界形成完整受理
路径，停发并排空后进入 trap，mret 返回。没有由此实现外部中断控制器或证明完整 RTOS
调度。中断本身不计作退休指令。

## 研究与性能怎样讲

先讲瓶颈、假设和简单对照，再讲模型筛选、RTL、安全验证、面积/STA 和保留输入。
I-cache 选用分段访问 RRIP，借鉴 ACIC 对访问段的区分，没有实现完整 ACIC；TAGE 原型
借鉴几何历史、tag 和 provider/alternate，使用已解析历史，不是完整 TAGE-SC-L。
其他文献、失败方案及取舍见[研究索引](../learning/FRONTEND_RESEARCH_INDEX.md)。

当前整核含复位边界面积 101,418.618 μm²，NanGate45 综合后完整 STA 通过 720 MHz。
这不是布局布线后频率，不含整个 SoC，也没有实体 SRAM 宏。旧简历的约 69,400 μm² /
767 MHz 属于历史配置，不能与本版 1 KiB/4 路 I-cache 混用。

MicroBench 报告同时给出原生定时器时间和相同窗口 IPC。Total 包含准备、验证及部分输出，
Scored 是计分窗口之和，两者 IPC 不必相等。原生 SoC 延迟模型仍有已知局限，主研究采用
独立物理延迟模型，具体边界见[计时规则](../verification/MICROBENCH_TIMING_RULES.md)。
本次固定发布没有新 train 测量；历史分数、插桩结果和官方参考不能直接混算加速比。

## 简历表述边界

- I-cache 写“参数化组相联 I-cache，当前 1 KiB/4 路/32 B 行”，不沿用当前两路的说法。
- 中断明确为 M-mode 定时中断；RT-Thread 需有对应版本的运行证据。
- DiffTest 比较 PC、GPR 和关键 CSR；访存副作用另由定向测试、断言和总线观察检查。
- 当前可复现综合/STA 使用 Yosys/Slang 与 iEDA/iSTA；OpenSTA 需对应历史使用证据。
- 研究保留原型与负结果，不把默认关闭、仅模型测试或未实现的机制写成稳定版已采用。
