# Codex 任务书：面向边缘 AI 软件的 CPU 前端探索与实现

## 任务目标与自主范围

仓库：`roundeodo/ysyx`，基础分支：`rv32-interview-20260911`。

针对指令预取、分支/目标预测、I-cache 分配与替换管理，自主完成：读取当前实现、诊断负载瓶颈、研究近年一手工作、筛选候选、设计电路、实现 RTL、验证、综合/STA、性能对比以及形成取舍结论。不要只交一份论文综述或实施计划，也不要先指定一个算法，再为它寻找理由。

优先考虑近年的方法或从近年工作提取的机制，但“新”不是默认启用标准。完整原型可以失败，失败候选保留实验记录；最终采用的机制必须优于合理的简单方案，或给出明确且可验证的其他工程价值。可以只改一个最值得改的方向，不要求三个方向都新增结构。

在实验工作分支中自主推进正常的工程决策，不必逐项等待确认。先写执行计划，再按阶段继续执行。不得擅自覆盖用户未提交工作、重置主分支、推送或合并远程分支，或扩大到不相关的 ISA、MMU、乱序后端及完整 L2 建设。

## 1. 读取实现，冻结可复现基线

先检查仓库中的 AGENTS.md，以及：

- `npc/docs/development/DEVELOPMENT_PROCESS.md`
- `npc/docs/development/NAMING_GUIDE.md`
- `npc/docs/architecture/AI_WORKLOAD_MODEL.md`
- 当前架构、前端、缓存、总线、验证和计时规则文档，以及对应 RTL、Makefile 和测试脚本。

以开始任务时实际取得的源码为准，不凭聊天记录判断结构。记录远程/本地 commit、未提交 diff、配置、工具版本、软件镜像与 ELF 哈希、链接布局、计时窗口、存储模型、随机种子及复位/预热方式。涉及最新修改时，先将其与本轮基线的关系说明清楚。

先运行相关基线验证。新观察器应当被动，不影响 DUT 控制，默认不进入综合；开启与关闭观察器应核对程序行为和计数。编译、仿真、综合分别使用独立输出目录，旧结果不得覆盖。

不要重新展开此前已决定暂缓的问题。若某个新候选直接依赖这些边界，先说明必要性，将必要正确性修复独立提交、独立建立基线，不能把它的收益混入新算法。

## 2. 选择能运行、能校验的负载，先测瓶颈

现有 MicroBench 保留为回归和参照，不能作为边缘 AI 适用性的唯一证据。依据当前 ISA 和运行环境，选择或移植实际可运行的小型 tokenizer/查表、sampling/后处理、量化解包/布局变换、runtime 命令队列或调度程序；不要求当前核运行完整大模型。明确这些是 CPU 代理负载，不冒称异构 SoC 的端到端 AI 成绩。

负载须有独立输出校验和不同输入、规模或阶段。若缺少浮点等能力，不暗中扩大 ISA；说明采用整数版本、软件例程或替代负载的原因及代表性。合成微基准用于隔离循环、冲突、间接跳转和带宽机制，不能代替真实负载的主结果。

在调参前划分开发/调参集与保留测试集，固定程序、输入、统计窗口和权重。不要把同一轨迹相邻片段当成独立泛化测试，也不要把 MicroBench 的 test/train 档位名称直接当作研究意义的训练/测试分离。最终全局参数冻结后再测保留集，不能逐程序手工挑选最优参数。

至少诊断：I-cache 工作集与冲突、暴露的取指等待；方向错误、BTB 缺失/目标错误、间接目标及返回错误；预测提前距离；I/D 总线竞争；可用于预取的实际服务机会。停顿分类应定义互斥规则或明确重叠，不能把所有计数直接相加当成 CPI 分解。

可使用理想化实验估计方向的潜力，但必须明确它放宽了哪些约束；理想预测或零延迟缓存只是诊断条件，不能算可实现结构。

## 3. 核验一手文献，筛选有适用前提的候选

优先检索任务执行日前已公开的近年工作，阅读作者论文、正式会议/期刊页面及作者 artifact。旧的经典方法用于强基线，不包装成最新研究；预印本、竞赛论文和主会论文必须区分。聊天中的论文名只能作为线索，需重新核验。

可作为检索起点的机制包括：Wrong-Path-Aware Entangling 的及时性与错误路径训练控制；SmartScout 的选择性 BTB 预填充及提前纠正；MORSL 的选择性预测表访问；Bumper 的退休有用性反馈。也应主动寻找更适合小型顺序核的新工作，而不是被这些名称限制。

对真正影响决策的每个候选，记录：来源与公开时间；解决的原始瓶颈；原系统规模、缓存层级、软件和并发前提；查询/训练时刻；需要保存的状态、位数、端口和恢复信息；本核是否具备这些前提；保留、删减和修改哪些机制；可证伪的收益假设；实现与验证成本。论文的“新增开销”不得误写成完整结构成本，L2 或大规模乱序核的结果不得直接外推到本核 L1I。

缩小或改造后的方案应称为“借鉴某机制的实现”，不能声称完整复现论文。参考代码要检查许可证和依赖。快速筛选最多聚焦 2～3 类机制，RTL 深入实现控制在 1～2 个有明确潜力的候选，不进行无边界的大规模穷举。

## 4. 先固定对照和预算，再做实现

对照至少包含以下逻辑层次；不涉及的层次可说明后省略：

| 对照 | 用途 |
| --- | --- |
| B0：冻结的当前实现 | 确定本轮变化 |
| B1：合理调参或同等预算扩容的简单实现 | 排除收益仅来自增加资源 |
| B2：只增加必要基础结构 | 隔离队列、buffer、并发或流水边界的收益 |
| B3：相同基础结构上的简单策略 | 例如简单预取、基础方向预测或 LRU/RRIP |
| C：相同基础结构上的新机制 | 测量新机制的独立价值 |

先测单项，再组合有证据的单项；组合后逐项关闭机制做消融。不能同时改预取、预测器、缓存容量和频率后，把全部收益归给其中一种方法。

做替换策略实验须有多个候选 way；保持直接映射时，将研究准确称为准入、旁路、预取 buffer 或 victim buffer，而不是 victim 选择。预测器的同预算比较须包含 tag、useful、历史、checkpoint 和元数据，不只比较计数器数量。预取成本须包含数据缓冲、地址表、队列、身份跟踪和新增端口。最终用综合结果核对总成本。

默认以实际执行时间为主指标、面积为约束，能耗作为有测量基础时的附加指标。本轮建议初始筛选线为：相对最强合理简单对照，固定权重的执行时间比几何平均不超过 0.97；全核映射面积增加不超过 5%；关键保留负载的执行时间回退不超过 3%。这是项目探索门槛，不是文献结论，也不是保证能够达到的承诺。

门槛、负载权重和存储预算须在候选评分前写入计划。若基线诊断说明门槛或预算不适当，可事先说明理由修改；不得在看到保留集结果后降低标准。未达标但有机制价值的候选可以保留为默认关闭的实验选项，不宣称为默认优化。

## 5. 从模型筛选进入真实 RTL

先复用或扩展已有 trace/性能工具缩小设计空间，再实现最有潜力的现代机制与对应简单对照。除非已证明近期候选缺少必要前提或被强基线支配，否则不要只停留在扩容或文献筛选。

功能轨迹适合初筛覆盖率、关联和 miss，但仅有退休 PC 的轨迹不能证明错误路径流量、预取及时性、总线争用或最终 IPC。在线策略只能使用当时已获得的信息，不能用未来 PC、未来 miss、尚未解析的分支方向或精确未来延迟训练。离线画像辅助方案须单独核算画像、元数据和泛化条件。

写 RTL 前，在现有模块说明中画清实际结构与接口；为新增状态写明所有者、分配、读取、更新、释放、flush 和复位条件。逐拍说明命中、未命中、受阻、新旧交接、恢复和错误路径。新增寄存器、等待状态和旁路都要有明确作用，不能为少一个状态破坏时序或协议，也不能为“模块化”重复保存大块载荷。

保持正式 RV32 基线可重现，候选由明确配置选择，不在顶层混入策略。新增能力须有真实实现与测试，不把增加 MSHR 参数或队列深度等同于已经实现并发能力。当前没有的 L2/MMU/大规模 OoO 前提只能列为未来工作。

## 6. 必须保持的正确性约束

不得回退已有精确异常、非分支错误 taken 纠正、FENCE.I 预测暂停、clean 失败停止和 dirty-victim 恢复机制。

预取与架构需求请求分开记账；预取本身不得凭空产生 fetch_entry、退休或架构异常。限定合法可预取区域，处理重复请求和 demand/prefetch 合并。已经展示且受阻的 valid 必须保持，已握手 AXI 事务不能直接取消；“需求优先”不意味着撤销已发出的预取 burst。错误预取的处理不能掩盖未来真实需求应报告的异常。

FENCE.I 必须覆盖新增预取缓冲、预测快照与在途回填，旧响应不能在维护后安装成新有效代码。若增加并发，重新验证预测元数据与响应的配对，不能继续默认只需要一个 pending_prediction。epoch/tag 回绕安全须考虑事务存活期间可能发生的恢复次数，不能仅凭“并发数小于 epoch 数”作保证。

若增加推测 GHR/RAS、循环状态或历史索引，明确查询快照、训练身份与错误路径恢复；不得使用已被后续查询改变的索引更新旧预测。

测试覆盖复位首拍、满/空边界、同时事件、随机反压、请求重复/错配、redirect 与返回同拍、FENCE.I 与预取同拍、总线错误及所声明合法的参数边界。优先通过独立参考结果、事务 scoreboard 和断言检查，不只检查程序结束。不得通过关闭断言、删掉失败用例、放宽架构结果或修改 reference 来制造通过。

## 7. 可信的时序、性能和功耗评估

核查仓库记录的 AXI Delayer 请求起点敏感性。对依赖并发和提前发请求的方案，必须有服务时序定义清楚、经独立探针核验的参照模式；历史模型可保留作对照。若需要修正模型，作为独立变更并重跑全部有关基线，不能把模型修正算作新 RTL 的收益。无法排除模型影响时，将结论限制为该模型下的观察。

同时报告同频率周期对比和各设计在通过完整 STA 的运行频点下的执行时间对比。执行时间 T=C/f；缓存/设备服务时间、带宽和计时器应按同一物理定义处理。降频导致设备延迟折算周期变化时，不能把 IPC 上升当作算法收益。不得将仅数据 setup 推算的 Fmax 或显示为 -0.000 的违例当作全时序通过，也不得把综合后 STA 称为布局布线签核。

同频 RTL 对比固定软件镜像、工具、链接布局、计时窗口和非 RTL 输入。软件辅助方案另开比较轴，不能与纯硬件收益混计。不同输入、存储延迟、带宽竞争和随机反压应做敏感性测试；最终报告所有约定负载，而不只列收益最大的。

报告额外预取流量、及时/迟到预取、未使用淘汰、真实退休使用、D-side 等待、分支错误分类以及面积/关键路径。没有可靠功耗工具时，只报告可测的表访问、端口活动或翻转代理量；表位数下降不能直接换算成能耗下降，更不能捏造 pJ 或每 token 能耗。

## 8. 交付与结束条件

在仓库内维护一份持续更新的执行计划，复用已有规范，不为每个小实验建立重复说明。至少保留：基线 manifest；有取舍结论的文献对照；候选与淘汰记录；可重跑实验脚本和机器可读结果；候选 RTL/配置与测试；原始日志索引；更新后的模块结构说明；最终设计决策记录。大体积波形、构建缓存与完整 trace 不直接提交 Git。

每个候选记录“假设—改变—结果—解释—决定”。必须明确说明至少一个被拒绝的更复杂方案，以及简单方案是否已经足够。最后回答：主要瓶颈是什么；为什么选该机制；为何不选其他方法；收益是否仍存在于同预算简单对照和保留集；增加多少状态、路径和流量；哪些场景退化；是否建议默认启用。

自主继续普通研究与实现步骤，不在每次算法或参数选择时等待用户决定。使用受控并行度、小批筛选和可复用缓存，不在共享环境无边界启动大量仿真/综合。遇到缺工具、权限或外部资料时如实记录，不能编造实测数据或修改无关系统环境。中断时保留可继续的具体进度，不将未完成项目标成通过。

成功结果不限定为“新机制必须胜出”。满足证据与正确性门槛的方案形成建议合入版本；没有胜出时保留稳定基线，交付已验证原型、负结果和原因。不要通过强行开启、降低验收标准或只挑有利负载满足“必须更先进”的表述。
