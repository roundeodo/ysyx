# 仿真与综合产物保留规则

默认覆盖固定工作目录，不为每次运行累计完整编译与综合产物。

- MicroBench：继续使用 `scripts/run_microbench_perf.py`，默认目录为 `result/performance/current`。
- 通用综合：使用 `scripts/run_synthesis.py --target <目标> 参数=值`，默认目录为 `result/synthesis/current`。RV64 可用 `--target sta`，RV32 可用 `--target sta-reset`。
- 原始 `make sta*` 是底层入口，不具备完整的归档和清理流程；日常测量使用上述 Python 入口。

运行前锁定工作目录，保存上次的小型报告后覆盖；不删除其他正在运行的任务、源码或工具。
只自动覆盖带有 `.npc-generated-workspace` 标记的自有目录；旧目录需先单独检查。
自定义输出目录须位于 `npc/result` 下。不要把外部日志重定向到将被覆盖的目录。

成功后保留配置、命令、版本/源码哈希、周期与退休数、IPC、时间、面积及 STA 报告中实际取得的指标；
小型结果和自动摘要归档至 `docs/verification/data/run-history/`，保留正负结果供比较。
编译目录、源快照、仿真器、综合网表等大产物删除；工作目录内大日志仅保留末尾。
分析者仍需记录关键路径、改动理由与取舍；自动摘要不能替代人工分析，也不能将工具退出成功等同于时序通过。
源码哈希只用于身份核对，不能替代未提交源码的备份；重要实现应单独提交版本。

失败时暂留当前工作目录供诊断，下一次正常运行覆盖。需要完整调试产物时显式传 `--keep-artifacts`。
`--prepare-only` 会保留后续 `--resume` 所需的镜像；完成并清理后的性能运行不再支持重新执行其旧镜像。
旧的时间戳目录不会被新入口自动批量删除。本次已清理的原始产物索引可能失效，以保留的报告及清理清单为准。
