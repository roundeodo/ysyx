# 负载规模与分支收益归因

本页对应当前源码的B0-victim、N0-victim、NSL-victim及早期目标组合。
十四个开发窗口：五类代理各两个输入，jsmn/miniz各冷、暖两个窗口；七个家族等权。
同一RV32I镜像、700 MHz、128KiB测试台RAM、100ns首响应/10ns后续beat。
用户要求不运行train；没有启动train，也不以train替代目标软件代表性检查。

## 现有负载有多大

每窗口36,777～443,280条退休指令、10,138～98,075次条件分支；63～231个不同控制流PC。
执行过的32B代码行39～163条，约1.2～5.1KiB；这是代码覆盖，不是动态数据工作集。
B0窗口148,504～2,930,739周期，在700 MHz下为0.212～4.187ms。
真实请求流仅六次调用；两个config约0.6KiB，另外四个对象各取64个词表项。
暖窗口只排除前两次请求，尚未证明预测器训练收敛。

宿主机墙钟与CPU时间分开：原始带事件/退休trace日志中，B0单窗口0.605～25.201s，
NSL为1.767～28.029s，十四项分别合计144.796s、170.213s，不含编译。
它们受宿主负载、编译优化和日志IO影响，不能据此比较CPU性能。

这些输入能用于功能、别名冲突和目标缺失诊断，但不能代表完整边缘AI软件。
静态分支数已大于16项BTB，所以“短”不等于没有表容量压力；
同样，重复现有输入很久也不会增加代码覆盖、间接目标种类或自然阶段。
0.31%来自确定性周期计数，不是宿主耗时噪声，但其外推范围仍很小。

## 方向改善为何没有等比例转成加速

下面计数均来自实际RTL事件，不是立即更新的软件模型。
84个配置/窗口的分支按退休控制流顺序逐项对齐，检查镜像、频点、访存设定、退休数和日志哈希。
总计每配置578,760次条件分支、2,384,137条退休指令。

| 配置 | 原始方向错误 | 条件分支EX纠错 | 方向正确taken、无BTB目标且仍晚纠错 | 家族等权时间减少 |
| --- | ---: | ---: | ---: | ---: |
| BHT16 | 70,477 | 75,563 | 19,349 | 参照 |
| TAGE | 25,981 | 55,733 | 34,689 | 0.43% |
| TAGE＋SC＋Loop | 29,225 | 57,044 | 33,202 | 0.31% |
| BHT＋早期直接目标 | 70,476 | 70,476 | 0 | 1.86% |
| TAGE＋早期直接目标＋早期RAS | 26,710 | 26,710 | 0 | 5.05% |
| TAGE＋SC＋Loop＋早期直接目标＋早期RAS | 30,324 | 30,324 | 0 | 4.76% |

前三项已取得匹配的700 MHz时序资格。后三项是700 MHz等周期条件的功能性能诊断，
对应新源码的PPA还在补齐，不能当作全部已能实际运行700 MHz。
表中的原始方向错误只问taken/not-taken；EX纠错检查最终next PC。
BTB缺失时顺序取指还会掩盖一些错误taken，因此这两列不能直接相减得到目标错误。

纯TAGE方向错误减少63.13%，但条件EX纠错只减少26.24%；NSL分别减少58.53%、24.51%。
NSL剩余条件EX纠错中33,202/57,044（58.20%）是方向正确taken却没有BTB目标。
0.31%那项early target/RAS均关闭，不能用它概括完整TAGE子系统的上限。
早期目标电路在I-cache返回指令后计算B/J目标，仍晚于最初预测查询；它把很多纠错提前，
不能把“EX不再纠错”视为“零预测代价”。组合变化也改变历史训练时刻和错误路径，原始错误并非固定不变。

存储和等待也限制收益。B0十项代理的周期分类中，36.93%为没有退休且LSU活跃，
47.62%为前端无指令且无结构阻塞；后者含I-cache及恢复影响，不能全称为I-cache miss。
四项真实请求窗口中LSU活跃等待占80.12%。NSL在十四项上少18,519次条件EX纠错，
总周期只少57,623；数据等待从10,964,538到10,962,398，I-cache miss反而从51,634到51,777。
这些是联合执行结果，不用“每次错判固定罚N拍”反推总时间，也不把这些占用计数当严格因果分解。

缩放SC/Loop当前也未稳定优于纯TAGE：十四项方向错误多3,244次。
这只限定于当前小表、特征、训练规则和输入，不代表作者完整TAGE-SC-L无效。
逐查询拆分已补在[SC与Loop的覆盖归因](correctors.md)，区分改对/改错以及独立运行带来的训练时刻变化。
BTB总容量、扩容成本和其他目标获取方法见[BTB与EX纠错](target-options.md)。

## 仍需完成的检查

每8,192次条件分支已输出一个统计窗口。jsmn冷窗口的TAGE错误率从首窗3.56%降到后续约0.5～1.1%；
miniz则有明显阶段波动。短ini/json仅约两个窗口，不足以证明稳态。
这些变化不能直接归因为预热：输入内容、调用阶段与表状态也同时变化。

后续在不使用最终保留输入的前提下，先固定更长、内容和阶段不同的实际请求序列，
分别增加单请求规模和请求数量；记录学习曲线、热点/低频分支、代码与数据范围和间接目标分布。
自然前缀、冷启动与计分区间分开，并检查排序是否随窗口长度变化。
若128KiB测试台限制真实输入，容量调整要对所有候选和基线一致，单独注明，不能偷偷改变cache或访存时延。
负载覆盖、方向/目标联合验证和合法频点PPA完成前，不冻结最终默认方案。

可复现：`python3 npc/tools/branch_v3/analyze_attribution.py`。
机器数据：[attribution.json](attribution.json)；代码覆盖：[workload-profiles.json](workload-profiles.json)。
JSON保留每项原始日志、二进制和解压事件哈希、分窗计数及等权计算结果。
