# BTB容量、目标获取与EX纠错

本页区分当前实现、已有原型和待验证方案；16项只是冻结起点，不是已证明的最优容量。

## 16项的含义和成本

当前比较配置使用完整目标BTB，总16项、8组、每组2路。每项对应一个控制流指令PC，
条件分支、JAL、JALR及return共享容量；BHT/TAGE和4项RAS另计。
默认BTB policy0允许not-taken条件分支分配；容量压力不只来自taken分支。

RV32I中完整表项的逻辑字段是27bit PC tag、32bit target、2bit kind、1bit valid，
16项加8个替换指针约1,000bit。扩为32项/2路时tag缩为26bit，连替换状态约1,968bit。
这只是逻辑状态位数，不是综合面积；无用低位可被综合优化，选择器/写译码也有额外成本。

现有流程将小表映射到标准单元，增加组数会扩大存储及读写选择逻辑，但保持两路时
查询仍只比较选中组的两路tag。不能将它描述为全相联比较器随容量全部展开，或宣称成本必然超线性增长。
旧B32测量不能直接与当前victim改写后的B0作精确面积归因；本轮已补同源码、同约束的
16/32/64/128容量对照，使用`btb-results.json`中的新结果。

当前十四个窗口覆盖63～231个不同控制流PC。这个数说明16项很小，不能单独证明动态热点需要多少项；
还应分别统计首次出现、前次尚未解析、组冲突和容量替换，以及不同控制流类型的目标缺失。

## EX纠错计数是什么

EX仍然验证实际条件与目标；希望减少的是发现next PC不匹配后的redirect/年轻指令取消次数，
不是取消EX验证。当前BTB同时负责控制流类型识别和目标供应：

`BTB缺项 → selected_taken保持0 → 按PC+4取指 → 实际taken在EX发现不一致 → redirect`。

因此方向预测正确不等于最终next-PC预测正确。NSL十四个窗口的57,044次条件EX纠错中，
33,202次是方向正确taken而原查询没有BTB目标。其余也包含方向错误等因素，不能全部按容量问题处理。

## 可比较的解决方法

| 方法 | 解决什么、何时生效 | 当前状态与代价 |
| --- | --- | --- |
| 同路数BTB扩容 | 查询时保留更多类型和目标，减少部分替换/冲突 | 16/32/64/128已补同源码闭环RTL/PPA，见[BTB联合探索](btb-study.md)。首次出现和未及时训练不能仅靠扩容解决 |
| 早期直接目标 | I-cache返回后识别B/J，计算PC+立即数，与方向预测结合，在EX前改正路径 | 已有RTL与恢复/反压测试；有组合延迟，EX纠错减少不等于零代价 |
| I-cache预译码信息/目标预填充 | 在refill或较早前端边界保存类型/位置信息，减轻对BTB识别的依赖 | 尚无完整RTL；占metadata，必须考虑查询时机、FENCE.I一致性和端口 |
| BTB准入、替换和索引 | 减少低收益项占用，降低热点冲突 | 已有若干策略开关；不能只按命中率排名，还要看漏识别和late redirect |
| 目标压缩或共享高位 | 同预算存更多entry | 已有compact RTL及跨区回退测试；表达不了的目标必须保留正确回退，不按低位相同误认完整目标 |
| 小快表＋较大慢表 | 小表维持早期预测，慢表补目标 | M0/M1诊断已有，尚无完整闭环RTL。小表命中不应强制等待慢表；迟到覆盖须计入真实周期 |
| RAS/间接目标专用路径 | 返回使用栈顶，多目标JALR可使用独立历史 | early RAS有RTL；一般JALR仍需寄存器目标或预测器，不能靠PC+立即数获得 |

[BOOM官方BPD说明](https://docs.boom-core.org/en/latest/sections/branch-prediction/backing-predictor.html)
明确将方向预测与控制流识别/目标获取分开：后者可来自BTB，也可来自I-cache返回指令的译码。
[NLP说明](https://docs.boom-core.org/en/latest/sections/branch-prediction/nl-predictor.html)
还描述了目标高位压缩。它们提供组织方式参考，不直接给出本核的最佳容量。

## 顺序与乱序的区别

先进方向预测器不依赖乱序执行才能工作。相同预测输入和训练序列下，改成乱序不会自动提高算法准确率。
从微架构代价推断，宽发射、深流水、较晚解析和更多在途指令通常使误预测更昂贵，
所以准确率改善往往更有价值；但乱序也可能提前解析独立分支，或以较老工作覆盖部分恢复时间。
实际收益必须测量，不能只依据“是否乱序”。

本核还受目标缺失和存储等待限制；移到乱序也不会自动修复当前SC选择与Loop迭代时机的问题。
本轮已把32/64/128项作为强简单对照，与早期直接目标及方向预测联合比较。
TAGE配改进BTB后的收益明显增加，说明固定16项目标供给的旧结果不能否定整个方向；
是否值得增加面积，仍须看各自合法频点和保留输入，见[联合探索记录](btb-study.md)。
