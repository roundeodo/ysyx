# BTB联合探索：当前证据与取舍

2026-10-02追加：三种旧替换控制之后，已扩展14种策略、六种组织及方向/预填充联合模型，
共420点/14开发输入；另做同组织SRRIP/SHiP式RTL对照，见[替换策略补测](btb-replacement-study.md)。
本页35点及原保留集记录维持原口径，追加模型准确率不能混入其周期/PPA结论。

稳定默认保持BHT16、BTB16/2路、线性索引、原轮转/全部准入；本轮没有推送。
冻结后的保留集已完成，最终选型见[取舍记录](decision.md)。
最新完整数值见`btb-results.json`。35个RTL配置已完成PPA和各自合法频点；
长窗口与最终保留集的状态单独记录，不能由短开发窗口替代。

## 为什么继续做

原TAGE能降低方向错误，但目标缺失仍造成EX恢复。本轮不固定16项BTB后否决TAGE，
而是把容量、相联度、索引、准入、替换分开，再与方向预测联合。
旧policy把替换与新not-taken是否准入绑在一起，无法分别归因；新增准入开关解决这个实验缺口。

## 模型、电路与对照

M1共120点：16/32/64/128项、2/4路、三种索引、轮转/2路LRU/SRRIP、全准入/taken准入。
`screen_btb.py`保留完整自然前缀和实际Q/F顺序，同拍先查询旧状态再训练。
独立C++模型存完整PC，不复制RTL的tag切片；旧BTB的3,234,632次查询命中、目标和类型全部复现。
候选仍使用基线时序，不重生错误路径，模型缺失减少不当成CPU加速。
全相联LRU影子表只说明同容量能否覆盖某次缺失，不声称对所有替换策略完成严格3C分类。

完整目标BTB增加索引0/1/2和独立准入0/1/2，电路及失效契约见
[模块说明](../../microarchitecture/BRANCH_V3_DESIGN.md#btb索引与准入实验)。
没有新增流水级或待写队列，稳定默认的周期和综合面积与本轮改动前完全一致。
折叠索引所有路共用同一组号，不是每路索引不同的skewed BTB；本轮也没有声称复现MicroBTB。

13组实际RTL先做单项/组合：容量四点；单独taken准入、单独SRRIP-all、SRRIP-taken；
单独fold、单独4路；4路SRRIP-taken的线性/fold对照；32/64项模型筛选组合。
随后加入TAGE及SC/Loop、早期直接目标的联合与消融；具体开关冻结于`btb-matrix.json`和`btb-joint-matrix.json`。

## 已确认的机制结论

十四个开发窗口、七类应用等权、700MHz逻辑比较：

| 配置 | 时间减少 | 说明 |
| --- | ---: | --- |
| 单独TAGE | 0.43% | 原BTB16 |
| BTB16/4路/fold/SRRIP/taken | 0.90% | 方向仍为BHT |
| BTB32/4路/相邻段XOR/SRRIP/taken | 1.81% | 方向仍为BHT |
| BTB64/4路/fold/SRRIP/taken | 2.96% | 方向仍为BHT |
| TAGE＋上述BTB64 | 5.07% | 没有早期目标；方向/目标联合才体现更多收益 |
| TAGE＋SC＋Loop＋上述BTB64 | 5.44% | 不能据总时间推断SC方向更准 |

本表的700MHz只隔离周期差异；未通过700MHz STA的配置不能把本表当作合法运行时间。
普通扩容不是单调改善：BTB64普通轮转十四窗口等权时间约增加0.03%，BTB128减少0.79%。
量化加载2418中，普通64项将纠错7,334→5,901，却使I-cache miss 934→1,181，周期1,224,590→1,247,783。
这是缓存/请求序列的实际交互证据；不能把纠错次数乘固定惩罚当作周期收益。

在相同578,760个条件分支中：

| 配置 | raw方向错误 | 条件EX恢复 |
| --- | ---: | ---: |
| BHT＋原BTB16 | 70,477 | 75,563 |
| TAGE＋原BTB16 | 25,981 | 55,733 |
| TAGE＋改善BTB64 | 28,355 | 26,179 |
| NSL＋改善BTB64 | 31,023 | 27,940 |

TAGE＋改善BTB并非方向本身更准；查询时机和训练可见性也改变，主要改善是有效next-PC供应。
NSL仍比纯TAGE多方向错误/条件恢复，却略少总周期，须按所有跳转与cache交互解释，不能说SC退化已修好。
只在taken时准入会故意缺少更多not-taken表项，所以“所有条件查询的BTB miss”不能直接代表有用目标缺失。

## 替换策略的独立影响

2026-10-02复核既有记录。固定BHT16、BTB16/2路、线性索引、镜像、cache及存储模型，仅改变替换；
全部准入与taken准入分别比较。14个开发窗口、七家族等权时间，六配置的168份同频/合法频点日志哈希均核对通过。

| 新条件分支准入 | 替换 | 模型taken目标正确率 | RTL的EX控制流恢复 | 同400MHz时间变化 |
| --- | --- | ---: | ---: | ---: |
| 全部 | 轮转 | 80.198% | 116,618 | 对照 |
| 全部 | 两路LRU | 80.424% | 115,619 | +0.0020% |
| 全部 | SRRIP | 81.406% | 113,933 | +0.0460% |
| 仅taken | 轮转 | 82.597% | 106,592 | 对照 |
| 仅taken | 两路LRU | 82.732% | 105,872 | -0.0073% |
| 仅taken | SRRIP | 83.626% | 104,060 | +0.0903% |

时间各自相对同准入轮转，负数表示更快；不是全部相对原全准入基线。
模型正确率分母为419,947次实际taken，缺项/最后目标错误均计失败，**不应用RAS覆盖**；
不是新54组报告里的联合下一PC准确率。模型固定基线查询/解析时刻，RTL则重新生成错误路径和I$请求。
原始计数见`btb-screen.json`；同频/频率/PPA及窗口日志身份见`btb-results.json`。

全准入单独改SRRIP，EX恢复减少2.302%，I$ miss却51,634→52,031（+0.769%），同频时间没有改善。
全核面积增加368.144μm²；已通过频点735→740MHz，各自频点时间仍增加0.168%，面积×时间增加0.532%。
目标供给改善不保证CPU加速；I$和请求序列变化是同时观察到的影响，尚不能将全部时间差唯一归到I$。
taken＋SRRIP相对原基线的同400MHz时间减少0.292%，主要不能归功于SRRIP：同准入轮转本身已减少0.382%。

两路LRU在新分配或解析taken命中时更新对侧victim；SRRIP新分配RRPV=2、解析taken命中提升为0，满组按最大年龄替换。
二者均不在预测查询时更新，也不是退休有用性反馈。范围限于这三种规则，没有证明其全局最优。
追加预译码/预填充/压缩模型固定默认SRRIP，没有独立扫描提示插入年龄、提升时机和替换算法；
因此其负结果只说明该组合的目标供给退化，不能声称已经拆清提示准入与替换各自的贡献。

## 面积和频率的处理

全部使用同一NanGate45、AREA 3、820MHz映射策略及原I/O/复位约束，检查四类setup/hold。
700MHz逻辑诊断以外，原矩阵实测520MHz；追加BHT256后该组织只能通过420MHz，
因此完整35点矩阵另补共同400MHz，保留520MHz失败报告。各自合法频点按5MHz细扫并实测：存储仍固定100ns/10ns，
所以更改CPU频率时重新仿真，不能简单把700MHz的周期数除以新频率。
5MHz搜索网格仅是已测频点；最终保留集另列于`final-results.json`，稳定默认未改。
报告为综合后标准单元STA，未完成布局布线；没有功耗测量，只保留查询与总线流量代理。

128项普通BTB的当前关键违例终点在BTB训练载荷寄存器，并非只因查询读表变长。
在本次映射上520MHz通过、540MHz失败，面积148,596.112μm²；这是当前电路组织的结果，不是128项BTB的物理上限。

32项/4路/fold/SRRIP/taken这一相同目标组织上，BHT16、BHT64、BHT256、gshare256、
TAGE、TAGE+Loop、TAGE+SC、TAGE+SC+Loop已分别进入闭环RTL/PPA。
NSL组合通过720MHz；同源码基线通过735MHz。没有用降低基线资格来扩大候选收益。
同频最快不能替代合法频点比较：BHT256组合700MHz逻辑时间减少4.12%，但合法420MHz下时间增加约10.33%。

## 方向错误减少为什么不保证更快

在相同BTB32/fold上，gshare256比TAGE多7,640次条件EX纠错，却在1KiB I-cache下
等家族时间少0.67%。将两者都换为8KiB I-cache作单独诊断，其I-cache miss都降至1,337，
此时gshare反而慢0.29%。数据缓存、软件和存储延迟均未改；这强烈支持I-cache交互影响排序，
不表示8KiB已成为新候选或证明全部差异只由一个计数决定。主线I-cache仍为1KiB。

验证集量化加载2442还暴露单独taken准入的退化。补相同730MHz对照后，
条件EX纠错10,837→10,183，目标纠错1,504→1,020，I-cache miss却833→1,390，
周期1,717,625→1,782,348，仍慢3.768%。这不是730/735MHz频差造成的；该候选超过预定3%门槛。
证据见`btb-admission-regression.json`和`btb-icache-diagnostic.json`/`btb-results.json`。

## 原生SoC交叉检查

仅运行MicroBench test，CPU700MHz、设备100MHz、原生CLINT计时，未运行train。
计分区三者均退休430,313条：B0为1,074,214周期/IPC0.400584；BTB32/fold为
1,040,425周期/IPC0.413593；NSL+BTB32/fold为1,024,242周期/IPC0.420128。
这是原生系统有效性的交叉检查，不把这个短test作为主选型负载。
Total包含打印路径，其退休数可能因打印的数字变化而不同；不能拿Total指令数要求三者相等。
原生1us timer及各子窗口取整，与被动cycle统计分别保留在`btb-native-index.json`所指报告。

## 正确性、规模与复现

- 39组BTB配置：1,404,000次查询、31,104,000次表项状态比对，含同拍查询/更新、失效、满组替换、高位PC和随机目标。
- 4组新组合×10个NEMU测试通过；4组×取指/FENCE.I/dirty恢复/精确异常共16项整核回归通过。
- 追加5组候选的50个NEMU输入、20项安全回归，以及H2E当前源码的10个NEMU输入/4项安全回归均通过。
- 5种故意错误已由独立模型检出；其中一个只破坏invalidate后的RRIP状态契约，另一个明确破坏有效位清除，二者不混为同一种失效证据。

  它扩大执行窗口，未扩大解析器自身的代码种类；保留集遵守冻结后执行规则。

入口：`screen_btb.py`、`test_btb.py`、`run_btb_matrix.py`、`run_btb_extended.py`、

大事件证据保持原有无损gzip；新长测量保存被动窗口计数，综合中间JSON压缩后校验原始SHA256。
