# Scoreboard 发射等待与乘除法优化（2026-09-27）

本轮没有运行 train。所有程序级测量运行完整 ysyxSoC；独立 RTL testbench 只用于
检查单元算术、握手和恢复，不用它代替 SoC 性能结果。当前候选为 `balanced-fu-*`，功能和周期检查通过，综合时序仍在验证。

## 已修改的机制

原先未就绪指令留在 decode。MUL/DIV/LSU 返回结果后，依赖指令先进入 ID/EX，
再在下一周期执行。新的 ID/EX 可以保存两个未就绪源的生产者索引，在该槽中等待。
正常完成值可以直接供本周期 EX 使用；若另一个源尚未返回或下游反压，则保存已返回值。
年轻指令仍不能越过等待项，保持单发射、顺序发射和顺序提交。

scoreboard 查询同时给出最近写者的索引。若生产者就是当前尚未分配的 EX 指令，
使用本次分配索引。旧的同名写结果不能唤醒等待新写的消费者。
LSU 只将旧访存上下文的正常 load 响应用于唤醒，不把新请求的本地异常选择逻辑接入
该旁路；异常返回不能唤醒，恢复清除等待有效性。

乘法器继续使用三级流水，独立请求的最小间隔为 1 周期。没有删掉满足组合时序所需的
算术寄存器。完成到提交仍有队列状态更新边界，不能把 FU 的 3 周期延迟写成固定提交延迟。

除法器继续每周期试减一次。在 PREPARE 一次定位被除数绝对值的最高有效位，移除
前导零后再迭代；原实现按 16 位分组跳过零，剩余组中的高位零仍逐周期处理。
W 类指令先处理低 32 位的有符号/无符号语义，再归一化。除零、零被除数、被除数
小于除数及除数绝对值为 1 的快速路径保留。不增加多周期时序例外。

## 低 IPC 的解释边界

RV64IM 用一条 MUL/DIV 替代多条软件算术指令。指令数下降比例如果大于周期数下降
比例，IPC 就会下降，执行时间仍可缩短。不能以恢复 RV64I 的 IPC 数字为目标。
本轮验证的目标是固定 RV64IM 镜像，减少真正可以消除的等待。

逐条 DiffTest 记录确认，10 个计分段按定时器 load 的架构边界划分时，前后指令序列
全部一致。总共 333,887 条中，有 921 条乘法、511 条除法/余数、73,419 条 load/store。
乘除法指令合计约占 0.43%；多周期指令的时间占比不能直接等同于指令占比，但这说明
只优化乘法器不足以解释或解决整个 test 的低 IPC。完整明细保存在
`instruction-mix-audit.json`。trace 与 DiffTest 开启后的周期、退休数也与原测量一致。

在当前 MicroBench test 全程统计中，M 类译码占比仅约 0.73%，LSU 请求未就绪占
互斥发射停顿约 49.86%。这些是 test 全程数据，不是 train 的 Scored 分布。
scoreboard 满还会与较老访存未完成重叠；互斥统计优先级把它计入容量项，不表示这些
周期都可以通过增加队列或删除 scoreboard 消除。保留 4 项容量，没有盲目扩大队列。

## 时序拒绝与边界修订（继续验证）

首个直接前递候选在 700 MHz 的 setup slack 为 −1.408 ns；连接检查、电容、转换时间
通过，数据路径与门控时钟建立时间未通过。关键路径从 DIV 结果选择/符号修正，经
操作数前递到下一条 MUL 的部分积寄存器。这不是可以靠多周期约束放宽的迭代路径。
因此前述周期收益只是被拒绝候选的仿真结果，不能作为已完成的 700 MHz 优化。

后续修订先缩短 FU 返回端的组合计算：DIV 需要负号修正的普通结果在单独修正状态
写回现有商/余数寄存器，返回端只选取已保存结果；无须取负的结果和特殊值保留原延迟。
MUL 第三级同时保存高半部和与高半部和加一，两者并行计算，返回端用低半部进位选择，
避免返回端串联 64 位自增器。乘法仍为三级流水，不放宽约束。再次进行功能与时序检查。


第二候选仍未通过时序：关键路径为提交异常判断 → 带 flush 的 FU valid → 操作数选择
→ DIV 输入求绝对值，setup slack −1.439 ns。控制取消不应混入宽数据选择：ID/EX
改用 FU 已保存的 result_present，发射和提交仍独立受恢复禁止，恢复沿清等待有效位。
DIV 请求先保存操作数，负操作数在独立 ABSOLUTE_VALUE 状态转换，正数沿原路径前进。
MUL 第一级改用 16 个 16×16 的 `*`，第二级统一压缩部分积，保持三级流水，降低
前递后第一级的组合计算深度。功能和 PPA 均须重跑；前述候选均不能宣称通过 700 MHz。


第三候选的功能检查已通过，Scored、Total、各子测试与整程序计数均与第一候选一致，
因此 4.18% 的 Scored 周期减少和 4.51% 的 Total 增加仍同时成立。当前原始记录为
`balanced-fu-microbench/`、`balanced-fu-directed/`、`balanced-fu-tests.log` 和
`balanced-fu-recovery.log`。无符号延迟表不变；`DIV -31/7` 与 `REM -31/7` 为 9 周期，
`DIV -31/-7` 与 `REM 31/-7` 为 8 周期。面积与 700 MHz 状态等待当前候选验收。

综合命令默认关闭 Yosys 的全局调试日志 `-g`；可用 `STA_YOSYS_DEBUG_FLAGS=-g`
重新开启。这只调整日志详细程度，保留相同综合脚本、映射目标和时序约束。


第三候选仍有 −0.607 ns setup 违例：LSU 响应状态迟到后，才控制 64 位返回数据选择，
再进入乘法第一级。下一修订在 scoreboard 与 ID/EX 保存生产者的完成端口类型，
数据端提前选择 LSU/MUL/DIV；返回有效性、异常和索引只决定源是否就绪，不再串入
宽数据选择。未就绪的数据可以变化，但不得执行或捕获为有效操作数。重点验证两源
不同返回时间、同一 FU 的不同生产者、旧端口残留索引以及异常返回。


第四候选提前选定返回端口后仍有 −0.626 ns setup 违例，最差路径已转为正常 D-cache
数据返回经前递进入乘法部分积，电气与复位检查通过。下一修订只对 load → MUL/DIV
保留一次操作数保存：ALU、分支、LSU 仍可直接使用正常 load 返回，乘除仅使用保存后的
load 值，并通过独立算术操作数接口切断该物理路径。MUL/DIV 之间的结果旁路保留。
这会影响 load 后立即乘除的延迟，必须重新测量同镜像性能，不能沿用前版周期。
