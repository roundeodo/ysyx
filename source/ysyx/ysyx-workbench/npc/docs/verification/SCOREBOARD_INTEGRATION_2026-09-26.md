# 顺序发射与乱序完成集成

日期：2026-09-26。状态：功能回归完成；补齐门控时钟覆盖后，700 MHz 综合后完整验收通过。
本轮代码与结果根目录：`result/verification/scoreboard-20260926/`。
修改前文件及哈希保存在其 `before/` 子目录，旧实验未删除。

## 实际变化

新增 `core/issue/riscv_issue_ctrl.sv` 与 `riscv_scoreboard.sv`。保留单发射和顺序发射，
独立 FU 可以乱序完成，8 项 scoreboard 按序提供最老完成项给 commit。没有重命名、
动态选发队列或 LSQ，没有新增 Issue 物理寄存级，没有修改乘除运算分级或放宽时序约束。

MUL/DIV 携带标识返回，结果前递不等提交。同名目的寄存器写入仍等待提交；所有访存先获最老位置授权。
分支解析当拍禁止年轻发射，保留较老运算；提交异常同时取消队列与单元有效位。
原 completion mux、WB 和集中式 hazard controller 保留作历史测试，不在活动后端实例化。

- 原有 35 个程序 DiffTest 通过。乘除整核程序在最终功能源码上复跑通过，活跃核周期为 182,246，退休 70,582 条。
- 整核缓存恢复 84 项、精确异常 40 项通过。
- NPC 与 SoC lint 通过；保留原有存储/互连组合环等警告，不声称零警告。
- 独立执行单元：12,816 项 ALU 对比、7,168 项分支、4,005 个 MUL 请求、6,408 个 DIV 请求，

## 性能与时序

测试程序 `tests/performance/scoreboard_overlap.S` 分别覆盖 DIV 重叠、连续独立 MUL、
独立 ALU、连续写同一寄存器，以及轮换 7 个目的寄存器、避开 WAW 的 RAW 依赖链。`run_scoreboard.py` 对两个仿真器运行同一二进制并要求
DiffTest 通过，记录二进制/仿真器哈希、退休数和活跃核周期。五组前后测试均通过，
退休条数一致。前四组见 `performance/manifest.json`，RAW 依赖链见
`performance-raw/manifest.json`；前递保持了原有吞吐，WAW 与 RAW 的代价不能混淆。

| --- | ---: | ---: | ---: |
| DIV 与独立运算重叠 | 21,582 | 17,492 | +23.38% |
| 连续独立 MUL | 7,738 | 2,373 | +226.09% |
| 独立 ALU | 2,373 | 2,373 | 0.00% |

乘除整核程序的相同镜像从 166,688 周期变为 182,246 周期，IPC 从 0.423438 降为
0.387290。此程序包含大量访存，当前保守的访存授权会增加等待。连续同名写测试则
直接暴露 WAW 阻塞代价：已有写入需要到提交拍才允许下一条进入 ID/EX；普通整数
结果还经过 EX 结果寄存级和 scoreboard 完成位，前递可解决 RAW，但不能解除 WAW。

35 个短 ISA 验证程序也核对了镜像哈希：全部与旧版一致，等权几何平均速度比为
0.8717，约下降 12.8%，见 `isa-comparison.json`。这些程序用于正确性验证，不能替代
真实 AI 工作负载，但足以说明短依赖链和访存等待的代价不能忽略。

因此，本轮证明了 FU 重叠收益和顺序提交正确性，没有证明全面性能提升。8 项容量未选优，
访存的最老位置授权和 WAW 等待是后续需要单独测量的优化点。不能把这些代价归于 RV64
位宽，也不能通过允许多个同名写入、却不处理生产者选择与恢复来直接删除阻塞。

仿真计时改为按 scoreboard 索引从发射配对到结果返回，多个同拍完成分别计数。
平均执行延迟以完成样本作分母，不能把相互重叠的指令延迟相加当作 CPU 停顿。
WAW 和后端资源等待单独记录。原有 IPC 的退休数/活跃核周期口径保持不变。

本轮以 820 MHz 为映射目标，再按 700 MHz、Nangate45 typical、理想时钟和每输出

改造前同类网表面积为 169,947.134 µm²，本轮增加 **17,519.026 µm²（10.31%）**。
映射时 MUL / DIV 面积分别为 44,590.644 / 3,564.932 µm²，较原版仅增加
36.708 / 27.398 µm²；主要增量在核心的在途结果存储、依赖和提交控制。
这些是映射模块统计，不能把综合后交叉优化的单元强行精确归给某一条 RTL 语句。

最初的旧验收脚本遗漏了 8,886 个寄存器端点，因而曾返回不完整的“通过”。补齐覆盖后，
`ppa-clock-covered/` 实测 AXI 输出最差 setup 为 -0.050 ns，MUL 结果前递到 ID/EX
为 -0.020 ns。按真实违例增强少量组合单元驱动后重新通过全部检查；每次替换均核对
Liberty 引脚方向和逻辑函数，全部连接与其他单元保持一致，见 `clock-drive-*/audit.json`。
修复过程没有改变指令延迟、FU 分级、前递规则或提交顺序，未添加多周期例外。

本轮 700 MHz 目标下，Issue 复用 ID/EX 已通过上述验收，无需因此额外增加寄存级。
这仍是单工艺角、理想时钟的综合后检查，未做 CTS、布局布线和多角签核，不能等同于
最终芯片频率保证。旧 EXU 基线也有时钟覆盖遗漏；其面积可比较，历史频率结论须单独复核。

## 补充：旧 STA 流程遗漏门控后缓冲路径

iEDA 日志中的 `has no clock data` 不是可以忽略的告警。本轮统计到 8,886 个寄存器
端点，时钟端都由电气修复加入的 BUF_X2 直接驱动。核对所用工具版本的
[时钟传播源码](https://github.com/OSCC-Project/iEDA/blob/aa25008b3778a76ae1975c839d4cc459f7f7b3b7/src/operation/iSTA/source/module/sta/StaClockPropagation.cc)
后，确认该版本在 ICG 输出连接非时钟引脚时停止传播，缓冲器 A 引脚因此被跳过。
旧版 EXU 验收日志也有同类遗漏；其历史“700 MHz 通过”只代表旧脚本覆盖到的路径。

最小电路 `clock-probe-v2/` 重现了两个缓冲后触发器的时钟丢失；补充同频、同相位的
派生时钟后，两处端点均获得时钟，诊断数从 4 变为 0。新辅助脚本沿非反相缓冲器和
ICG 验证时钟确实来自 `clk_i`，只在被工具跳过的首级缓冲器输入处建立 1:1 派生时钟。
它不改变网表、不增加多周期例外，也不取消原有门控检查。

最小电路还核对了原时钟和派生时钟下的四个触发器：CK 引脚的转换时间均报告为 0 ns，
见 `clock-model-audit.json`。这是当前 iSTA 的理想时钟模型；日志中的库表查询下界告警
继续保留。本轮没有建模实际时钟树的延迟、转换时间与不确定度，不能据此承诺芯片频率。

验收脚本已改为拒绝任何缺少捕获时钟的诊断，并累计各时钟组的 TNS，防止新增时钟组
掩盖前一组的违例。相关小测试已纳入 `make test-timing`。`ppa-clock-covered/` 保留补齐
覆盖后的真实违例，`ppa-clock-drive-2/` 保存最终通过结果。两个目录以及原始失败日志均保留。
