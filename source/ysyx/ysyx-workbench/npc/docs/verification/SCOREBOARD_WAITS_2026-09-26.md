# Scoreboard 等待优化

日期：2026-09-26。功能回归、周期测量与 700 MHz 综合后完整验收均已完成。
本轮独立目录：`result/verification/scoreboard-waits-20260926/`。
修改前源码、文档、仿真器及哈希已保存，初版实验保持原样。

## 变化

1. 允许多条写同一个架构寄存器的指令占用不同结果槽。读取寄存器时，只从程序顺序上
   最近的一条较老写指令前递。删除目的寄存器等待接口、WAW 停顿计数以及相关比较逻辑。
2. LSU 可跨过已排除异常的较老纯运算；前一条访存的地址、写数据和字节使能仍须保留到提交。
   保留当前完成当拍放行与前一条访存提交当拍交接。
3. 仍按序读取操作数、按序发射、按序提交，FU 可以乱序完成。
   未新增流水级、物理寄存器堆、独立重命名表或动态挑选发射队列。

实现规则与恢复前提见[设计记录](../microarchitecture/SCOREBOARD_DESIGN_RECORD.md)。
本轮保留 FU 完成到提交的寄存边界；其时序作用不能当作无条件可删除的等待。

## 复现

```sh
make test-scoreboard test-scoreboard-core git_commit=
make build-npc lint-npc lint-soc git_commit=
# 使用新输出目录，避免覆盖旧测量
make sta-qualified git_commit= STA_OUTPUT_ROOT=<新的绝对路径>
```

周期比较使用 `tests/performance/run_scoreboard.py`，以保存的 `baseline_sim`、本轮
`top_sim` 和同一个 NEMU 参考模型运行同一镜像，要求两端 DiffTest 通过且退休数一致。
原有五种运算负载之外，增加 DIV 与 load 重叠、多同名 FU 结果，以及 load/store 循环。

## 结果

本轮通过 **700 MHz 综合后完整验收**。最终标准单元面积 **187,183.668 µm²**，
初版为 187,466.160 µm²；本轮减少 282.492 µm²，约 0.15%。

| 检查 | setup 裕量 | hold 裕量 |
| --- | ---: | ---: |
| 数据路径 | +0.029 ns | +0.060 ns |
| 门控时钟 | +0.060 ns | +0.095 ns |

全部时钟组的 max/min TNS 均为 0，缺少时钟的端点诊断为 0；复位连接、电容和转换时间检查通过。
条件与初版一致：Nangate45 典型角、理想时钟、每个输出 10 fF，未设置额外全网扇出上限。
尚未做 CTS、布局布线或多角签核。理想 CK 转换时间为 0，日志仍保留低于库表下界的提示。

原始映射面积 186,320.498 µm²；三轮共增强 19 个组合驱动，增加 14.098 µm²；
实际电容修复保留 798 个 BUF_X2，增加 849.072 µm²。没有新增流水级或多周期时序例外。
驱动替换逐项核对逻辑函数和引脚，并核对其余单元与连接不变；每轮都重新检查负载和完整时序。

初次检查、两轮常规驱动调整后的最差 setup 依次为 -0.043、-0.010、-0.005 ns。
旧流程到两轮上限后返回失败，原报告保留在 `ppa-v2/`。已将默认流程补为最多三轮：
前两轮选择不小于 45 ps 的失败路径组合输出弧，最后一轮降到 35 ps，每轮最多调整 12 个驱动。
新增的候选边界、最后一轮成功、轮数上限与失败返回测试通过，见 `fine-drive-tests.log`。

本轮从已完成的第二轮网表继续最后一轮，复现命令保存在 `fine-drive-commands.json`，
使用的脚本快照及哈希保存在 `fine-drive-source/` 和 `fine-drive-source-hashes.json`。
最终通过的目录是 **`ppa-clock-drive-3/`**；`final-ppa-summary.json` 汇总结果和证据哈希。
正常的 `make sta-qualified` 已包含这次有上限的细调。

## 已完成的功能与周期测量

625 项 scoreboard 检查、6 个整核定向场景、40 个精确异常场景和 84 个缓存恢复场景
全部通过。新增场景验证同名 DIV/MUL/ALU 的最近生产者选择、迟到结果、队列回绕，以及
load 在较老 DIV 前完成但在其后提交；第二条访存不能覆盖第一条尚未提交的上下文。
NPC 与 SoC lint 通过，保留原有存储/互连警告。第一次写法曾将 LSU 组合完成信号带回
访存授权；已删除这条不需要的依赖，修订后的警告路径中不再经过 scoreboard。

八组专项在修改前后使用相同镜像，均通过 DiffTest，退休数一致：

| 负载 | 初版周期 | 本轮周期 | 周期减少 |
| --- | ---: | ---: | ---: |
| DIV 与独立运算 | 17,492 | 17,480 | 0.07% |
| 连续独立 MUL | 2,373 | 2,373 | 0.00% |
| 独立 ALU | 2,373 | 2,373 | 0.00% |
| 连续同名写依赖链 | 5,420 | 2,356 | 56.53% |

35 个原有程序和 RV64M 综合程序全部通过 DiffTest，两版退休数一致；原有镜像哈希也与
初版测量一致。35 个程序的等权几何平均周期比（初版/本轮）为 **1.137211**，同频下约提高 13.72%。
RV64M 程序均退休 70,582 条，周期 **182,246 → 171,264**，减少 6.03%，
IPC **0.387290 → 0.412124**。这些是功能程序集和专项测量，不代表真实 AI 应用吞吐。

与更早的、尚未加入 scoreboard 的顺序完成版本相比，RV64M 程序仍多 4,576 周期，
即周期多 2.75%。该旧版本的 700 MHz 检查存在时钟覆盖缺失，不能据此比较两个版本在
各自可实现频率下的运行时间。本轮单一未提交访存上下文仍会限制连续访存；不能为了消除等待直接允许
第二条访存覆盖上下文。后续须单独比较增加上下文存储或改变提交旁路的面积和时序代价。

结果位于本轮目录的 `performance/manifest.json`、`isa/manifest.json`、
`regression-commands.json`、`precise/manifest.json` 和 `cache-recovery/core/manifest.json`。
两版仿真器保存为 `baseline_sim`、`current_sim`；`final-rtl.sha256` 固定本轮 RTL。
综合输入与最终源码之间仅有断言换行调整，`style-equivalence.json` 记录忽略注释与空白后的内容一致性；这不是形式等价验证。
