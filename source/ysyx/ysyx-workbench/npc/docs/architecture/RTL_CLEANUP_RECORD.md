# RTL 修复与清理记录

日期：2026-09-05。

## 1. 本轮改变了什么

本轮落实[设计检查](RTL_DESIGN_REVIEW.md)中已确认的错误与代码问题。先修正数据保存和
错误恢复，再删除无用状态与重复实现，保持现有顺序核的流水边界和正常命中吞吐。

| 问题 | 实际修改 | 验证关注点 |
| --- | --- | --- |
| D-cache反压时响应被新地址改变 | 阵列读取与请求接收绑定；停顿时保持阵列输出和写读旁路 | 无效输入跨字/跨组变化、有效下一请求等待、响应身份、反压解除 |
| 写回失败后旧脏数据无法恢复 | 排空读写事务后逐字恢复旧行，再恢复tag/valid/dirty并返回fault | B/R完成顺序、双向错误、整行重读和重试写回 |
| 整行写回缓冲重复保存 | miss unit保存唯一副本，AXI适配器只保存元数据和进度 | 数据从请求握手保持到响应握手；W反压时保持当前字 |
| FENCE.I清理错误只用仿真断言处理 | 独立维护控制器保持取指阻塞，撤下请求一拍后重试，成功后才失效I-cache | 连续三次写回失败后恢复，等待失效完成 |
| I-cache存在不能启用的回填旁路 | 删除互斥条件下不可达的选择路径、逐字可见向量和相关端口 | 保留原缺失请求的所需字提前返回及阻塞式查找 |
| 预测器重复保存分类输入 | 入口共用调用/返回判断，BTB训练只保存目标类型 | JAL、条件分支、间接跳转、RAS及训练流水 |
| next PC重复计算 | 由IFU统一选择；删除预测器无使用者的next PC字段与输出 | 查询身份、预测目标、IFU请求地址和反压 |
| core内混合数据选择与维护状态 | 提取operand select和cache maintenance controller | 端口依赖、前递优先级、维护次序和恢复 |
| DPI重复及异常next PC采样过晚 | 两种平台共用调试头文件，读取同拍提交重定向结果 | csr-trap、mret、standalone与SoC展开 |
| SoC读通路组合过程混合正反方向 | 拆开下游请求与上游应答的计算，显式导入配置包 | 等价检查、转换器回归及SoC组合环告警消除 |
| 形式验证使用过期接口和规则 | 更新生产者资格、WB前递与flush性质，移除已不存在的LSU直接前递假设 | 深度20的队列顺序、最近生产者优先与恢复控制 |

默认64 B行的写回数据少保存一份512位缓冲。预测训练包以2位目标类型替代64位立即数和
两个5位寄存器号，声明宽度减少72位。这些是RTL结构变化；映射后寄存器数、面积和时序
以同配置综合结果为准。回写适配器的独立 Nangate45 综合已经确认少了512个触发器，
面积从3995.054降至1670.480 µm²（约58.2%）；这不是整核面积降幅。
完整4 KiB缓存配置的整核综合因长时间未完成而停止，已保留日志；本轮没有整核PPA结论。

## 2. 删除与共用的内容

- 删除未实例化、无测试使用的 `riscv_redirect_arbiter` 和 `riscv_axi4_error_target`，同步
  两份filelist。删除前源码保存在本轮快照，当前文档不再将它们列为已集成能力。
- 删除未使用的重命名、执行请求、统一完成候选类型及其容量；删除恢复请求中无人读取的
  ROB年龄和flush范围占位字段。M2按实际ROB与恢复设计重新定义接口。
- 删除LSU无调用的 `request_has_memory_access()`。
- 缓存命中和回填共用 `merge_store_bytes()`；三个仿真监视器共用比例和延迟计算包。
- 删除预测器与I-cache的无用接口时，同步父模块、断言和测试，避免保留只为旧接口服务的
  比较或检查。

当前有56个HDL文件，另有一个共享DPI头文件。每个文件的职责见
[模块总览](RTL_MODULE_MAP.md)。单纯删除未实例化模块和未使用类型主要减少维护负担，
不能把文件减少数换算成硬件面积收益。

## 3. 代码怎样组织

core以连接为主，操作数选择与维护控制分别有明确模块。预测器、缓存、LSU、宽度转换器
和仿真监视器的声明移到使用它们的功能附近；读写转换各自按输出、下一值和寄存器更新
组织。状态组的边界依据它负责的数据与事务确定。

预测器中同拍查询仍读已保存的表项；最新训练结果会前递给后续训练。注释不再把训练旁路
误写成已有查询旁路。仿真监视器分别说明原始计数与候选预测模型，计算报告所需的函数
放在报告附近，不把候选模型的错误数说成当前RTL的错误数。

纯声明移动使用语法树核对前后的语法标记，确认没有遗漏表达式；随后仍运行lint和受影响
回归。这项检查不替代功能测试。排版继续使用工作区Verible包装器，保留列对齐、局部空行
和续行缩进。

## 4. 保留的实现选择

寄存器写回到新读值、刷新被阻塞的数据包，以及执行结果到ID/EX的前递作用于不同周期，
都予以保留。D-cache相邻写读的数据旁路和脏位旁路同样都需要；它们已有独立测试覆盖。

当前保留load经WB前递、LSU逐阶段处理、取指缓冲寄存器边界，以及一次一个共享读突发。
增加更早的load前递、预测查询旁路或请求周转能力，会增加选择逻辑或改变时序路径；这些
属于下一步需要测量的结构优化，不属于可直接删除的冗余。顺序核的正确性与回归继续优先。

持续写回错误会使FENCE.I维护持续重试并阻塞取指。当前没有机器检查异常、平台重试上限
或软件错误报告接口；本轮没有据此宣称完整的系统容错支持。
