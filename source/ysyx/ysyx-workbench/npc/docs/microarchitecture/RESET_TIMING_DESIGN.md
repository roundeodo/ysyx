# 系统复位与综合后电气修复

2026-09-25。本次解决原始复位直接进入核内、复位被误设同步输入延迟，以及映射网表的驱动负载超限。

## 复位职责与接口

`riscv_reset_controller` 使用未门控时钟，外部低有效复位异步拉低输出；外部释放后经过两个上升沿同步，再在下降沿释放系统复位。
`riscv_npc_system` 是实际系统中唯一的复位控制器所有者，将同一释放信号送往核、CLINT、仲裁与路由，并通过 `system_rst_no` 供 SoC 位宽转换器和独立仿真模型使用。

`riscv_core_reset_boundary` 仅用于包含真实释放电路的纯核综合/STA，不含 CLINT 或 SoC。其同步器与实际系统使用同一模块。
原始异步复位不人为指定相对时钟的同步到达时间；同步链和释放寄存器到核内复位端的 recovery/removal 检查保留。不用全局 false path 掩盖核内复位路径。

## 电气修复边界

标准单元映射后，根据库中输入电容、输出电容上限及报告的转换时间检查负载。
默认使用库的完整电容上限，不额外限制全网扇出；旧的扇出 16 和 65% 电容预算仅保留为显式可选参数。优先给过大负载加入非反相缓冲树，本次使用 BUF_X2 缓冲树，不改变原单元类型。
若新增缓冲位于失败的建立时间路径上，可在原驱动仍满足电容预算和扇出上限时将关键输入接回原驱动。
仅允许缩短新增缓冲的连接，不修改原逻辑单元、外部输入驱动模型、时钟端或异步控制端。
每轮保留失败网表与报告，折叠新增缓冲后核对全部原始单元和端口，再重跑 STA。
保持/removal 失败时不使用该缩短方法；任何检查仍失败都必须返回非零。
保留原网表；每次变换保存连接等价审计、单元与面积变化。此步骤不增加指令流水级，也不修改功能握手。
时钟和复位网络单独标识，实际物理实现仍需 CTS、布局寄生和多工艺角验证。
