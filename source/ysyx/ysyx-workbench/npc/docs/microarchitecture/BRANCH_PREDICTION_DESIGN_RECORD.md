# 分支与跳转预测设计记录

状态：当前结构说明与候选优化方法

最后更新：2026-09-24

## 1. 当前预测什么

`riscv_branch_predictor` 根据取指 PC 和过去的执行结果，预测是否跳转及目标
地址。当前不在该模块中读取或译码待取指令。

| 结构 | 默认配置 | 作用 |
| --- | --- | --- |
| BHT，分支方向表 | 16 个 2 位饱和计数器 | 预测条件分支是否跳转 |
| BTB，分支目标缓冲 | 共 16 项、2 路 | 保存已知控制流指令的类型和目标 |
| RAS，返回地址栈 | 4 项 | 根据调用与返回记录预测返回地址 |

没有可用目标预测时继续顺序取指。直接跳转目标会通过已解析控制流结果写入预测状态；
这不表示预测器能在首次取到指令之前直接译码 JAL 立即数。

2026-09-24 核对面试分支的最终实验选择后，继续采用以上容量、PC 索引二位方向表、
轮转 BTB 和解析后更新的 RAS。容量参数保持不变；本次将查询改为一级响应寄存器，并去掉额外训练流水。
源分支中默认关闭的 gshare、TAGE 等候选未迁入；RV64 是否受益仍需独立测量。
证据与迁移边界见[前端配置同步记录](../verification/FRONTEND_CONFIGURATION_SYNC_2026-09-24.md)。

## 2. 查询与取指身份

IFU 向预测器发送 PC、取指路径代号（epoch）和有效信号。BHT、BTB 和 RAS 并行组合查询，
比较标记并选择预测结果后进入一级响应寄存器；输出包含对应 PC、epoch、预测方向和目标。

预测器端口没有 `frontend_tag`。IFU 另行管理 I-cache 请求的 tag，将预测信息与实际取指
请求关联。指令返回时，IFU 检查 tag 与 epoch，再组成 `fetch_entry_t` 交给取指缓冲。

预测响应被阻塞时保留内容。发生重定向时清除旧查询，旧路径的 I-cache 响应仍需按其接口
接收并丢弃，不能因为预测改变而撤销已经接受的总线事务。

## 3. 训练与恢复

执行结果级得到真实方向和目标，判断预测是否错误并发出重定向。该级已经保存稳定的解析
结果，直接驱动 BHT、BTB、RAS 更新，不再重复寄存训练信息。三个表分别由 `riscv_bht`、
`riscv_btb`、`riscv_ras` 管理状态，预测模块负责分类、结果选择和响应保持。

预测器返回查询PC、epoch、方向与目标；IFU统一选择下一PC。预测器内部不再保存一份
无人使用的next PC计算结果。

- BHT 根据已解析条件分支更新，JAL/JALR 不训练条件分支方向。
- BTB 保存已解析控制流的类型和目标。
- RAS 根据调用、返回以及寄存器使用规则更新。
- 普通 redirect 清除查询流水；失效操作另行清除可能过期的预测状态。

查询与训练同拍时读取更新前的表值，没有训练到查询的组合旁路。这是明确的预测时序，
错误预测由执行端纠正。不要把 I-cache 替换状态的同拍旁路与预测表查询混为一谈。

预测状态不属于软件可见的架构状态。错误预测允许发生，但恢复必须保证正确的指令序列。
后续若在执行确认前更新返回栈或预测历史，需要单独设计恢复方法，不能沿用当前更新规则
却直接声称已经支持推测状态恢复。

## 4. 当前需要验证什么

- 预测与实际取指请求正确对应；旧 epoch 响应不能作为新路径指令进入后端。
- 响应反压时 PC、epoch 和预测结果保持稳定。
- 同一 BTB 组内最多一路命中同一 PC。
- RAS 满、空、连续调用、连续返回及更新冲突有确定行为。
- 连续训练不能丢失更新；同拍查询读取旧表值，PC、epoch 和结果仍须属于同一次查询。
- 预测错误能恢复到正确目标，不能导致指令丢失、重复提交或错误路径副作用。

当前实际测试证据见 [验证记录](../verification/EXPERIMENT_LOG.md)。预测器容量与性能结论
必须对应具体构建配置。

## 5. 使用 Branchsim 比较方案

`npc/tools/branchsim` 读取退休控制流记录（trace），包括 PC、类型、真实方向和目标。
它可以比较方向算法、表容量、目标预测和返回预测，适合快速筛选候选方案。

在 `ysyx-workbench/npc` 中执行：

```bash
make branchsim-test
make branchsim-trace
make branchsim-run
make branchsim-explore
```

记录软件版本、输入、trace 校验值、参数和命令。模型使用退休顺序，而 RTL 在执行解析后
训练，存在时序与推测访问差异；不能要求两者在所有程序中给出完全相同的计数。

预测准确率也不能直接换算为 IPC。最终还要测量恢复代价、取指等待、后端停顿和时钟频率。
当前可用普通分支、循环、调用与返回程序，不要求 AI runtime。
